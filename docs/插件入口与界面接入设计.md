# 插件入口与界面接入设计

2026-09-30。状态：直接入口与工作区/覆盖界面第一步已实施；Attention 来源和 Drover 迁移仍为设计。保留已发布的独立进程、Rust SDK 和结构化画面协议；实际清单、协商及保留键见 [协议扩展](插件协议.md#8-直接入口与覆盖界面扩展)；本文未实施部分仍是概念契约。

## 用户要求与设计边界

用户原话：“像drover这种，我肯定是界面在saddle上，而不是我进入插件对话框照这个插件然后open panel啊”。参考 Herdr 后，用户确认功能入口、界面位置和提醒应分别接入 Saddle。

已确认原则：插件管理归设置，插件功能直接融入日常界面。主控亲自完成，先用 Counter 验证，再迁移 Drover。下面的接入位置、接口划分和验证顺序是主控的具体设计建议，不扩写成用户原始验收点。

## 三种能力

| 能力 | 插件提供 | Saddle 负责 |
| --- | --- | --- |
| 功能入口 | 稳定操作 ID、标题、要打开的视图 | 在日常界面显示入口、路由点击/键盘激活 |
| 界面 | 视图 ID、展示位置、结构化画面与交互逻辑 | 分配区域、焦点、外框、尺寸与输入路由 |
| 提醒 | 短提示，或当前待处理条目 | 提示展示、Attention 汇总与跳转 |

三种能力都不要求插件实现任务模型。无界面的插件可以只做后台工作并发提醒；有入口的插件也不必发布 Attention 条目。安装/启用与使用入口保持分开，点击功能入口不隐式启用已停用插件。

## 1. 入口：直接访问功能

先提供一个固定的日常入口区域，不实现任意工具栏、右键菜单或可编程布局。建议入口在左侧 Agents 顶部，与 Tasks、Attention 一样直接可见。插件显示自己的功能名称，例如 Counter；不增加必须先打开的“插件功能”选择器。

概念上分开声明“操作”和“展示入口”：操作有局部 ID、标题和目标视图；展示入口引用操作。全局身份使用 `(plugin_id, action_id)`，不使用标题匹配。首阶段每插件一个视图、一个直接入口，操作只负责打开/聚焦视图；不做可执行任意命令的通用 action runner。

示意，具体换行由可用宽度决定：

```text
┌ Agents · 4       Tasks ┐ ┌ Workspace ──────────────────────┐
│ Counter               │ │ 当前 agent 或插件界面           │
│ Attention · 0 Settings│ │                                 │
│ ... agents ...        │ │                                 │
└───────────────────────┘ └─────────────────────────────────┘
```

- 启用的插件贡献入口；停用/移除时撤下入口。Starting/Failed/Unresponsive 的入口保留状态，不能伪装成可执行；失败原因和 Restart 仍由插件管理提供。
- 多个入口采用稳定顺序；宽度不足时换行，空间不足时可滚动。必须能用键盘选择/激活，不能挤掉 Agents 的基本操作或靠截断隐藏唯一入口。
- 不允许插件自行占用宿主保留键。第一步不建立通用快捷键编辑系统；Drover 迁移时保留现有 Tasks 快捷操作，将其绑定到通用入口路由，而不在渲染器中按 Drover ID 特判。
- Settings → Plugins 继续管理安装、启停和故障。原 Open panel 可作为旧插件的兼容入口，不再是新插件的日常必经之路。

## 2. 界面：区域和业务分离

先支持两种位置：已有的工作区面板，以及适合 Tasks 的居中覆盖界面。不增加原生窗口、HTML、像素画布或侧栏任意绘制。

| 位置 | 打开 | 关闭 |
| --- | --- | --- |
| 工作区 | 打开新 tab，已有该插件视图则聚焦 | 关闭显示，保留插件进程 |
| 居中覆盖界面 | 覆盖工作区，原 tabs/panes 不变 | 返回打开前的有效焦点，保留插件进程 |

插件仍在自己的进程内用 Ratatui Buffer 绘制；宿主复用现有帧校验、主题、宽度和输入契约。窗口位置不改变插件业务实现，也不启动第二个插件进程。首阶段一个插件仍只有一个逻辑视图，不允许同时在两个位置接收输入。

覆盖界面不写入工作区布局，不恢复为永久 tab。打开时保存来源焦点；来源已消失则返回 Agents。关闭/停用/崩溃后的迟到帧和输入不得落到下一个打开的界面，沿用会话身份与尺寸修订校验。

Settings、确认框或另一个覆盖界面已打开时，拒绝新的覆盖打开并保留现有界面，不偷偷丢弃草稿或替换确认目标。Ctrl-] 返回 Agents；覆盖界面的 Esc 由宿主用于关闭，插件需在握手时知晓该保留键，不把 Esc 同时当成业务输入。其他输入仅送给当前可交互区域。业务二次确认可在插件画面内部完成。

入口打开时可携带当前选中/聚焦 agent 的公开身份和已知项目目录；值未知就明确缺失，不读取 Corral 内部数据，不自动猜任务 ID。插件把这次上下文当作打开时快照，不会因焦点后台变化而自动替换用户正在确认的业务目标。

## 3. 提醒：短提示与持续条目分开

现有 notify 继续表达“一次短提示”，保留去重、限流和 accepted 不等于用户看见的语义。不把通知增加、消失或点击解释为任务完成、接受或派发。

Attention 扩展采用插件来源的当前条目快照：每条有插件局部稳定 ID、短标题/说明、要打开的操作，以及插件自己解释的目标数据。Saddle 校验来源、容量和操作引用，负责汇总展示；不理解任务号、Running/Awaiting/Done，也不代替插件保管业务真相。

- 快照替换只影响该来源；空快照明确表示没有条目，没收到新数据不表示清空。
- 条目出现或变化不必然触发短提示。何时提示、重启基线和业务去重由插件决定。
- 点击只负责打开相应视图并传入目标数据；插件重新读取公开业务状态后展示，接受等写操作仍由用户明确触发。
- 插件断连时来源显示不可用，旧条目失效且不能点击，不能显示成“已处理”。停用/移除撤下该来源；这只改变界面，不改变任何业务状态。
- 首期不建立通知持久化服务、跨插件事件总线或任务推进后台。多实例业务去重仍由插件按自身公开契约处理。

该快照与“打开指定目标”的消息是后续能力扩展，不复用 notify 的会话内计数器当业务 ID。具体消息字段、快照预算和过期目标验证在实施该能力时补入协议文档；Counter 入口阶段不提前实现整套 Attention 数据通路。

## 兼容与职责

现有插件清单继续工作，仍可从管理页打开工作区面板。新入口、覆盖位置、上下文和 Attention 分别以明确的能力声明协商；旧宿主不能把必需能力忽略后假装支持。每项实际实施时更新清单校验、握手、公开类型、SDK 与协议说明；当前协议文档仍描述已交付功能，不提前把草案写成可用 API。

Saddle 只增加通用入口目录、视图展示位置和 Attention 来源接口。Drover 自己保留队列读取、目标令牌、提交/接受、通知基线等逻辑；Corral/corral-dispatch 不变。迁移后同一任务来源只保留一份适配，避免内建 Drover 与插件同时轮询、重复入口或重复通知。

## 实施顺序与观察方式

1. **Counter 直接入口和展示位置**：启用后从 Saddle 的 Counter 入口打开，验证工作区/覆盖位置共用同一插件和画面协议，关闭重开仍保留计数。先落这一小段；不接真实任务、不修改 Drover。
2. **通用 Attention 来源**：用独立合成条目验证更新、撤回、断连失效及点击打开指定目标，与已有短提示明确分开。仍不操作真实任务。
3. **Drover 迁移**：列清现有 Tasks、Attention、通知偏好、项目选择和关联跳转的搬迁清单，再实施。任务编辑的输入光标等缺口按实际清单补齐，不在此稿预造控件框架。

Drover 的目标体验：启用后原位置出现 Tasks；点击打开任务覆盖界面；任务待验收时 Attention 和提示按现有规则出现；点击提醒打开对应任务；用户仍亲自提交/接受。停用后撤下任务能力，终端和 agent 操作继续可用。当前内建 Drover 尚未搬迁，这段是目标，不是现有行为。

## Herdr 参考与取舍

只读核对了本机 Herdr 0.9.3、同版本源码和已安装的 Herdr Plus。Herdr 把 actions 和 panes 分开声明，操作可进入动作菜单/快捷键，窗口支持不同 placement；其插件 v1 的窗口承载终端程序，并未提供原生非终端 UI。

本设计借鉴入口/承载分离，保留 Saddle 已有的结构化绘制；固定功能入口与 Attention 来源是 Saddle 自己定义的扩展点，不声称 Herdr 已有完全相同的机制。也不照搬其每项 action 启动 argv 命令的模式，Saddle 继续复用已启用的插件进程。
