# 插件入口与界面接入设计

> 已退役（2026-10-05）：Saddle 已删除遥测、Drover 和整个插件系统。本文只保留设计/验证历史，不再作为当前操作规矩或安装指引；旧磁盘数据不读、不删。当前功能与命令见 [README](../README.zh-CN.md)，派发路由由 ranch 提供。

2026-09-30。状态：工作区/覆盖界面已实施；侧栏逐插件入口已被本轮统一插件命令面板替代；通用 Attention 来源已实施，Drover 迁移仍为设计。保留已发布的独立进程、Rust SDK 和结构化画面协议；实际清单、协商及保留键见 [协议扩展](插件协议.md#8-直接入口与覆盖界面扩展)；本文未实施部分仍是概念契约。

## 用户要求与设计边界

用户原话：“像drover这种，我肯定是界面在saddle上，而不是我进入插件对话框照这个插件然后open panel啊”。参考 Herdr 后，用户确认功能入口、界面位置和提醒应分别接入 Saddle。

已确认原则：Saddle拥有外壳，插件通过统一命令面板打开自己的界面，插件管理归设置。主控亲自完成，先用 Counter 验证，再迁移 Drover。下面的接入位置、接口划分和验证顺序是主控的具体设计建议，不扩写成用户原始验收点。

## 三种能力

| 能力 | 插件提供 | Saddle 负责 |
| --- | --- | --- |
| 功能入口 | 稳定操作 ID、标题、要打开的视图 | 在日常界面显示入口、路由点击/键盘激活 |
| 界面 | 视图 ID、展示位置、结构化画面与交互逻辑 | 分配区域、焦点、外框、尺寸与输入路由 |
| 提醒 | 短提示，或当前待处理条目 | 提示展示、Attention 汇总与跳转 |

三种能力都不要求插件实现任务模型。无界面的插件可以只做后台工作并发提醒；有入口的插件也不必发布 Attention 条目。安装/启用与使用入口保持分开，点击功能入口不隐式启用已停用插件。

## 1. 入口：统一插件命令面板

2026-09-30用户确认新的外壳原则，替代原侧栏逐插件按钮。Saddle固定显示Plugins入口，插件不能自己增加主界面控件。命令面板居中显示搜索框、名称、状态和打开/切换动作；管理作为次要入口。行单击只选择，动作点击或Enter执行；Esc恢复原焦点。正常状态不占大段说明，异常显示原因。不绑定新的全局快捷键。

2026-10-04 起（T74，见 DESIGN「Tasks 直接入口」）：插件仍不能自行增加主界面控件，但用户可在管理页把一个有视图的插件固定到 Agents 头部，Agents 焦点 `p` 打开；Plugins 面板不变。

一插件一行，使用注册表稳定ID；停用、失败、不可用也保留可选择项。运行且未打开视图显示Background；已打开（包括非活动tab）显示Open并提供Switch。Starting/Stopping/Restarting/Disabled/Failed/Unresponsive/Unavailable不可执行；无界面插件显示后台状态，动作禁用并说明没有可打开的界面。状态由本Saddle实例产生，不把另一实例的登记设置等同于本地运行事实。

启用仍立即启动，面板不隐式启用或重启。重复激活复用现有进程/视图。失效的按下/释放手势取消；执行时校验当前状态。列表更新保持选中的插件身份，不按状态重排行。主界面不显示Counter等插件自定义按钮。旧清单panel.v1插件也可列入，不要求更新SDK。

面板是宿主临时模态层，不写布局；Settings、创建、关闭确认等编辑界面存在时拒绝打开，不丢草稿。在插件覆盖界面之上可呼出面板，取消恢复原界面；切换另一个插件关闭旧显示但保留其进程。同一个插件已有workspace视图时仍优先聚焦。

## 2. 界面：区域和业务分离

先支持两种位置：已有的工作区面板，以及适合 Tasks 的居中覆盖界面。不增加原生窗口、HTML、像素画布或侧栏任意绘制。

| 位置 | 打开 | 关闭 |
| --- | --- | --- |
| 工作区 | 普通入口打开新 tab 或聚焦已有视图；`+` / `Split → 方向 → Plugin…` 明确选择位置，已有视图则 Move | 关闭显示，保留插件进程 |
| 居中覆盖界面 | 覆盖工作区，原 tabs/panes 不变 | 返回打开前的有效焦点，保留插件进程 |

插件仍在自己的进程内用 Ratatui Buffer 绘制；宿主复用现有帧校验、主题、宽度和输入契约。窗口位置不改变插件业务实现，也不启动第二个插件进程。首阶段一个插件仍只有一个逻辑视图，不允许同时在两个位置接收输入。

覆盖界面不写入工作区布局，不恢复为永久 tab。打开时保存来源焦点；来源已消失则返回 Agents。关闭/停用/崩溃后的迟到帧和输入不得落到下一个打开的界面，沿用会话身份与尺寸修订校验。

从 `+` 或 Split 选择 Plugin… 时，复用插件状态列表；只有运行且有界面的插件可打开，已有工作区视图标为 Move。选择前不创建空窗格；取消保持布局。分屏不能选择来源窗格自身的插件。显式位置覆盖清单默认值，插件仍使用同一套 workspace 尺寸、绘制和输入协议，开发方式不变。

Settings、确认框或另一个覆盖界面已打开时，拒绝新的覆盖打开并保留现有界面，不偷偷丢弃草稿或替换确认目标。Ctrl-] 返回 Agents；覆盖界面的 Esc 由宿主用于关闭，插件需在握手时知晓该保留键，不把 Esc 同时当成业务输入。其他输入仅送给当前可交互区域。业务二次确认可在插件画面内部完成。

入口打开时可携带当前选中/聚焦 agent 的公开身份和已知项目目录；值未知就明确缺失，不读取 Corral 内部数据，不自动猜任务 ID。插件把这次上下文当作打开时快照，不会因焦点后台变化而自动替换用户正在确认的业务目标。

## 3. 提醒：短提示与持续条目分开

现有 notify 继续表达“一次短提示”，保留去重、限流和 accepted 不等于用户看见的语义。不把通知增加、消失或点击解释为任务完成、接受或派发。

Attention 扩展采用插件来源的当前条目快照：每条有插件局部稳定 ID、短标题/说明、要打开的操作，以及插件自己解释的目标数据。Saddle 校验来源、容量和操作引用，负责汇总展示；不理解任务号、Running/Awaiting/Done，也不代替插件保管业务真相。

- 快照替换只影响该来源；空快照明确表示没有条目，没收到新数据不表示清空。
- 条目出现或变化不必然触发短提示。何时提示、重启基线和业务去重由插件决定。
- 点击只负责打开相应视图并传入目标数据；插件重新读取公开业务状态后展示，接受等写操作仍由用户明确触发。
- 插件断连时来源显示不可用，旧条目失效且不能点击，不能显示成“已处理”。停用/移除撤下该来源；这只改变界面，不改变任何业务状态。
- 首期不建立通知持久化服务、跨插件事件总线或任务推进后台。多实例业务去重仍由插件按自身公开契约处理。

该快照与“打开指定目标”现由 attention.v1 提供，不复用 notify 的会话内计数器当业务 ID。消息字段、预算和过期目标校验见协议 §10；独立 Attention demo 验证该通路，Counter 无需升级。

## 兼容与职责

现有插件清单继续工作，仍可从管理页打开工作区面板。新入口、覆盖位置、上下文和 Attention 分别以明确的能力声明协商；旧宿主不能把必需能力忽略后假装支持。每项实际实施时更新清单校验、握手、公开类型、SDK 与协议说明；当前协议文档仍描述已交付功能，不提前把草案写成可用 API。

Saddle 只增加通用入口目录、视图展示位置和 Attention 来源接口。Drover 自己保留队列读取、目标令牌、提交/接受、通知基线等逻辑；Corral/corral-dispatch 不变。迁移后同一任务来源只保留一份适配，避免内建 Drover 与插件同时轮询、重复入口或重复通知。

## 实施顺序与观察方式

1. **Counter 入口和展示位置**：启用后从 Saddle 的 Plugins 面板打开，验证工作区/覆盖位置共用同一插件和画面协议，关闭重开仍保留计数。先落这一小段；不接真实任务、不修改 Drover。
2. **通用 Attention 来源**：用独立合成条目验证更新、撤回、断连失效及点击打开指定目标，与已有短提示明确分开。仍不操作真实任务。
3. **Drover 迁移**：列清现有 Tasks、Attention、通知偏好、项目选择和关联跳转的搬迁清单，再实施。任务编辑的输入光标等缺口按实际清单补齐，不在此稿预造控件框架。

Drover 的目标体验：启用后在 Plugins 面板出现 Tasks，选择后打开任务覆盖界面；任务待验收时 Attention 和提示按现有规则出现；点击提醒打开对应任务；用户仍亲自提交/接受。停用后列表显示已停用，不提供任务操作，终端和 agent 操作继续可用。当前内建 Drover 尚未搬迁，这段是目标，不是现有行为。

## Herdr 参考与取舍

只读核对了本机 Herdr 0.9.3、同版本源码和已安装的 Herdr Plus。Herdr 把 actions 和 panes 分开声明，操作可绑定快捷键或经CLI/API调用；本轮复核未确认内建菜单会自动列出全部插件动作，窗口支持不同 placement；其插件 v1 的窗口承载终端程序，并未提供原生非终端 UI。

本设计借鉴入口/承载分离，保留 Saddle 已有的结构化绘制；统一插件入口与 Attention 来源是 Saddle 自己定义的扩展点，不声称 Herdr 已有完全相同的机制。也不照搬其每项 action 启动 argv 命令的模式，Saddle 继续复用已启用的插件进程。
