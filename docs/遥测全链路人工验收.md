## A. 正常链路：小任务从 Pending 到 Done

### A1. 在 Saddle 创建测试主控

1. 点击左侧 Agents，让焦点回到 agent 列表。
2. 点 **New**，或在 Agents 焦点下按 **n**，打开 New agent。
3. 按下表填写；不要沿用自动带入的 Saddle 仓库目录。

| 界面项 | 填什么 |
|---|---|
| Project / Directory | 点击 **Edit path**，粘贴上面的测试仓库绝对路径 |
| Agent | 选 **Codex** |
| Role | 选 **Controller** |
| Prefix | `saddle-e2e-20261002-113520` |
| Name | Controller 模式下应为 `main`；核对完整名字与上面一致 |
| Advanced → Open in | 选 **New tab**，便于保留当前对话 |
| Advanced → First message | 粘贴下面这段 |

First message：

> 你是这个测试项目的主控。先读 AGENTS.md 和 corral-dispatch 技能，只确认已就绪，等待我从 Drover 正式派发任务。现在不要实施、委派或操作队列。请检查你的实际执行环境里 TYPESAFE_API_KEY 是否非空，只报告“已设置”或“未设置”，不要输出内容，也不要提前请求 JEV。

4. 点 **Create agent**。等主控启动并回复；首次信任提示由你亲自确认。

**检查并勾选：**

- [x] 新 tab 中是测试主控，工作目录是测试仓库。
- [x] 主控已读规则并等待，没有提前开实现者。
- [x] 主控报告密钥已设置。当前 saddle/main 有密钥不代表新主控一定有，以新主控的检查为准。

若密钥未设置，把结果告诉我，先处理这个准备缺口；不要把密钥粘贴到聊天中。真实 JEV 成功会用到外部服务，缺 key 不能算正常路由通过。

### A2. 在 Tasks 界面添加测试项目

先确认本次带 **Add project** 的 Drover 插件已经更新并重新启用，再开始这一步。无需运行 `drover init`，也不用让主控替你注册。

1. 点 Saddle 的 **Plugins**，选择 **Drover**，打开 Tasks。
2. 点顶部 **Project** 项目选择器（或按 c），再点 **Add project**（a）。
3. 在 **Directory** 粘贴上面的测试仓库绝对路径（Ctrl-U 清空），点 **Check / Reload**。也可以点 **Browse** 浏览目录，进入测试目录后点 **Use directory**。
4. 应显示 **Not added to Tasks**。确认 **Project short name** 为 `saddle-e2e-20261002-113520`。
5. 点 **Choose agent**，选择 `saddle-e2e-20261002-113520/main`。这只设置默认接收方，不启动或派发任务。
6. 点 **Save**，进入该项目的任务列表。重新打开项目选择器时，应看到 **Added** 和所选主控。

如果显示 **Existing Drover configuration found**，点 **Reuse & add** 沿用原配置和数据；接入后在 Projects → **Settings** 核对接收主控。如果显示 **Already added to Tasks**，直接点 **Open**；不要重新建目录。显示 **Unavailable** 时先查看原因，不覆盖原配置。

**Project settings** 中可更换主控，或 **No receiver** 改成手工交付；Cancel 不保存。接入不会修改 AGENTS.md，不会强制项目以后只能通过 Tasks 工作，也不自动开启遥测。

### A6. 在 Saddle 看主控与实现者工作

你不用运行路由命令，也不用手工开实现者。等测试主控按规则推进，必要时在 Agents 中选择它新开的实现者，查看实时终端。

- [ ] 主控通过 dispatch 插件请求 JEV，能给出路由结果和自己最终采用的档位/模型/理由。
- [ ] 实际开了专用实现者，而不是主控自己写功能。
- [ ] 主控交付的任务书仍只要求求和与三个测试，没有擅自变成网页、服务或其他功能。
- [ ] 实现者完成后，主控实际审查，再报告测试、本地合并和清理结果。
- [ ] 不要求为这个小任务强行另开独立审查者；有主控审查记录即可。
- [ ] 主控没有替你把任务提交或接受，Drover 仍是 Running。

**JEV 成功与兜底分开算：** 若缺 key、请求失败或插件不可用，主控可以自行定档继续；但这不能算“A 的真实 JEV 成功路径”通过。JEV 响应成功但某项建议为 null，则可以由主控自行判断，不等于请求失败。

想核对产物时，在测试主控对话里说：

> 请展示三个求和例子的实际输出和自动化测试结果，说明你核对过哪些改动，不要再次派发或操作 Drover 状态。

三个结果应为 **5、1、0**。程序可以是命令行程序，但测试操作由主控执行，你在 Saddle 里看结果。

### A7. 由你人工提交和接受

1. 回到 Drover，选中 `E2E-A`。
2. 点 **Submit for review**；核对确认框中的任务，再确认。
3. 任务应进入 **Awaiting release**。先停一下，看看状态及已配置的通知。
4. 确认主控报告与产物符合要求后，点 **Accept**，核对确认框后确认。
5. 任务应进入 **Done / History**。

- [ ] Running → Awaiting release → Done，每次都由你的动作触发。
- [ ] 未自动派发下一项。
- [ ] 若要验通知，提前在 **Notifications** 选择一种方式，让这次新变化触发通知；不在变化之后切设置再要求补弹旧通知。

### A8. 从任务进入遥测，核对整条链路

1. 在 Drover 选中本任务，点 **Telemetry ↗**。
2. 选择本轮链路，点 Open 或按 Enter。
3. 选事件，按 **Enter / Read** 打开正文；使用页内滚动，Esc 返回。看页面底部的快捷键提示操作即可。
4. 主控刚完成新操作时，点 **Refresh** 再查看。

逐项核对，不要只看“列表里有一条”：

| 看什么 | 应该看到什么 |
|---|---|
| 原始任务正文 | 与 A4 填的内容一致，来源标为实际交付方式 |
| JEV 路由 | 摘要、实际请求、完整解析响应与建议；不是只剩三个结论 |
| 主控决定 | 实际档位/模型/强度及理由，与 JEV 建议分开 |
| 任务书 | 实际交给实现者的完整快照；对照 A4，确认没有私自扩大范围 |
| 实现者与操作 | 本次派发身份、agent instance 和实际执行结果能对应 |
| 完成回复与审查 | 能打开完整回复与主控审查正文 |
| 任务流转 | 有本轮进入 Running、Awaiting release、Done 的记录 |
| 收尾 | 本地合并和清理结果真实；本测试未推送，就不能写推送成功 |

- [ ] 长正文能读到结尾，不只是摘要或路径。
- [ ] 没有把缺结果、unknown 或采集失败显示成已成功。
- [ ] 若同一任务有多轮，选这一次 run，不凭相似标题猜。

遥测不是对所有聊天的自动录屏。主控必须按技能记录声明与材料；这里也在验它有没有正确遵循流程。顶部摘要可能比固定上限的事件列表新，先 Refresh 再比较。
