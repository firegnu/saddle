# T77 遥测展示整理方案

2026-10-04，saddle/dev-t77-design。状态：设计稿，待主控对齐后在同一分支实施。

## 推荐（一句话）

只动 Drover 任务详情的绘制：**Telemetry 跳转改成一眼能认出的“打开”链接，并在 Run details 首屏加一个 `Look further` 小节，逐条写明报告、原始运行记录、完整遥测各在哪里、怎么打开**；其余内容一行不删，只合并重复的说明句、弱化技术标识。不改采集、存储、查询（`telemetry/reports.rs` 不动）、任务状态、插件协议和宿主 Telemetry 页面。

## 现状问题（源码核对）

1. **跳转链接看不出来**：`queue.rs` `draw_content` 的页签行最右放 ` Telemetry ↗ `，颜色用 `t.text`。普通页签是 `t.muted`，当前页签是 `focus`+粗体+下划线，所以链接看上去只像一个“稍亮的页签”。它只能用鼠标点（`telemetry_click()`，没有键），Run details 正文里却多处写“open Telemetry”“Full chain: Telemetry”，读到这些字的地方没有可点的东西。
2. **首屏说明句重复**：`overview` 尾部 1–2 句、`reports` 开头 2–3 句，都在讲“不代表成功 / 完整链路去 Telemetry”。
3. **技术标识混在正文里**：每份报告正文后面的 `Event`、`Dispatch`，以及 `Trace`，和正文一样用 `t.text`。
4. **下面还有什么，首屏看不出来**：报告份数、之前几轮、退回历史，都要往下滚才知道。

## 拟改动（全部在 Drover 插件内）

| # | 位置 | 改什么 | 不改什么 |
|---|---|---|---|
| 1 | `queue.rs` `draw_content` 页签行 | 文字改为 `Open in Telemetry ↗`（窄时 `Telemetry ↗`）；颜色用 accent（`t.focus`）加粗、不加下划线，前面空一格放一个 muted 的 `│` 和页签隔开。和当前页签的区别不只是颜色，还有“Open in”这个动词、↗ 符号、没有下划线、靠右独立摆放 | 位置靠右、只能点、同一个 `telemetry_click()`、同一个 `TelemetryFilter`（全部轮次，`run: None`）、未编号任务不显示、不可用时变暗 |
| 2 | `detail.rs` `overview` | `Next step` 移到第一行；先放 Review/Closure/Submission/Acceptance，再放四类投递节点；说明句只留“不代表整体成功”这一句，多委派那句保留 | 每行的字段和取值、未知或缺失时的文字 |
| 3 | `detail.rs` 新 `look_further` | 新小节 4 行：报告数和“在下面”、本轮和之前几轮及退回条数、完整链路链接、run/trace 标识。数字全部来自已读的 `reports.entries.len()`、`previous_runs.len()`、`return_history.len()` | 不发新查询，不推断任何结论 |
| 4 | `detail.rs` `reports` | 标题加份数；开头两句合并成“声明不等于验收”和“后面的报告可能修订前面的”两句；`Event`/`Dispatch` 合成一行 muted；`Trace` 改 muted | 每份报告的标题、verdict、links、正文全文、正文读取失败的原因 |
| 5 | `queue.rs` 画详情时 | `TaskDetail::lines` 额外返回 `Full chain` 那一行的行号；这一行滚到可见区时，在该行的链接文字上加一个 `Hit`，key 用同一个 `telemetry_click()` | 处理函数不动，所以它的条件（列表页、编号任务）也不变 |
| 6 | Help 页、README、DESIGN.md | Help 里的键名改为 `Open in Telemetry ↗`；README 的 Run details 段落和 DESIGN.md 补一节简短记录 | 键位不变 |

不新增快捷键、页面、弹层、宿主能力、协议字段和颜色角色。

## 源码已有的 vs 本次要改的

- **已有**：`telemetry_click()` 和对应的处理函数、`TelemetryFilter` 已带可选的 `run`、宿主按 binding 打开 Telemetry 并筛选、`buttons::Hit` 点击区、详情的滚动和 `view` 夹紧、`field`/`note`/`heading` 排版、报告和节点数据（`Reports`）。
- **要改**：上表 1–6。都是 Drover 里的绘制和文字，外加一个在可见行上登记点击区的小改动。
- **宿主 Telemetry UI**：不需要改，所以不碰。

## 取舍

- **不拆成多级页面或折叠区**：折叠要加状态和键位，多级页面违反“不造复杂页面体系”。只在首屏指路、下面保持一整页往下滚，原有的阅读位置、刷新和夹紧行为都能保留。
- **链接用文字加强调，不套按钮框**：设计语言写了“链接不强行套按钮外框”。靠动词、↗ 符号、位置和不加下划线来和页签区分，不只靠颜色。
- **正文里再放一个可点链接**：用户读到“Full chain”的地方就能直接点，不用回到右上角找。用的是同一个点击 key，处理逻辑不变。代价是 `lines` 要多返回一个行号。
- **`seq` 和时间戳仍留在首屏**：它们是到 Telemetry 里对照事件的依据，删掉就少了对应线索。只在报告里把 ID 类信息弱化。

## 待主控对齐

1. 链接文字用 `Open in Telemetry ↗`，可以吗？现有测试按子串 `Telemetry ↗` 查找，改了也不会失效。
2. 正文里可点的 `Full chain` 行（第 5 项）要不要做？不做的话，那一行只写“top right”。
3. **默认不做**：从 Run details 只打开**本轮**遥测（用现有 `run` 字段）。这会改变“打开全部轮次”的既有行为，作为可选项列在这里。
4. 实施时的验证：`cargo test -p saddle-drover-plugin --lib --test ui --test ui_drover_polish --test process`，外加 clippy（`-p saddle-drover-plugin --all-targets -D warnings`）。现有测试会更新断言，不放宽；另外补测：首屏有 `Look further` 和三个去向、两个链接点下去都发出同样的全部轮次请求、窄屏下报告仍能滚到。只改插件，不跑全仓测试。
