## 1. 输入和输出：这次实际迁什么

输入是现有corral-dispatch整套资源和Saddle已有插件/遥测接口。目标交付是同版本Saddle中的可选官方dispatch插件，包含路由工具、skill与项目规则模板，并可选记录路由过程。它没有一个现成的常驻派发服务可直接搬入；拆任务、选择模型家族、审批、派发、审查、合并和收尾仍由主控按指令完成。

| 资源 | 当前职责 | 迁入后建议归属 |
|---|---|---|
| SKILL.md | 拆任务、任务类型/任务书模板、模型分工、验证预算、派发、审查返工、收尾 | dispatch插件随版本提供的指令资源；保持可读Markdown |
| 项目AGENTS模板.md | 项目明确采用主控分派、命名/worktree/合并等项目参数 | dispatch插件提供模板与预览；由用户明确采用，不静默修改项目文件 |
| route.py | 请求JEV并整理三项建议 | dispatch插件内部Rust路由模块；最终无需Python脚本 |
| README.md | 安装、API key、降级判断、技能及模板使用说明 | 插件使用文档，与资源版本同步 |
| corral基础skill | agent创建、送话、等待、回复和关闭的公共操作说明 | 保持基础Corral职责；不是dispatch插件拥有的资源 |

建议保留技能名 `corral-dispatch`，插件显示名可以是Saddle Dispatch、内部ID为dispatch；先不因产品归属改变技能触发名，否则现有AGENTS引用与用户调用同时失效。命名是建议，尚未写入安装版。

## 2. 已查证现状

### 2.1 技能确实存在，模板也必须迁入

实际来源为 `../corral/corral-dispatch-skill/`，Corral HEAD `6923da1ee0c766468c31e1f577fb8370b8b6da77`，该资源目录工作区无改动。现有四文件为SKILL.md、项目AGENTS模板.md、route.py、README.md。

本机 `~/.agents/skills/corral-dispatch` 和 `~/.claude/skills/corral-dispatch` 都是指向该目录的软链接；因此移动/修改旧源码会影响现有会话以后读到的资源。此次只读取，没有改链接。`corral install-skills` 的源码 `../corral/src/corral/skills.py` 只安装基础corral技能；dispatch README另行要求链接整个目录。不能把两者安装行为混为一谈。

模板故意不叫AGENTS.md，避免被agent当成当前目录的强制指令。模板包含“主控不写功能代码”、被委派者不再派发、原话验收、agent名前缀、worktree位置、审查/合并/空提交和清理规则；这些是项目选择采用的约定，不是宿主运行时规则。模板中的CLAUDE.md软链接只是说明，不授权迁移时批量创建或覆盖用户文件。

技能内的任务文件模板也必须保留，不能只迁外置项目模板。它还依赖corral基础技能进行生命周期操作；外围迁移期间继续使用其公开契约，不能顺带改Corral源码或私有状态访问方式。

### 2.2 JEV职责比“给难度”更具体

当前route.py在一次请求里询问档位、交叉审查、影响面。模型家族由主控依skill选，JEV不决定使用Claude还是Codex。任何null或请求失败由主控兜底，项目可写“不用路由”，不阻断委派。

本地脚本固定模型 `jev-1.13.0`、URL `https://api.typesafe.ai/v1/systemone`；key只从TYPESAFE_API_KEY读。超时10秒，HTTP429/529或网络超时等最多重试一次，部分路径等待1秒。shape保留当前概率舍入、置信度/阈值规则及usage字段。这些是本地实现事实，未验证远端服务版本或可用性，本轮没有发请求。

CLI从stdin读取摘要并strip；请求只发摘要，不发任务书。未来任务书快照可以本地进入遥测，但不能因采集而增加发给JEV的内容。保存实际请求JSON和解析响应，不保存Authorization头/key，也不把解析JSON称为HTTP原始字节。业务网络重试与遥测写入重试必须分开。

### 2.3 Saddle现有能力及缺口

| 当前代码 | 已有能力 | 不能直接假定已有 |
|---|---|---|
| src/plugins/registry.rs | 外部包清单、相对executable、enabled、可选view/action；添加默认停用 | 官方内置插件目录、headless命令贡献、技能/模板资源声明与安装所有权 |
| src/plugins/runtime.rs、src/control_cli.rs | 运行中TUI转交command.v1；一次命令带session/id、不重放 | 无TUI时运行插件命令；command参数上限48KiB，不适合传完整证据正文 |
| plugins/drover/package.sh | 单独编译打包插件目录，插件拥有业务 | 自动成为同一Saddle产品发布的一部分；发布资源安装器 |
| src/telemetry/capture.rs | Store prepare_operation/record_begin/record_end；进程内非序列化Capture固定generation | 将Capture经JSON给外部插件；普通append声称直接观测 |
| src/main.rs | agent、telemetry、ctl三个入口 | dispatch插件命令或skill安装命令 |

所以不能只复制route.py，也不应把JEV挤进当前command.v1来假装完成headless插件支持。当前外部进程插件模型与官方core plugin的统一打包仍有一层通用接入设计要完成。

## 3. 推荐的运行结构（待确认）

建议官方dispatch采用同版本Rust core plugin：业务代码与资源放 `plugins/dispatch/`，宿主通过通用插件目录和命令分发注册它。它可以与宿主编译进同一发布物，启用/调用边界仍由插件管理；同一进程不等于业务归宿主。第三方现有进程插件机制保留，不强迫Drover或其他插件先重写。

```text
主控读取 dispatch skill 与项目自己的 AGENTS
  ├─ 调用已启用 dispatch 插件的 route
  │    ├─ 插件构造请求 → JEV → 解析/整理建议 → 返回主控
  │    └─ 可选调用通用采集接口 → Saddle 遥测
  ├─ 主控结合建议选择实际模型/强度/预算并提交决定记录
  └─ 主控调用 Corral（或需记录时 saddle agent）完成委派

无 dispatch 插件：手动 Corral 委派 / saddle agent / telemetry 仍独立可用
```

候选公开入口优先采用通用形式，如 `saddle plugin run dispatch route ...`，而非把dispatch硬编码成宿主必备子命令；具体拼写待接口设计。命令先检查插件可用/启用，缺失或停用则在请求前明确返回不可用，不暗中执行宿主备用JEV逻辑，不自动启用插件。无需运行TUI，不选择TUI实例，也不新建常驻daemon。

插件启用与关闭遥测是不同开关。遥测关闭不禁用插件路由；插件停用不禁用遥测。建议停用阻止后续新调用；已经发出的JEV请求不因插件管理动作被默认为没执行，其完成/取消语义另在命令契约明确，不能自动重试补偿。

宿主只理解插件ID、入口、通用参数传递、状态和能力注册，不理解JEV问题、模型映射、任务难度、任务队列或分派条件。完整路由规则、HTTP客户端与建议解析仍在插件内。

## 4. 遥测接入建议与依赖方向

推荐在官方core plugin的进程内提供窄的通用可选采集接口，由宿主实现存储。接口声明放通用SDK/独立接口层；dispatch依赖该接口，不能依赖Saddle应用crate后再被Saddle反向依赖。插件持有本次采集会话，宿主实现内部保留既有Capture，不把generation或可伪造的捕获token作为公开JSON参数。

调用顺序是：插件固定本次实际请求与输入 → 显式选中时通过接口准备快照/begin → 插件自己请求JEV → 通过同一个采集会话保存取得的完整解析响应和建议 → 返回业务结果及独立采集状态。没有上下文、关闭或存储不可用时，路由仍执行；旧generation被撤销后end不能换新凭据补写。不能以遥测失败为理由再次调用JEV。

这复用同进程Capture的能力，但保留插件业务归属和启用检查。需要验证通用接口在无遥测实现时可用、插件可单独测试、没有上层循环依赖，以及快照/begin原子性和关闭期间结果丢失的明确回执。准确方法名、正文流转、错误分类和取消边界仍待接口设计，本文不直接批准实现。

`execution_observed` 表示同版本受控执行路径采集，不是对任意插件的身份认证。第三方经普通CLI提交仍是plugin_statement/controller.note，不能因为自报插件ID或调用append就获得直接观测标签。现有来源规则不放宽；若未来要支持任意外部进程插件的同等级现场采集，应单独设计，不能暗加跨进程token协议。

备选是独立进程dispatch再调用通用捕获服务。它需要解决一次调用凭据、进程退出/关闭撤销、完整正文通道和服务可用性；当前没有这些能力，因此本轮不优先推荐。此比较不授权把插件业务迁到宿主来回避问题。

## 5. 插件可用性、技能安装与项目约定

| 状态 | 意义 | 不应自动做的事 |
|---|---|---|
| 产品携带dispatch组件与资源 | 同版本发布物中可选能力已存在 | 不因此启用路由、改项目AGENTS |
| 插件已启用 | 允许该插件的新路由调用 | 不因此开启遥测、启动派发或覆盖全局技能 |
| agent已安装skill | agent可发现分派流程，按请求或项目规则选用 | 不使所有项目默认委派，也不证明插件启用 |
| 项目AGENTS已采用分派约定 | 该项目默认采用主控分派 | 不作为Saddle管理的项目状态，也不授权真实队列放行 |

用户已确认首版不增加项目启用开关或项目采用名单。未写分派约定的项目不因全局skill安装而默认委派，但用户当次明确要求完整分派流程仍可触发；仅要求开一个agent问问题时使用基础corral技能。skill与模板保留分工，不能把项目必须提前生效的规则全部移入按需读取的skill。

用户已确认停用行为D1：已安装skill与项目规则保留；插件未启用时主控明确说明路由不可用，自行判断档位，继续项目规则或当次用户已要求的分派流程，不暂停询问、不回退隐藏route.py、不自行启用。未要求分派的项目不会因此自动委派。已复制的项目规则不会因停用插件被抹掉，修改项目工作方式仍由用户决定。

agent已经加载进上下文的skill不能被卸载动作从记忆里撤回；可保证的是新调用入口的启用检查和文件安装状态，不能承诺旧会话忘记指令。新资源切换提示是否需新开/重新加载会话，按实际agent行为说明，不把静态文件替换当作已生效。

## 6. 资源安装、升级、卸载与过渡建议

- 插件包同时带SKILL.md、项目AGENTS模板.md、README和资源版本信息。route.py迁成Rust后，新skill改用插件公开入口；旧脚本仅在阶段05切换前继续服务旧流程，不长期双写或维护两套日常入口。
- 宿主依据插件声明提供通用资源安装/更新机制，不把dispatch文本写死在宿主安装器。按最新用户决定，用户选择安装/启用插件时自动完成对应skill安装，不要求再单独安装skill；具体触发点及失败处理在接口设计中固定。普通打开Saddle不构成覆盖用户资源的授权，同名冲突/用户修改不能静默覆盖。
- 保留技能目录名corral-dispatch，安装整个资源集合，避免SKILL相对引用找不到模板；正式版用同版本发布资源，不链接开发checkout。第一批沿用当前Claude/Codex两个已使用目标；其他agent的skill发现机制不在未调查时宣称支持。
- 安装应记录拥有的目标路径、资源版本与内容指纹。升级不覆盖用户自行修改的内容或来源不明同名目录；先给出具体冲突。卸载只移除自己拥有且未被改写的资源，不删除源仓库、项目AGENTS或用户文件。具体机制作为通用资源安装方案验证。
- 当前两个dispatch软链接属于旧安装，不能按新安装器的所有权自动删除；阶段05明确预览旧链接、备份/回退再迁移。本轮不更改任何链接或全局技能。
- 首版项目接入方式已获用户确认：在插件安装或首次启用入口展示插件提供的说明及随包项目AGENTS模板位置，指导用户仅为希望默认主控分派的项目手工合入规则、填写参数并处理已有约定。具体提示位置/文案待入口设计；不在每次路由调用重复提示。不提供项目启用开关、自动插入/覆盖/删除AGENTS或必经的agent配置流程，不修改现有CLAUDE.md链接。保留模板现有语义；插件停用不删除项目规则。

## 7. 路由行为与可观察记录

新路由模块先保持旧输入/输出语义：摘要为主控提供、只发送摘要；三项建议及不确定null保留；模型家族和实际选择仍由主控按skill决定。模型版本、规则版本/内容指纹及实际请求JSON可关联入库；成功时分别保存完整解析响应与整理建议，不能用后者替代前者。key不进入参数日志或正文；无key/服务失败时输出路由失败与主控兜底指引，不阻止手动委派。

暂不改变旧阈值、模型分工、验证预算或网络重试策略来顺手优化路由准确性。需要调整时另行明确，避免将移植产生的差异与以后评估的策略差异混在一起。
