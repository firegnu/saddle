## 1. 证据与使用方式

值得在这次整理中确定一套轻量的设计语言：统一视觉语义、同类组件、信息层次和尺寸适配规则；不另造大组件框架，不为了统一而推翻已有操作习惯。精致来自可读、克制和一致，而不是给每个可点元素增加装饰。

Claude 初审覆盖源码和设计文档，Codex 对主要分歧作了静态复核。没有运行 UI、截图、预览或测试。下文区分：

- **明确修正**：源码能确认的错误文案、对齐、布局规则或信息重复；实施时仍需相应展示检查。
- **整理建议**：事实差异已存在，但采用哪种视觉表达属于设计选择，不能称为功能缺陷。
- **待渲染确认**：真实对比度、拥挤程度、终端兼容，以及残字和遮挡的实际观感与出现频率，尚无实际画面证据；不否认表内已由代码确认的残字条件和几何重叠。
- **本轮之外**：需要改变业务、协议、快捷键映射、导航或产品能力的内容，另行讨论。

现有设计依据：[主设计](../DESIGN.md)、[主题设计](../UI主题设计.md)、[插件入口与界面接入](../插件入口与界面接入设计.md)。现有已批准规则仍优先；新提议待用户选择实施时确定，不能把本报告写成追认授权。

## 2. 这次统一的边界

允许讨论和建议调整布局、绘制、对齐、间距、颜色角色、标题、可读标签、已有操作的提示和显示顺序。界面继续使用英文；用户正文、报告和原因保持原文。

不改变任务状态机、运行身份与令牌、权限、升级语义、查询和分页语义、数据结构、持久化、自动化、PTY/输入协议、agent 生命周期。未知、过期、失败、accepted/pending 不能因视觉整理被呈现为成功。

不新增快捷键或改变现有按键含义、默认焦点及危险确认行为。移动按钮或标签时同步现有命中区域，保留操作语义；需要改变导航层级或 Tab 顺序时另列交互变更，不夹带进纯展示补丁。

Agents 3a 侧栏、三行圆角工作区 Tab、插件覆盖层灰细框等已有明确设计不一刀切替换。关闭显示、停止 agent、关闭 shell 继续保留各自原有含义。

## 5. 初审中撤回、降级和排除的提议

1. 撤回“Diagnostics 与 Updates 的 Refresh 权重不同就是问题”。按页面目的决定主操作。
2. 将“所有弹窗同外框、同尺寸”“所有列表同样式”修正为同类组件统一，保留有依据的组件变体。
3. 撤回“黄色只能用于焦点”的固定颜色禁令；采用角色与非颜色线索，保留现有主题和覆盖。
4. 不给每个入口加按钮框，不在每一处重复所有快捷键，不给没有键的操作补新绑定。
5. H9 从初审推测升级为锁定依赖源码确认，仍未运行复现；对比度、实际密度等未验证项不能写成已确认观感问题。明确的显示差异也不自动构成高优先级问题。
6. 不把 Add a 改成 No tasks yet 后掩盖已有历史任务；不把缺快捷键、没有搜索框标题等直接等同为功能缺陷。
7. 扩展插件主题协议、移动端实现、统一命令入口、项目接续与任务交付新能力属于后续能力建议，不搭车本轮 UI 整理；既有队列关联见第 9 节主控背景，不属于双方共同核实范围。

## 6. 建议实施顺序

以下是建议的实施分组，不是已派发任务，不改变现有 Pending 顺序。开始实施仍由用户触发。

1. **确认本意见并准备代表性画面**：先看 Settings、Tasks 主界面、一个选择列表三类，再补 Tasks 表单、Telemetry、New agent、Diff。与设计语言文档采用方式一致。用合成数据展示常规/窄/矮窗口以及长文本、空、加载、错误、陈旧状态。先确定间距、选中、焦点和按钮层级，不同时重做全部界面。
2. **明确小问题**：错误快捷键帮助、Split 与确认页对齐、状态栏短 notice 残字、已过时文案；toast 几何重叠需结合画面决定调整位置。每项保持业务和输入映射不变。
3. **公共规则与高频界面**：按已确定的组件族整理，包含状态栏 X5、消息配色与层次 X6、按钮文案 X3；先 Settings，再 Tasks 动作条，不强行抽取新框架。
4. **其余宿主及插件**：Telemetry、New agent、终端与选择器、Drover 表单/Help/Links，最后 Diff 的模式/页脚/现有主题映射。
5. **保留回归样例**：让后续公共样式改动能看到跨界面影响。静态和合成展示验证不冒充真实终端/真实 agent 端到端验证。

新增展示回归应明确归属；不把“整体变好看”作为覆盖错误操作或信息丢失的理由。既有测试背景单列于第 9 节。文案和标签对齐等无争议小修不依赖视觉选型，可以提前或并行安排，仍须用户触发实施。
