## 选择与依据

选用`ureq = { version = "=3.4.2", default-features = false, features = ["rustls"] }`，写入Cargo.lock。官方发行包MSRV为1.85，项目1.96满足；该feature采用rustls、ring和webpki-roots，不引入native-tls/OpenSSL系统运行库。ring的本地编译仍待实施阶段标准构建确认；没有执行成功的预先保证。关闭默认gzip，使用既有serde_json处理原始体，不开启全局preserve_order。

- [发行源码](https://static.crates.io/crates/ureq/ureq-3.4.2.crate)，本机只读副本 `/var/folders/vs/3tm61ygs569g764_td0zxtym0000gn/T/saddle-03c-ureq-research-mn5um66z/ureq-3.4.2`；核Cargo.toml.orig/features、src/run.rs、src/timings.rs、src/unversioned/mod.rs。
- [配置接口](https://docs.rs/ureq/3.4.2/ureq/config/struct.ConfigBuilder.html)：显式max_redirects(0)、http_status_as_error(false)，自行处理所有非2xx及限量错误正文。无global/per-call总超时；分别配置解析/连接/请求头发送/请求体发送/响应头等待/响应体读取预算。recv_body是阶段总预算，不是每次read重新计时。
- [TLS接口](https://docs.rs/ureq/3.4.2/ureq/tls/struct.TlsConfigBuilder.html)：Rustls/WebPki默认组合；不暴露关闭证书验证或替换生产URL的入口。

## 重试分类的实施注意

[Error枚举](https://docs.rs/ureq/3.4.2/ureq/enum.Error.html)中的Io没有发送阶段；不能仅按Io错误种类把等待响应时的reset重试。保持已批准设计：仅首次429/529延迟1秒；请求完整发出前的错误或任意超时允许一次重试，发出后的非超时错误/截断/无效JSON不重试。

发行源码run.rs中send_request/send_body先完成，随后recv_response；没有非重定向的请求自动重试循环。若高层Error不足，允许插件内部局部适配默认Connector/Transport来保存发送/接收阶段，不改ureq源码或Corral，不造通用网络框架。[Transport公开低层接口](https://docs.rs/ureq/3.4.2/ureq/unversioned/transport/trait.Transport.html)可观察transmit_output/await_input；NextTimeout携带reason，但reason只是最近截止预算，不能脱离配置假定它永远等于当前阶段。不得用请求体Read已耗尽当作网络发送已完成的证明。

unversioned接口可能随minor变更，因此精确固定版本，包装局限于插件transport模块；如仍无法保留设计行为，先报告最小缺口而非默默扩大重试。正式语义以接口设计5.1/5.2为准。测试仅假传输/回环服务器/合成凭据；实际TLS链路、代理环境兼容性没有在本次研究中验证。
