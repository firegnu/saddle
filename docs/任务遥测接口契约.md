## 1. 这轮评审修正了什么

2026-10-02新增定稿：[单任务遥测边界](遥测单任务边界设计.md)，本分支已实现，未安装或迁移真实库。该补充优先定义不可逆`trace close`、schema v2（输入schema_version仍为1）、只读兼容v1/v2与写入口迁移、`closed_at`查询、关闭后写入/采集拒绝及有界区间。原可逆set-recording继续表示暂停，与结束分开；已结束trace不允许补交或重开，原始历史仍可读，重新明确要求记录须新trace。Tasks run关闭顺序和失败回执见补充设计，不改变人工业务操作。当前使用文档已同步；不能将分支实现称为日常安装已提供close命令。

| 原草案缺口 | 收敛后的规则 |
|---|---|
| trace 建立后，没有明确交给主控的路径 | Drover 将显式记录上下文随本次任务交付给主控；后续逐次传参，不靠环境继承 |
| 所有证据引用必须同 trace，无法保留前一执行轮次的需求来源 | 允许显式复用已记录证据；新事件保留原取得方式，用唯一允许跨 trace 的 carried_from 指向原证据 |
| 任务书快照与 begin 分开成功，可能失去实际版本关联 | 同一次调用的快照、begin、关联和 operation 在一个数据库事务提交 |
| 只规定 event 幂等，创建 trace/dispatch 的回执丢失可能重复建链 | 三种记录创建均使用调用方预先生成的稳定 ID；重交只保存记录，不执行业务动作 |
| 同一 event 可以在事后补 link，绕过“当时依据” | event、正文引用和关联一次提交后不可修改；纠正与补录追加新事件 |
| 故障路径只写“失败”，消费者可能重派 | 明确纯记录命令与执行命令的两种回执；执行命令退出结果始终属于业务动作 |
| 关闭后重新开启，旧在途结果可能被新版本接受 | operation 固定开始时的全局与链路 generation；不重新取版本补写结果 |
| “Corral 迁入后内部调用”未明确依赖方向 | Saddle 上层分别调用 agent-core 与遥测；agent-core 不导入遥测，也不接收记录上下文或记录器 |

## 2. 模块及接入

Saddle 遥测模块处理开关、记录、证据引用、SQLite/正文持久化和查询。调用方不操作表、不选择哈希路径、不协调文件与数据库提交。

Saddle agent 入口负责实际 Corral 调用及现场采集。JEV 调用与路由建议属于可选的 saddle-dispatch 插件（corral-dispatch 迁入后的组件）；主控结合建议决定委派对象、模型和强度，宿主遥测不取得难度来驱动派发。插件的现场采集设计见第5.1节，尚未实现。仅显式选择记录时采集；不记录时不要求数据库存在或初始化，遥测不可用不阻止有效的业务调用。纯记录 CLI 只接收主控或插件提交的材料，不提供伪造 `execution_observed` 的选项。

### 2.1 Corral 零遥测依赖（用户确认）

```text
Drover / 其他插件 ──可选记录与查询──→ Saddle 遥测公开接口
saddle-dispatch 可选插件 ──调用 JEV，向主控返回路由建议
                       └─可选采集──→ Saddle 遥测接口（现场采集接入待设计）

Saddle agent 执行入口（上层组合）
  ├─ 执行业务 ──→ 当前 Corral CLI / 将来 agent-core
  └─ 按需记录 ──→ Saddle 遥测模块
```

这里的 Corral 与 corral-dispatch 是两个不同职责：前者是 agent 基础设施，后者迁入后仍是可选的分派工作流及路由插件。没有 dispatch 插件也能手动通过 Corral 委派；直接 Corral 调用不会自动被 Saddle 遥测捕获，需要记录时可显式使用已实现的 saddle agent 入口。插件提供的“主控不写功能代码、通过委派完成实施”属于工作流规则，不是宿主或 Corral 的强制限制；不改变本仓库 AGENTS 对当前主控的规定。

- 当前适配只在 Saddle 一侧实现。记录控制参数由 Saddle 消费，不为 Corral 新增遥测 argv 参数、环境、agent 标签或 hooks；其业务接口不增加 trace_id、dispatch_id、数据库路径或遥测开关。业务原有参数不因采集器而改变。第 7 节由 Drover 明确构造的主控交付附段属于普通消息正文，Corral 只按原 send 语义传递字节，不解析或使用其中的关联 ID。
- 将来迁入的 agent-core 不导入 Saddle 遥测模块、不接收 recorder/sink/callback，也不感知记录是否启用。不能通过“注入一个通用记录接口”把遥测职责隐藏进 Corral。Corral 原有的生命周期状态与内部运行事件仍由它正常维护，不属于新增任务遥测。
- 上层在调用前记录输入，在调用后记录公开返回或查询所得事实。Corral 只返回正常业务结果，不主动回调遥测。更深的内部信息若未公开，保持未知；不能为补齐遥测而读取 Corral 私有状态或修改其基础设施职责。
- 替换外部 CLI 为内部调用时，只改 Saddle 的调用位置与结果适配。agent-core 必须能独立构建和测试，不初始化遥测、不要求 SQLite 或 Drover。当前外部 Corral 也继续独立运行。
- 遥测模块不导入 Drover、corral-dispatch 或 agent-core 来驱动它们。它保存调用方提交的事实与声明；任务关联按不透明来源字段处理，第三方插件按同一公开契约接入，无须在宿主增加插件名称判断。

实现验证须覆盖：未选记录时不创建遥测目录；数据库不可用时假 Corral 仍只执行一次；传给 Corral 的 argv 与调用方业务参数一致、env 没有新增遥测上下文；将来 agent-core 的依赖与接口检查不含遥测类型或记录回调。最后一项在 Corral 迁入阶段执行，当前不提前迁移核心。

### 2.2 插件与存储接入

此处 Drover 始终指已经运行在 Saddle 中的 `plugins/drover/`，不是已退役的独立 CLI/watch；不恢复旧服务。Drover 保留任务业务状态及默认记录选择，调用公开记录/查询接口。插件进程由宿主提供当前 Saddle 可执行文件的绝对路径（拟为 `SADDLE_HOST_BIN`）；记录上下文不放在进程环境。不要将原来表示程序路径的 Corral 配置直接改成含空格的 `saddle agent` 字符串。

拟议存储位置沿用 Saddle 状态目录规则：绝对 `$XDG_STATE_HOME/saddle/telemetry/`，否则 `~/.local/state/saddle/telemetry/`。包含 `telemetry.sqlite3`、`blobs/sha256/`、`tmp/`。初建目录仅当前用户可访问，文件仅当前用户读写；查询无库时返回未初始化，不为一次查询创建库。记录关闭不删除已有内容。首期不提供任意备用存储后端。

## 3. 身份、字段与不可变关联

ID 是不透明字符串，生成策略采用 UUID v4；不得按任务号、时间、agent 名或路径生成关联。以下示例的短 ID 仅便于阅读。时间用 UTC；未知为 null，不能填成零或当前时间。

| 对象 | v1 必要字段 | 可选字段 |
|---|---|---|
| trace 创建 | schema_version、trace_id、origin（task/ad_hoc）、label | binding：kind/scope/key/run；四项一起给出，宿主只保存声明 |
| trace close | schema_version、trace_id、actor（声明） | 无；拒绝未知字段，不带正文 |
| dispatch 创建 | schema_version、dispatch_id、trace_id、kind | parent_dispatch_id；kind 为 implementation/review/redispatch/controller_handoff |
| 调用上下文 | schema_version、trace_id、dispatch_id | basis_event_ids、decision_event_id、previous_brief_event_id；只引用此前已保存事件；send 必须另有 send_kind=initial/followup/rework |
| 提交事件 | schema_version、event_id、trace_id、kind、observed_at、producer、payload、links、bodies | dispatch_id、operation_id；按下表限制；仅全局 recording.changed 的 trace_id 可为 null |
| 正文输入 | role、path | 无；绝对普通文件路径，保存该文件的原字节 |
| 事件链接 | relation、target_event_id | 无；关系由事件类型限制 |

`origin=task` 必须有 binding；它不证明任务已经开始。初次 trace 创建默认 capture_enabled=true，受总开关约束。后续只有开关操作可修改 capture_enabled/generation；外部绑定、parent 和既有事件不可改写。

每条事件由存储端生成 seq、recorded_at、fingerprint；正文哈希与字节长度由采集端计算并验证。公开 append 的 producer 及 controller_statement/plugin_statement 均是调用方未认证的声明，统一记录 source_auth=unverified；同一 CLI 不能证明提交者真是插件。只有 Saddle 实际执行/开关路径可生成 execution_observed/system_control，append 拒绝这两个值。v1 取得方式封闭为 controller_transcription、user_supplied_file、plugin_provided，不存在 direct_user_input。查询使用“声明的说话者/来源”措辞。task.transition 也不能独立证明 Drover 已持久化，核验任务状态须由消费者调用 Drover 公开接口；遥测宿主不为认证来源读取业务文件。工具返回内容只是公开工具观测，不因此成为验收结论。

链接类型限定为：`based_on`（依据）、`responds_to`（回应）、`supersedes`（更正或新版本）、`uses_brief`（实际快照）、`uses_decision`（选择）、`carried_from`（复用证据）。一般链接必须在同一 trace；目标须已提交，或是同一原子采集批次中排在前面的新事件，不能形成环或指向未来事件。parent、operation 与 begin/end 一律不能跨 trace。

仅 `evidence.reused` 的 carried_from 可跨 trace，且目标只能是既有需求、提议、授权或复用证据。复用须显式请求：保留原正文哈希、原声明说话者和取得方式，新增本次复用的提交者/时间；不能把旧的主控转录改标为直接用户输入。原始证据仍可追溯，不复制成“新用户消息”。它不是自动补采关闭期间的会话。

同 task 新 run 建立新 trace；kind/scope/key 仅用于候选查询，不能单靠任务号认定这些 run 属于同一已登记任务。Drover 为未编号待办试分配的 T 号在失败后可能复用，故查询单列“未见运行登记声明/登记未核验”的尝试；只有消费者核实 task/run 登记后，才在任务视图汇总已登记轮次。缺 task.transition 不证明未登记，有该声明也不证明真实登记。遥测不自行修复或占用任务号。数据库仅对完整外部绑定设唯一约束，手工链路无需虚构任务或 run。用户在任务执行中途才选择记录时，可绑定当前公开 run，但 coverage_start 是实际开始记录时间，不回填整轮完整历史。

### 3.1 v1 事件约束

作用域：T=trace 必填且 dispatch/operation 为空；D=trace/dispatch 必填且 operation 为空；O=三者必填；G=三者为空，仅全局开关。D/O 的身份一致性由复合约束验证。下表未列出的类型、正文角色或链接拒绝，不能用通用 payload 绕过关联校验。C/P=controller_statement/plugin_statement（均未认证），E=execution_observed，S=system_control（E/S 仅内部路径产生）。

正文 `!` 必需，`?` 可选；E 事件现场捕获失败时，可用同角色的结构化 gap 代替，不能用空正文冒充。成功取得的正文不得省略。C/P 的必需正文缺失则整个提交无效。每个角色至多一个正文，links 的相同 relation/target 不重复；除明示至少一个外允许空链接，并显示依据缺失。

目标简称：U=需求/提议/授权/evidence.reused；B=brief.snapshot；R=route.begin 或 route.end（引用任一端都有效，查询通过 operation 关联另一端，不因另一端晚到而改写决策链接）；Q=agent.reply.end；V=review.recorded；C=controller.decision。supersedes 默认只指同类型；正文与状态未知字段使用 null 并带 gaps/reason，不填伪造值。

| 事件 | 作用域/来源 | 正文角色 | 允许链接及目标 | payload 必需字段（可空须明确） |
|---|---|---|---|---|
| requirement.recorded | T / C,P | text! | supersedes→同类型 | declared_speaker、acquisition、declared_at（可 null） |
| proposal.recorded | T / C,P | text! | based_on→U；supersedes→同类型 | declared_speaker、acquisition |
| authorization.recorded | T / C,P | text! | responds_to→U；supersedes→同类型 | declared_speaker、acquisition、context_complete；为 true 时至少一个 responds_to |
| evidence.reused | T / C,P | text!（内部复用目标，不接受替换正文） | carried_from→U（恰一个，唯一可跨 trace） | 原来源字段由目标复制；reused_by 为本次声明提交者 |
| controller.summary | D / C,P | text! | based_on→U,B；supersedes→同类型 | purpose=route/dispatch/review |
| brief.snapshot | O / E | brief! | based_on→U,V；supersedes→B | absolute_path、captured_at、publication_phase=begin/end、begin_missing |
| route.begin | O / E | summary!、request! | based_on→U,controller.summary；uses_brief→B | router_model、router_version、rules_version（版本未知可 null）；gaps |
| route.end | O / E | response?、suggestion? | 正常无；begin 缺失时按下述恢复规则 | outcome、begin_missing；成功时两种正文必需，失败保留已取得者；gaps |
| controller.decision | D / C,P | reason! | based_on→U,R；supersedes→同类型 | planned_model、planned_effort、validation_budget（未知可 null） |
| agent.start.begin | O / E | prompt? | based_on→U；uses_brief→B；uses_decision→C | cwd、agent_program、explicit_parameters、labels（无法识别可 null）；gaps |
| agent.send.begin | O / E | message! | based_on→U,V；uses_brief→B；uses_decision→C | target_name、send_kind=initial/followup/rework；gaps |
| agent.reply.begin | O / E | 无 | 无 | target_name；gaps |
| agent.start.end / agent.send.end | O / E | 无 | 正常无；begin 缺失时按下述恢复规则 | outcome、公开结果字段（可 null）、begin_missing；gaps |
| agent.reply.end | O / E | reply? | 无 | outcome、begin_missing、name/instance/at（可 null）、association=not_proven；成功时 reply 或 gap 必需 |
| review.recorded | D / C,P | text! | based_on→U,B,Q,V；supersedes→同类型 | reviewer（声明）；verdict 可选 passed/changes_requested/inconclusive |
| controller.note | T 或 D / C,P | text! | based_on→U,B,R,Q,V,C；supersedes→同类型 | note_kind=review/rework/decision/closure/other |
| task.transition | T / C,P | reason?（业务变更原因，最多一个） | 无 | binding（须与 trace 声明一致）、from/to（业务状态不透明字符串）、business_committed_at（可 null） |
| recording.changed | T 或 G / S | 无 | 无 | enabled、generation、actor（声明）、changed_at；仅 trace close 可写 closed:true |

operation 的 kind 固定为 route/agent.start/agent.send/agent.reply；事件阶段必须与之相符，begin/end 的 kind 不能混用。brief.snapshot 属于同一次 route/start/send operation。关联的 uses_brief 必须指本 operation 的快照；previous_brief_event_id 只用来生成新快照的 supersedes，不代替现场快照。正常 begin 的 basis 与 decision 固定；后来的更正事件不修改它。send_kind=initial 表示本 dispatch 的首次交付（包括 controller_handoff 或把新委派交给已有 agent），followup 表示跟进，rework 表示返工；由调用方显式填写，不从内容或 agent 状态推测。

快照读取失败时不生成没有正文的 brief.snapshot；route/start/send 的 begin 额外允许 brief 作为 gap 角色，uses_brief 留空。未提供任务书时可同样标 brief/not_supplied；不存在假快照引用。

仅在 begin_missing=true 时，route/start/send 的 end 可沿用对应 begin 所允许的 based_on/uses_decision/uses_brief 链接类型与目标。依据与决策必须来自调用开始前已固定的上下文，快照必须是调用前实际取得的原字节；不能在 end 时加入新授权。只有 end 的记录仍明确显示 begin 缺失，不伪造前置记录已提交。

payload 中列出的结构和已命名可选字段必须按版本验证，未知字段拒绝，不能让实现者各自接受不同类型。gaps 为 `{role,reason}` 数组，reason 首期限定 not_supplied/unreadable/too_large/unrecognized/not_available/write_failed；同一角色成功正文和 gap 不可并存。执行入口回执可以报告整个存储 unavailable，不要求把失败本身写入失败的数据库。

actual model/effort 与声明标签分开。业务 argv 按数组原样执行，但 v1 不整体落盘任意 argv/env：只提取明确的模型/强度参数、cwd、agent 程序、role/model/effort 标签及实际 prompt/send 内容，不保存任意认证参数或配置。只识别公开参数边界和受支持的明确形式；不认识就 null＋unrecognized，不从标签推测实际模型。这保留旧记录器的字段范围，也避免为任务书定位解析 argv。

## 4. 正文与操作如何一起保存

路由、start/send/reply 入口生成 operation_id 和固定 begin/end event_id。generation 是内部取得的捕获凭据，调用方不能指定。操作一旦开始，不能以新的 generation 补交旧结果。

1. 解析本次显式上下文，验证已知关联；没有上下文则直通操作，不读取遥测任务书。
2. 获取有效开关版本。关闭或存储不可用时跳过采集，执行原操作。若已确认 ID 不存在、跨 trace 或字段无效，则在执行前返回参数错误。
3. 对需要的正文制作快照并暂存。所有 --brief-file 与正文文件输入只接受绝对路径，不为定位任务书解析 Corral 的 --cwd。缺失任务书记明确 gap，不猜路径、不截断成“完整正文”。
4. 在同一事务中复核版本、发布正文、写入 operation、brief.snapshot、begin、正文引用与 links。begin 使用本次新快照，不能只有一份历史文件引用。同一文件重复内容可复用 blob，但各次快照事件保留。
5. 实际调用一次，不因记录失败重放。返回后复核原版本，保存 end。begin 写入失败而 end 可保存时，在 end 事务建立缺失的 operation，标明 begin 缺失；不能补造 begin。若原版本仍有效，允许把调用前已暂存的原任务书字节随 end 原子发布，brief.snapshot 保留原 captured_at 并标 publication_phase=end、begin_missing=true；不得在调用后重读文件冒充原快照。暂存已丢失则记录 gap。

当任务书捕获失败但 begin 元数据可写时，begin 带 `gaps=[{role:"brief",reason:"unreadable"}]`，不带假哈希；业务动作继续。任务书、prompt、路由请求或响应不会因资源限制被静默截断。若正文失败导致整笔写入失败，向调用方明确报告，不能声称已保留完整链路。

结束结果区分：spawn_failed、exited（exit_code）、signaled（signal）、timed_out、unknown。Corral 的 confirmed/pending/merged_with_draft/name/instance/at 原样保存。超时或无 end 不能推导为未执行；name 相同也不能替代 instance。

正文在快照后被修改仍是可能情况。v1 保证保留调用前观察到的版本，不保证 agent 打开文件时还是同一版本；实现这种更强保证需要改变文件交付机制，超出本轮记录接口。

## 5. 命令输入输出与重试

纯记录与查询命令已在阶段 01 实现；agent/dispatch 执行入口按后续阶段实施，不能把本节提案示例当成已全部可用。纯记录命令以 `--input FILE` 读取 UTF-8 JSON；正文通过 JSON 中的绝对文件路径传入。stdin 形式可用 `--input -`，不与业务命令的 stdin 共用。

| 命令 | 行为 |
|---|---|
| `saddle telemetry settings get/set` | 读取或设置全局 enabled；set 只接受布尔值 |
| `saddle telemetry trace create/set-recording` | 建立链路或改变该链路开关 |
| `saddle telemetry trace close` | 不可逆结束链路；stored/duplicate=0，invalid=2，unavailable=1；无库/未知 ID 不初始化 |
| `saddle telemetry dispatch create` | 建立一次派发身份 |
| `saddle telemetry append` | 追加主控/插件材料或显式复用已有证据 |
| `saddle telemetry list/show/events/body` | 查询绑定/对象、分页事件或读取正文 |

纯记录写入统一回执：

```json
{"schema_version":1,"ok":true,"status":"stored","id":"event-u1"}
```

status 为 stored / duplicate / disabled / conflict / invalid / unavailable；后四项 ok=false，error 只含 code 和简短说明。退出码拟为：成功或同内容重复 0，存储不可用 1，参数错误 2，ID 内容冲突 3，采集关闭 4。此约定仅适用于遥测命令，不改变 Corral 退出码。

trace/dispatch/event 的 ID 由调用者在首次提交前保存。同 ID 同规范内容返回 duplicate；同 ID 不同内容返回 conflict。事件的正文和 links 属于内容的一部分；不能在重复提交时加授权依据。schema_version=1 的规范化规则固定：对象键排序、数组顺序保留、数值按 serde_json 的值语义比较、正文比较实际字节哈希；不以重新序列化的 JSON 哈希冒充原始正文哈希。

关闭状态仍允许查询已有 ID。调用方回执丢失时，先查询该 ID；需要重交则重交相同记录。v1 在关闭状态不读提交文件中的正文来判定 duplicate，返回 disabled。不存在“失败后再运行一次 route/start/send”的补录路径。

agent 入口采用显式分隔，防止遥测参数与原 Corral 参数冲突：

```text
saddle agent --record-context /abs/context.json --brief-file /abs/task.md -- start <原 Corral start 参数>
saddle agent --record-context /abs/context.json --brief-file /abs/rework.md -- send <原 Corral send 参数>
saddle agent --record-context /abs/context.json -- reply <原 Corral reply 参数>
```

`--` 后参数逐项传给配置的 Corral 程序，不拼接 shell；没有记录上下文的调用不采集。工具实际 stdout/退出结果不被遥测回执替换。遥测状态用 stderr 的独立单行前缀 `saddle-telemetry: ` 加 JSON 报告，包含 operation_id、begin/end 保存状态及简短 gap code，不重复输出正文。调用尚未执行的参数错误明确标为 executed=false；进程中断可能连回执也没有，不能从没有回执推断未执行。

### 5.1 dispatch 插件的路由与可选遥测（设计收敛，待实现）

具体契约见[dispatch插件接口设计](dispatch插件接口设计.md)；2026-10-02主控限定复核M1/M2通过，D1停用行为由用户确认。该结论只批准设计进入串行实现，不表示现场采集已可用；阶段01/02既有接口不变。

可选插件拥有JEV请求、解析和路由建议；主控决定实际委派。`saddle plugin status|run`提供无需TUI的通用入口，二进制组装根登记dispatch，通用下层接口crate不依赖宿主或具体插件。宿主库不导入dispatch业务，遥测模块不反向调用插件。原宿主必备`saddle dispatch route`方案仍撤回；不修改Corral。

记录上下文显式传入，无上下文不初始化遥测。插件在外部调用前经受控Recorder提交一次begin材料，宿主持有固定generation的Capture，保存任务书快照/begin及返回后的end，沿用既有begin缺失恢复和开关撤销语义。保存实际请求、完整解析响应与独立整理建议，不把HTTP错误片段当完整response；shape失败保留已经取得的完整解析响应，缺正文有gap。回执通过本次call_id的完整首行起始和末行终止边界匹配，缺失/截断保持未知，采集失败不重放业务。

受控现场采集限同版本经审查的官方core plugin执行路径；普通append仍只能提交未认证的controller/plugin声明，不能借插件ID伪造execution_observed。新的route执行接口实现前仍无产品现场路由采集可用，现有route事件表不代表接入完成。

停用插件保留skill及项目规则，只拒绝后续插件路由调用；主控说明不可用后自行判断档位，继续项目规则或用户当次已要求的分派，不自行启用、不回退旧脚本、不额外暂停询问。没有分派要求的项目不因此自动委派。遥测关闭不阻止路由，dispatch停用不影响独立存储/查询或saddle agent。

skill随插件安装更新，AGENTS模板只给说明，由用户决定项目采用。真实安装及消费者切换仍在阶段05，旧dlog/route.py此前维持使用，不双写、不原地改Corral仓库资源；Corral最后迁移。

### 5.2 agent 入口的退出、取消与等待预算

纯遥测命令的 1/2/3/4 不用于 `saddle agent` 自身失败。Corral 正常退出时原码透传（其现有 0–9 不重定义）；Saddle 在调用前拒绝使用 125，无法启动 Corral 使用 127，子进程受信号结束使用 128+signal。只有可确定未启动 Corral 时才报 executed=false。无论本次是否选择记录，入口自己的拒绝或启动失败均必须输出该状态回执；配置的外部程序自身也可能返回 125/127，因此不能仅凭退出码判定未执行，须同时取得 Saddle 回执的 executed=false。子进程 stdout/stderr 中的同名文字不当作宿主回执：不能仅用“最后一条 final=true”识别宿主，因为背压可能令宿主终止回执完全缺失而业务输出仍完整。Saddle 必须提供与本次调用绑定的宿主起始边界及匹配的终止回执（调用标识由 Saddle 生成，不传给 Corral），起始边界位于任何业务 stderr 字节之前，终止回执必须带 final=true 和同一调用标识；任何过程回执不得带 final=true。起始边界未能完整输出时，不能让子进程文本占据或被误认成该宿主边界。消费者仅在进程退出、输出收齐且首个宿主边界与最终回执完整匹配时采信执行状态；边界或终止回执缺失/不完整/不匹配一律保持未知，即使正常退出且读到 EOF。业务原字节和已知正常退出码仍保留，不能通过无限等 stderr 或篡改业务退出码保证回执到达。这里不是针对恶意子进程的来源认证。Corral 已启动后状态不明，不得套用 125/127 宣称未执行。Drover 接入时必须区分入口拒绝和业务结果，125/127 不得触发 start 状态登记；超时、信号或未知不自动重发。退出码正常但遥测保存失败时，仍保留业务退出码。

受支持的调用方（包括 Drover）必须为本次 Saddle agent 命令创建独立进程组：在 exec 前设置组，记住该次 PGID；该组包含 wrapper 和它启动的 Corral CLI 客户端，不包含调用者或其他用户进程。取消/超时先对这一个组发 TERM，至多 250 ms 后 KILL 并回收直接子进程，不能只 child.kill wrapper，也不能按名字批量杀进程。wrapper 单独收到 INT/TERM 时向已启动的 Corral 客户端转发并回收；SIGKILL 无法转发，调用者任意只杀 wrapper 时不承诺后代必停。

Corral 已按自身机制分离的 agent/pen 不属于这个短命客户端组，取消请求不自动 stop agent，也不能撤销已经发生或排队的投递。这样的结果仍是未知，不承诺“取消即从未执行”。进程组隔离与取消只改变 Saddle 调用层，不修改 Corral 核心。

首期锁竞争等待预算（实施初值，可据合成验证调节，不改变超时跳过采集语义）：单次遥测写入最多等锁 100 ms；Drover 发消息前的 trace/dispatch 创建与 begin 等锁总预算 300 ms，超过后跳过采集、继续业务。任务锁期间不重试一整套遥测初始化。此预算不包含任意磁盘阻塞/fsync 的硬实时保证；整个子进程仍受调用方总超时管理（当前 Drover 为 60 秒），取消必须结束上述客户端组。end 遥测等待不延长业务的总超时；来不及保存就报告 gap。正文资源上限在实现时用合成大文件确定，超限明确 gap，不静默截断。

## 6. 开关与并发的确定行为

数据库 v2 在 traces 末尾追加 closed_at，历史值为 NULL；新库直接 v2，reader 接受 v1/v2 只读（v1 投影 NULL），writer 在同一 IMMEDIATE 事务复核版本、加列/三触发器并设 user_version=2，沿用100 ms等锁预算。失败整体回滚，不重写旧行/正文/链接。旧二进制拒绝 v2，无降级迁移；部署需成套宿主/Drover/技能并先取得一致性备份。

`trace close` 先只读确认有库（无库 invalid/unknown trace_id，不建目录），再于写事务读取 trace：未知 invalid，已结束 duplicate。未结束则先写 recording.changed（enabled=false、generation+1、closed=true），再将 capture_enabled=false、generation+1、closed_at=同一 changed_at，一起提交；总开关关、trace 已暂停也能结束。三个触发器分别拒绝已结束 trace 的开关/generation/closed_at 更新、event 插入及 dispatch 插入；operation 与事件同事务，随拒绝回滚。

只读 policy 返回开关、代数、closed_at，不因结束报错；写入门只对存在且已结束的 trace 优先返回 disabled/trace_closed，其后才判总开关、未知trace/暂停，保留原有校验位置。create 同ID、dispatch、append、采集和 set-recording(true) 不得续写，set-recording(false) 幂等 duplicate。合法旧上下文的业务照常执行一次，begin/end=disabled；非法上下文照旧拒绝，不能借结束绕过关联检查。close 立即撤销所有在途 Capture，begin/end 均不得补写，已存部分保留、缺 end 仍未知，不设宽限或推断原因。

总开关和每条链路开关的实际状态改变才递增各自 generation；重复设置同一值是幂等成功，不撤销在途捕获。设置状态与最小 recording.changed 控制事件同一事务提交，返回成功后才更新界面。recording_policy 只存当前值，历史由不可变 recording.changed 保存：全局事件 trace_id=null，链路事件绑定对应 trace，查询据此重建区间。

关闭与正文最终发布共享写锁：关闭先提交，旧版本不得发布；发布事务先完成，关闭等待该事务后才成功。临时读取和暂存不在锁内，可能留下关闭前开始捕获的字节，不承诺安全擦除。

全局关闭后，trace/dispatch 创建、append、路由/agent 内容采集都停用；查询和开关控制可用。业务仍可执行，不能因此自动开 trace。重新开启允许之后新开始且有显式上下文的操作；之前被关闭撤销的 end 不会复活。采集到的 begin 没有 end 时，查询同时给出相关关闭区间，但不能断言缺失一定由关闭造成。

## 7. Drover 的交付顺序

1. Drover 按新任务默认选择或本次明确选择，生成本次 run_id；记录被选择且总开关有效时，创建 trace 与 controller_handoff dispatch。
2. 将记录上下文作为独立、明确标识的附段加入 Drover 原本发给主控的任务交付消息。该附段仅含 trace_id、dispatch_id、声明的 task/run，不改任务书正文，也不包含新的任务授权。它由任务交付方 Drover 构造，不由遥测包装器偷偷改 prompt。
3. 以 send_kind=initial 调用 Saddle agent 入口执行这一次 send，保存实际发送的整个片段。没有 MAIN_AGENT 的现有手工路径，把相同上下文放进返回的 manual_text。遥测创建失败则按原路径交付，明确本次没有有效记录上下文。
4. 按现有交付结果规则持久化 Drover 任务状态，再提交 task.transition。不把 trace 创建成功等同于 Drover 写入成功；保留现有 unconfirmed/unknown 状态，绝不自动重发。
5. 主控拿到上下文后，为实现、审查各建 dispatch；每次 route/start/send/reply 显式传对应上下文。压缩会话后可用公开查询恢复，不能按“最新 trace”猜。上下文不构成自动执行授权。
6. Submit/Accept/Return 业务落盘后按完整 run binding 解析 trace、尝试追加 transition（Return 附原始 reason）。仅 Accept/Return 之后用这个已解析 trace 调用 close，独立300 ms预算；即使 transition 失败或耗尽预算也尝试。无 trace/查询失败则不 close、不新建。流转结果增加 `telemetry.close:{status}`（stored/duplicate、实际失败或 not_attempted），外层 status 保留 transition 结果；不回滚/重试业务。失败可能永久缺少遥测流转和原因，Drover 原始退回原因保留。主控不代关 Tasks trace；同run返工仍同trace，Return 后新run按既有项目默认/本次覆盖。

实际由 Saddle 观察到的 Drover 交付片段，可作为“交付方尝试发送给主控的内容”基线；是否送达仍看 confirmed/pending，不能因此证明内容作者是用户，也不能在 pending 时称主控已收到。

任务交付可能先于任务状态落盘。主控收到的 task/run 是本次交付声明，状态仍从 Drover 公开接口确认；遥测不能承诺两个存储原子提交。Drover 操作结果保留原业务 record 字段，另加 telemetry 状态，避免把“任务记录失败”和“遥测失败”混为一谈。

## 8. 查询、覆盖程度与验证计划

list/show(trace) 增加 closed_at；已结束 trace 的 recording_history/intervals 按结束事件 seq 截止，终止区间无条件以 changed_at 封口，不追加无限off尾段。时间原样保留，即使回拨也不改成按时间截断；未结束算法与原始 events 查询不变。UI 依据 closed_at 显示英文 ended 状态和 Trace ended 事件，不从最后区间、closure 声明或结束状态推断任务成功。

list 支持完整外部绑定或 kind/scope/key 查询多轮；show 以 ID 读取记录，不自动合并不同 trace。events 按 seq 分页，首请求返回 upper_seq，后续查询携带同一上限；后来的补录不混进同一次导出。每页单独读事务，不持有跨页长事务。body 按哈希验证并输出完整原字节；缺失、损坏与空文件有不同结果。引用内容未修改，才可复用备份中的哈希正文。

trace 展示 coverage_start、开关区间、已知 gaps、缺 begin/end，以及 evidence 来源。reply 操作的缺 end 单独标为“回复查询未完成/结果未知”，不计入投递或交付结果未知，也不把多次 reply 算成多次交付。手工追加始终以新 recorded_at 保存；它不是被撤销 operation 的 end。调用方声明的时间若早于当前记录时段或落在关闭区间，显示“事后提交/声明时间在未采集区间”，不修改历史操作或推断该材料当时已被捕获。用户已确认“不自动补录”，并选择允许显式手工补交旧材料；必须标明事后提交及声明时间，不冒充当时已采集，也不补成被撤销 operation 的 end。不能输出未经证明的“完整率 100%”：绕过 Saddle 的 Corral 操作、主控漏提交的授权、存储彻底失败都可能不可见。允许判断“这些已记录操作具有完整材料”，不等于“本任务所有操作均已记录”。

后续实现按项目 TDD 约定验证以下具体性质；本轮仅进行设计检查，没有执行这些测试：

- 同 ID 重交 trace/dispatch/event 不重复；变更任一 link 或正文报冲突。
- 跨 trace 操作关联拒绝；显式证据复用保留转录来源；后补授权不改变旧 begin。
- 任务书快照与 begin 要么一起保存，要么一起失败；缺正文有明确 gap，不把残缺文本标完整。
- 关闭、重复关闭、关闭后重开与在途结果交错，旧版本不会发布；关闭失败不显示为成功。
- 假 Corral 的副作用计数始终为一次，即使 begin/end 保存失败、锁超时或回复丢失。
- Drover 交付成功但业务状态写入失败时，遥测不伪造 running；插件禁用后手工 trace 仍可查询与记录。
- 跨页期间追加事件不会改变已固定上限的导出；损坏正文返回错误，不显示为空。
