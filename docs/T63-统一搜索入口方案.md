# T63：统一搜索入口方案

2026-10-04。**待用户确认，只设计，未实施。** 源码基线 `b6f93d9`。以下是推荐及取舍，不新增用户验收点，也不修改已批准的 DESIGN。

用户原话：在已有 Agent 搜索和插件面板的基础上，统一可搜索的操作入口，用于找项目、切换 agent、打开任务和进入具体设置页，减少记忆入口位置的负担。

## 推荐：扩展现有 Search，只做查找与导航

保留 Agents 底栏的 `/ Search`，把现有 Agent 搜索扩展为统一搜索弹层。Agents 焦点按 `/` 或点击入口打开；终端中的 `/` 继续透传，不新增全局快捷键。Plugins 面板、Settings 按钮及 T74 用户固定入口保留，用户无需重新配置。

输入普通文字，按名称/标题做不区分大小写的子串匹配，不加前缀语法。结果标明种类、来源和去向；↑↓ 选择，Enter 或 `Open` 打开，单击行只选择，Esc/Close 返回打开前的焦点。沿用插件面板的输入框、选中态和完整鼠标手势处理；搜索输入不流入终端。

空输入先列 Agent、插件入口和六个 Settings 页；输入文字后再查询项目/任务，避免一打开就铺满历史任务。按 Agent、Project、Task、Plugin、Settings 分组，组内顺序稳定。只导航，不从搜索结果派发任务、修改设置或启停插件。

## “找项目”和“打开任务”具体指什么

**找项目推荐指已知项目，不扫描磁盘。** 输入项目名可以找到两种结果：Corral 公开 cwd 对应的 Agent，以及 Drover 已登记项目的 `Project · … · Tasks` 入口。Agent 行沿用 cwd 末级目录名匹配；登记项目由插件按名称/路径匹配并展示路径，同名项目可区分。两者不按名称强行合并成仓库，不新增项目首页或宿主项目登记库。

**打开任务推荐包含定位某一条任务。** 输入任务编号或标题，Drover 在已登记项目的 Current、Awaiting、Pending、History 中查找摘要；每行显示项目、编号/标题和状态。选择后打开该项目的 Tasks，选中该任务，旁边显示原有任务内容。另保留 `Plugin · Tasks`，供只想打开任务面板时使用。跨登记项目查任务是本方案对原话的推荐解释，尚未获准。

| 输入示例 | 会看到什么 | 选中后去哪里 |
| --- | --- | --- |
| `owlet` | `Agent · owlet/main`；`Project · owlet · Tasks`，带登记路径 | 前者切到 Agent；后者进入该项目任务列表，无 Agent 也可用 |
| `saddle/dev` | 名称匹配的 Agent，已打开者标 `Open` | 已有窗格直接聚焦；否则沿用现有接入 |
| `T63` 或标题片段 | `Task · saddle · T63 · 统一搜索入口` 等匹配项 | 打开 Tasks 并定位该条；同编号跨项目分别列出 |
| `Tasks` | Drover 的插件入口，以及文字恰好匹配的其他结果 | 插件入口按打开搜索时的来源 cwd，沿用 T74 普通打开规则 |
| `Colors` / `Diagnostics` / `Plugins` | 明确标为 `Settings › …` 的页；插件打开项另标 `Plugin` | 直接进入对应设置页，不要求用户再记 F1–F6 |

设置首版只索引 General、Colors、Advanced、Diagnostics、Plugins、Updates 六个现有页名；不搜索每个字段或插件内部的设置页面。进入 Diagnostics/Updates 沿用现有读取/检查行为，不触发保存或升级。

## 源码核对：可复用与最小缺口

| 部分 | 已有能力 | 本方案所需变化 |
| --- | --- | --- |
| 搜索及 Agent | [search.rs](../src/search.rs) `Search::matches/key/draw`，仅搜索 Agent 全名/cwd 末级目录；[app.rs](../src/app.rs) `search_outcome` → `attach` | 扩展结果种类，复用输入和接入路径 |
| 插件入口 | [palette.rs](../src/plugins/palette.rs) `Item::action/explanation`、`Palette::event`；[app_plugins.rs](../src/app_plugins.rs) `plugin_palette_outcome` | 在 Search 复用插件状态与打开/切换路由；保留原 Plugins 面板 |
| 设置页 | [settings.rs](../src/settings.rs) `Page/PAGES`、私有 `show`；[app.rs](../src/app.rs) `open_settings/settings_outcome` | 小的页级导航入口，复用 Plugins/Diagnostics/Updates 各自处理；不能直接把所有 Page 都交给只适用于字段页的 `show` |
| 项目与任务数据 | [Drover README](../plugins/drover/README.md) 的公开 `projects/list/show`；[core.rs](../plugins/drover/src/core.rs) `list` | 查询/匹配放在插件内；宿主不解释任务 JSON，不读项目登记、`.drover.conf`、queue/state 文件。公开 list 的每页 20 条不能冒充搜索全集 |
| 精确跳转 | [plugin.rs](../plugins/drover/src/plugin.rs) `open_target`、Attention/NotificationOpen；[queue.rs](../plugins/drover/src/queue.rs) `locate` | 内部目标和定位可复用，但外部任意搜索结果目前没有打开接口；不能伪造 Attention 条目来借道 |

**必要的插件缺口是一项可选的“导航搜索”能力：查询候选 + 打开候选。** 查询传文字，插件返回有上限的种类、标题、来源说明及不透明目标；宿主只展示。激活时插件重新核对目标并复用 `open_target`，宿主打开/聚焦原视图，不再发送来源 cwd 覆盖明确目标。查询换词、关闭或插件会话变化后，旧结果不能触发跳转。未编号任务沿用插件的文本身份；同文重复无法唯一定位时进入项目列表并提示选择，不猜行号。

这项能力是新增的小契约，**不是现有协议已经支持**。复用现有插件消息、会话及视图生命周期，只增加上述两步；不扩成任意命令注册平台，不改变现有 `command.v1` 的无焦点副作用契约。查询在插件内异步完成，加载中或部分项目不可读须明确显示。旧插件继续显示普通打开入口，不要求全部插件升级。精确消息字段留到用户确认范围后确定。

若不增加该能力，最小版本只能搜索 Agent、插件名和设置页，再进 Tasks 手工选择项目/任务；这能减少入口记忆，但不能声称已支持无 Agent 项目和具体任务的内容搜索。

## 常用路径与 T74 保留项

- **项目无 Agent：** Drover 已登记的项目仍可搜索并打开 Tasks，空项目显示原空列表。不自动创建 Agent、接入项目或开终端；未登记且没有公开 Agent 的目录不在本次搜索范围。
- **插件未安装/停用：** 未安装时没有它的项目/任务结果；停用/失败时保留插件入口和原状态说明，引导到 Plugins 管理。搜索可说明仅包含当前可用来源，不能把来源不可用显示成“没有任务”；不自动安装、启用或重启。
- **正在编辑：** Settings、新建表单或确认框在前台时沿用模态阻挡，不叠开 Search。插件内仍有草稿或操作在跑时，由插件沿用 `open_target` 的保留现场提示，用户完成/取消后重新选择；不丢草稿、不排队等它结束后静默跳转。
- **T74 不变：** 仍由用户固定一个插件动作，无默认固定；`p`、头部位置与窄栏隐藏、固定与启用分离、不可用转 Plugins 说明均保留。普通 `Plugin · Tasks` 使用打开 Search 前的来源快照，沿用 T74 的匹配/无匹配/无法判断及输入使定位失效规则；明确项目/任务结果则按用户所选目标打开。

## 请用户决定的两件事

1. **项目范围：** 是否接受“Corral 已知 Agent 的项目名 + Drover 已登记项目”？推荐接受；任意本地仓库发现或新项目工作区不纳入本次。
2. **任务深度：** 是否需要按编号/标题跨已登记项目直接找某条任务？推荐需要，并接受上面的最小插件能力；若“打开任务”仅指打开 Tasks 面板，可省去单条任务查询，但无 Agent 的登记项目搜索仍需要插件候选与项目跳转接口。
