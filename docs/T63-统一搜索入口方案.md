# T63：统一搜索入口方案

2026-10-04。**用户已批准轻量范围，按实施任务书落地。** 本文替代原设计中的扩展推荐；原 Drover 候选查询、登记项目枚举及精确任务跳转接口未批准，不纳入本轮。

用户原话：在已有 Agent 搜索和插件面板的基础上，统一可搜索的操作入口，用于找项目、切换 agent、打开任务和进入具体设置页，减少记忆入口位置的负担。

用户确认首版整合已有入口，任务侧主要关注插件可用性，不做跨项目单条任务搜索。

## 已确认的入口与范围

扩展 Agents 底栏已有 `/ Search`。Agents 焦点按 `/` 或点击 Search 打开；终端中的 `/` 继续透传，不新增全局快捷键。沿用普通文本、不区分大小写的子串匹配、↑↓ 选择、Enter/单击结果导航、Esc/Cancel 退出及完整鼠标手势消费。点击 Search 保留原输入来源，取消恢复原焦点。

| 输入 | 结果与去向 |
| --- | --- |
| `owlet` | 按现有公开 cwd 的末级项目目录名匹配相关 Agent；选中后切换/接入原终端 |
| `saddle/dev` | 匹配 Agent 全名；已有窗格直接聚焦，不重复接入 |
| `Tasks` 或插件 ID | 宿主可见的普通插件入口；可用时打开/切换原视图，不要求 Pin |
| `Colors`、`Diagnostics`、`Plugins` 等 | `Settings › …` 六个现有页面之一，直接进入该页 |

空输入列出 Agent、插件和设置页，行内标明类别与去向。**项目搜索只查当前 Agent 的 cwd 项目名，不涵盖所有本地仓库或无 Agent 的 Drover 登记项目；打开任务指打开 Tasks 面板，不能搜索任务编号、标题或正文。**

## 插件可用性与现场保留

- 未安装没有对应插件项；已登记但停用/失败/无响应保留真实状态及原因，激活进入该插件管理页，不隐式启动、重启或启用。正常运行且有视图时复用普通打开/切换路径；内置或无视图插件只进入管理。
- 搜索随现有插件状态刷新；保留所选插件身份，状态变动后不能用旧结果打开，激活时再次核对。插件失效不影响 Agent 和设置页结果。
- Settings、创建、确认及插件覆盖层仍按既有模态规则处理输入；Search 不替换正在编辑的弹层。恢复插件原视图时沿用该插件自己的草稿和来源定位保护。
- 六个设置页为 General、Colors、Advanced、Diagnostics、Plugins、Updates。复用各页原处理；Diagnostics/Updates 只触发原读取检查，Plugins 走管理页，不将三者送入普通字段页索引。不保存设置、不触发升级。
- Plugins 面板、Settings 按钮和 T74 固定入口保持。Tasks 搜索项不要求固定；普通打开沿用来源焦点的 cwd 规则及插件已有定位保护，不引入明确任务目标。
