# 核心遥测：存储、执行采集与查询

第一阶段提供独立于 TUI、插件和 Corral 的 `saddle telemetry` 命令与 Rust 存储接口。阶段 02A 新增独立 `saddle agent` 执行入口，组合 Corral 公开 CLI 与可选现场采集；阶段 02B 在 Settings → General 提供同一全局开关的界面入口。阶段 03A 新增通用 core plugin 接口和无界面 `saddle plugin status/run`；03B 新增通用技能资源安装器与管理页内置行。03C 在二进制组装根登记默认停用的可选 dispatch 插件，提供 JEV 路由实现和 corral-dispatch 技能资源。源码接入已完成；只用合成输入、隔离 HOME 与本地假服务验证，没有真实 JEV 请求、实际安装或消费者切换。04B 在源码中接入 Drover 可选记录与跳转（见下文“Drover 可选记录”），05A 已在源码移除旧 Drover Dispatch 日志页及 dlog 执行依赖，并更新随插件交付的技能；尚未实际安装或切换全局资源，旧 dispatch-log 数据不导入、不删除，仅保留供离线历史查看。事件规则见 [接口契约 v1](任务遥测接口契约.md)。

产品默认值沿用 [DESIGN 中 2026-10-01 的用户确认](DESIGN.md)：原话由主控逐字提交，注明来源及未经独立核验；首次安装全局遥测默认关闭；允许事后手工补交旧材料，但保留入库时间和晚交标记，不改写历史操作、不自动补录。

## 目录、开关与版本

数据目录为绝对 `$XDG_STATE_HOME/saddle/telemetry/`，否则为 `$HOME/.local/state/saddle/telemetry/`。目录初建权限 0700，数据库、暂存及正文文件 0600。仅使用本机磁盘。

- `telemetry.sqlite3`：八张表；数据库 `user_version=1`，独立于输入 JSON 的 `schema_version=1`。
- `blobs/sha256/<64 位小写哈希>`：完整原字节；`tmp/`：同文件系统暂存。
- 首次全局关闭。无库的 `settings get`、`list/show/events` 返回 `initialized:false`，不创建目录或数据库。关闭时创建和 append 返回 `disabled`，不读取正文文件。查询和开关仍可用。
- `settings set` 可初始化数据库；trace 初建 `capture_enabled=true`、generation 0。实际开关变化才递增相应 generation，同时追加 `recording.changed`。同值设置返回 `duplicate`。
- 本版本锁定 rusqlite 0.40.2（bundled），Cargo.lock 锁定 libsqlite3-sys 0.38.2，链接 SQLite **3.53.2**。`settings get` 的 `sqlite_version` 来自二进制实际链接库；写入口另要求版本至少 3.51.3。该版本包含 [SQLite WAL-reset 修复](https://www.sqlite.org/wal.html#walresetbug)，不以系统 `sqlite3` 的版本代替核验。

SQLite 使用 WAL、连接级 foreign_keys=ON、synchronous=FULL、100 ms busy timeout 和短 `BEGIN IMMEDIATE` 写事务。查询每次持有独立短读事务。关闭与正文发布共用同一数据库写锁；正文读取、哈希及暂存 fsync 在锁外，最终不覆盖发布和目录 fsync 在锁内。锁超时返回 unavailable；没有后台重试或业务操作重放。

每个正文上限 **16 MiB**，使用流式读取和哈希；超限不截断。纯记录提交失败；内部现场采集转为 `too_large` gap。空文件是合法原字节，与缺失/损坏不同。数据库回滚允许留下已完整发布但未引用的正文，不会确认引用未可靠发布正文的事件；没有自动 GC。关闭不删除历史，不承诺安全擦除已暂存字节。

## Settings 中的总开关（阶段 02B）

TUI 的 Settings → General 最后一项 `Telemetry recording` 就是上面的全局 `recording_policy`，与 `settings get/set` 和 `saddle agent` 使用同一数据目录（TUI 进程的 `XDG_STATE_HOME`/`HOME`）。不在 `config.toml` 或插件中另存 enabled。

- 打开 Settings 只读：无库显示 Disabled，不创建目录或数据库；无法读取（目录不可用、版本不支持、锁等待失败等）显示 Unknown 并在说明行给出原因，不当作关闭。下方两行说明：开启只允许已显式选择记录的链路，关闭不影响任务/agent 执行、不删除历史。
- 键鼠与其他布尔项相同（Space/Enter/←→ 或点击切换，Ctrl-D 恢复默认 Disabled）。切换只是草稿；Esc/Cancel 不写库；没有改动时 Save 不调用存储。Save 以 Settings 读到的 generation 做比较后设置（`Store::set_recording_if`）：期间被外部 CLI 等改过、或读到时状态未知，则出现与配置文件冲突相同的 Keep/Discard/Back 提示，什么都不写。成功后显示实际保存的状态。
- 配置文件与遥测库是两次独立提交，不宣称原子。先完成配置校验与文件冲突检查，再写开关，最后写文件：开关写入失败时配置仍照常保存并即时生效，Settings 保持打开并保留开关草稿和错误；开关已提交而文件写入失败时，提示两部分各自结果，开关不回滚，再次 Save 只重试文件。
- 从插件页回到暂存的 Settings 时，未改动的开关会重读实际状态；已改动的保留其编辑依据，由 Save 检查外部变化。

## 命令及输入

写命令以 `--input FILE` 读取 UTF-8 JSON，`--input -` 读取 stdin。未知字段、未知版本或错误类型拒绝。所有正文 `path` 必须是绝对普通文件路径，不接受目录、FIFO 或符号链接，不根据 cwd 猜测路径。

```text
saddle telemetry settings get
saddle telemetry settings set --input FILE|-
saddle telemetry trace create --input FILE|-
saddle telemetry trace set-recording --input FILE|-
saddle telemetry dispatch create --input FILE|-
saddle telemetry append --input FILE|-
saddle telemetry list [--kind KIND --scope SCOPE --key KEY [--run RUN]]
saddle telemetry show --id ID
saddle telemetry events [--trace-id ID] [--dispatch-id ID] [--after-seq N] [--upper-seq N] [--limit N]
saddle telemetry body --sha256 HASH
```

示例均为合成 JSON，ID 示例仅便于阅读。调用者首次提交前生成并保存 UUID v4 字符串；ID 按不透明字符串处理。重试沿用同一 ID，不重新执行业务动作。`show` 可查 trace、dispatch、operation 或 event；若调用者让不同对象类型共用 ID，则返回歧义错误，应使用不同 ID。

全局开关（enabled 仅接受 JSON 布尔值；actor 是声明）：

```json
{"schema_version":1,"enabled":true,"actor":"synthetic controller"}
```

无任务链路：

```json
{"schema_version":1,"trace_id":"synthetic-trace","origin":"ad_hoc","label":"synthetic example"}
```

task 链路须有完整 `binding:{kind,scope,key,run}`，四项均为非空字符串。完整绑定唯一；相同 kind/scope/key 的不同 run 保持独立，既有绑定不可修改。它们只是调用方声明，不证明 Drover 中存在任务或已登记运行。

链路开关：

```json
{"schema_version":1,"trace_id":"synthetic-trace","enabled":false,"actor":"synthetic controller"}
```

派发身份（可选 parent_dispatch_id 必须已存在且属于同一 trace）：

```json
{"schema_version":1,"dispatch_id":"synthetic-dispatch","trace_id":"synthetic-trace","kind":"implementation"}
```

kind 为 implementation / review / redispatch / controller_handoff。

需求原文提交：

```json
{
  "schema_version":1,
  "event_id":"synthetic-requirement",
  "trace_id":"synthetic-trace",
  "kind":"requirement.recorded",
  "observed_at":null,
  "producer":"synthetic controller",
  "evidence_kind":"controller_statement",
  "payload":{
    "declared_speaker":"user (declared)",
    "acquisition":"controller_transcription",
    "declared_at":null
  },
  "links":[],
  "bodies":[{"role":"text","path":"/absolute/synthetic-input.txt"}]
}
```

时间为 RFC3339 UTC 字符串或契约允许的 null。未知时间不填当前时间。`dispatch_id` 按事件作用域提供；纯记录事件不能带 operation_id。producer、controller_statement / plugin_statement 均未认证，存储统一生成 `source_auth:unverified`。`execution_observed` / `system_control` 以及客户端自填 source_auth 均拒绝。取得方式仅 controller_transcription / user_supplied_file / plugin_provided。

payload 必需字段、正文角色与允许链接遵守契约事件表。这里明确 JSON 类型：声明的说话者、reviewer、planned_model、planned_effort、validation_budget 为字符串（decision 三项可 null）；context_complete 为布尔值；task.transition 的 binding 与 trace 相同，from/to 为不透明字符串。acquisition、purpose、verdict、note_kind 使用契约枚举。controller.note 的 note_kind=other 可存第三方执行路由的声明材料，不会变成 route 现场观测。

显式复用已存证据时，payload 只传 reused_by（必须等于本次 producer），bodies 必须为空，links 恰一个 carried_from。存储端复制目标的正文引用、原声明说话者、取得方式及可得的 declared_at，并校验正文完整性；允许跨 trace，禁止替换原正文：

```json
{
  "schema_version":1,"event_id":"synthetic-reuse","trace_id":"another-trace",
  "kind":"evidence.reused","observed_at":null,
  "producer":"synthetic plugin","evidence_kind":"plugin_statement",
  "payload":{"reused_by":"synthetic plugin"},
  "links":[{"relation":"carried_from","target_event_id":"synthetic-requirement"}],
  "bodies":[]
}
```

所有关联目标须是已存事件，或内部原子批次中此前的新事件。除此复用外不得跨 trace。数组顺序参与内容比较，对象键排序；数值按 serde_json Value 语义比较。正文按实际字节 SHA-256 比较，输入文件路径不参与去重。seq、recorded_at、fingerprint 由存储生成。正文、链接和事件不可更改；同 ID 加新依据是 conflict，应另建纠正事件。

## 回执与查询

纯记录回执形如：

```json
{"schema_version":1,"ok":true,"status":"stored","id":"synthetic-requirement"}
```

| 退出码 | status | 含义 |
|---|---|---|
| 0 | stored / duplicate | 已提交或同内容重复 |
| 1 | unavailable | 锁超时、版本不支持、存储或正文不可用 |
| 2 | invalid | JSON、字段、关联、文件输入或查询参数无效 |
| 3 | conflict | ID 内容冲突或完整绑定已被占用 |
| 4 | disabled | 全局/链路关闭或在途 generation 已过期 |

失败为 `ok:false`，error 只含 code/message。常规 JSON 回执在 stdout；`body` 成功输出完整原字节，失败 JSON 在 stderr，stdout 不输出残缺正文。body 先校验全量哈希和长度，`body_missing` 与 `body_corrupt` 可区分；空文件成功输出零字节。无库 body 返回 not_initialized。

`events` 默认页长 100，范围 1–1000，按 seq 升序。首请求返回 upper_seq、next_after_seq、has_more；后续携带相同筛选条件、同一 upper_seq，以 next_after_seq 作为 after_seq。新增或晚交事件不会进入已固定上限的导出。每页独立事务，不保持跨请求读锁。

`show` trace 返回实际 coverage_start、全局及链路控制历史、有效开关区间、已知 gaps、证据声明来源、每个 operation 的 begin/end ID，以及本链路全部派发 `dispatches:[{dispatch_id,kind,parent_dispatch_id,created_at}]`（04A 增加的只读字段，包括尚无事件的派发；不改 schema 或写入规则）。缺 end 不等于未执行；reply 缺 end 标为“回复查询未完成/结果未知”，不计为未知交付。通过 operation ID 可关联路由 begin/end，无需改动决策链接。

begin_missing/end_missing 只表示阶段记录是否保存；unknown 根据已存 end 的 outcome 和相关公开结果另行判断。timed_out、unknown、signaled 仍保留结果未知；send 缺少 confirmed=true 或 pending=true、start 缺少 name/instance 或 pending=true 时，也不能清除未知标记。成功 route/reply 若只有所需正文的 gap，则具体结果仍未知。明确 spawn_failed、已确认的发送、具有实例身份的启动，以及结果正文已保存的成功查询不会无差别降为未知。unknown=null 不等于成功、已送达或验收通过；pending 不证明后来投递，reply 的未知始终只描述回复查询，不计入 delivery_result_unknown。

list 支持完整绑定或 kind/scope/key 的多 run 查询，不自动合并。结果单列“未见运行登记声明”或“登记声明未核验”；task.transition 不能证明真实业务状态。来源时间早于入库时的当前记录时段时，事件查询显示 late_submission、declared_time_outside_current_coverage 及说明。手工晚交始终保留新 recorded_at，不倒改历史依据，不补成旧 operation 的 end。

查询只描述可见材料；没有完整率百分比，也不能由缺少记录断言操作从未发生。

## 宿主查询页（04A）

TUI 中 Agents 焦点下按 `t`，或点 Agents 顶部操作行的 `Telemetry`，打开居中的只读查询窗口（完整正文占用工作区）；底栏为 `Input ▸ Telemetry · Esc Close/Back`。页面打开期间所有键盘、粘贴和鼠标输入都留在页面里，不送到底层终端或插件，`saddle ctl` 的布局写请求与其他模态页一样返回 `busy`（只读请求与插件请求照旧）；最外层 Esc 关闭并把输入还给打开前的位置（Agents 或 Viewer）。不需要启用任何插件。页面只调用上面的 `Store` 查询（`settings/list_bound/show/events/body`），不写库：

- **无库**：显示 `Telemetry is not initialized — nothing recorded yet. No files were created.`，不创建目录或数据库。总开关关闭只改变右上角 `Recording: Off (global)`，已存记录照常可查。读取失败（目录不可用、版本不支持、锁超时等）显示错误码与说明，`r` 重试，不显示成空结果。
- **链路列表**：最新在上；每行创建时间（UTC，宽窗显示完整日期；scope简称在行内、原值在下方）、origin、绑定或标签、运行登记说明（原样显示 Store 的“登记声明未核验/未见运行登记声明”）及链路暂停。底部显示选中链路的 label、scope/key/run、coverage_start。`f` 打开 kind/scope/key/run 一行表单：kind、scope、key 必须都填（与 Store 绑定查询相同，按原值精确匹配），否则表单内提示、不发查询；run 可空。`F` 清除筛选，`r` 刷新开关和列表。宿主内部打开入口另可带一个不透明 `BindingFilter` 及来源名（Filter 行注明 `(from …)`），供 04B 插件跳转使用，Tasks 的 Telemetry 关联入口使用此能力。
- **项目 / 类型 / 搜索**：`p` 或项目按钮选择已加载记录中的关联scope（未关联项目单列）；`t` 选择任务/临时操作；`/` 输入标题、任务号或run搜索，Enter完成、Esc取消。只在当前列表内筛选，不修改项目设置或查询接口；插件预填的精确binding仍有效。`f` 保留高级精确筛选，`F` 清除所有筛选。列表和链路详情为最大160×36的居中窗口，列表高度随条目收缩，全文使用最多160列的居中大阅读窗口，正常尺寸四周留边，极窄或极矮时收起对应留边。
- **链路详情**：两次独立读取，分开标注。顶部三行来自 `show(trace)`，标 `Now (queried 时刻Z)`：绑定与登记说明、当前开关与关闭区间数、gaps 数、operation 数及缺 begin/缺 end/结果未知计数，以及 `Dispatch:` 列表。事件列表来自 `events`，标 `Events seq ≤ upper_seq`：首页固定上限，`n` 以同一上限取下一页（每页 100 条）并接在后面，之后新增或晚交的事件不混入；`r` 同时重读当前摘要和新上限的第一页。两者不是同一时刻快照；缺 begin/end 与结果未知只出现在当前摘要（`o` 操作摘要、选中 begin/end 事件时的 `op … now:` 行），事件列表不插入无 seq 的行。`o` 操作摘要中的 begin/end 若在已加载事件中则写 seq，不在则写事件 ID 并注明 `beyond event list`（全部已加载）或 `not in loaded events`。`i` 显示当前开关区间、`coverage_notice` 原文与已知 gaps。Tab/Shift-Tab 在 All 与本链路各派发之间切换（来自 `dispatches`，含尚无事件的派发），按 `dispatch_id` 重新读取事件；选中的派发按 ID 保存，`r` 重读当前摘要期间仍按该 ID 读取事件，不会退回 All 或指到别的派发。选中派发时在技术详情显示其 kind、parent、created_at（空派发仍直接显示）。
- **事件详情**：列表显示可读事件名与“宿主观测 / 主控声明 / 插件声明 / 系统控制”；详情优先显示结果、声明来源和正文预览。单份正文用 **‹查看全文 · Enter›**，多份正文用 **‹选择正文 · Enter›**；没有正文时明确说明，不显示全文按钮。预览仅取当前选中事件第一份正文的前两行，经 `Store::body` 校验并转义；空、缺失、损坏、非UTF-8分别显示，不替代完整阅读。切换事件后旧读取结果丢弃。`v` 或 **‹技术详情›** 展开原始事件名、event/trace/dispatch ID、存储的全部payload（嵌套点分键、数组原值）、正文哈希等；不补造字段。详情较长时标题显示行段，`J/K` 或面板滚轮独立滚动，换选回到顶部。
- 来源声明与晚交说明仍按Store原文显示；任务书快照、实际发送内容、原始需求、回复和退回原因分别命名。缺项显示原因；命令退出码不代表任务成功或验收通过。链接仍显示目标seq与原始类型，`carried_from` 只对当前选中事件解析目标链路，失败如实显示，不猜测、不自动跳转。

- **正文阅读**：经 `Store::body` 按哈希校验后一次读入完整原字节（≤16 MiB），只渲染可见行，不截断、不写库。UTF-8 默认软换行（`w` 切换，不换行时 ←→ 平移），`\t`、`\n` 以外的控制字符显示为 `\x1b` 这类可见转义；非 UTF-8 头部写 `not UTF-8`、默认十六进制，`x` 切到标明 lossy 的替换字符视图（UTF-8 正文的 `x` 切十六进制）。空正文显示 `Empty body (0 bytes, hash verified)`；`body_missing`/`body_corrupt` 等显示错误码并明说不是空白正文，`r` 重试。
- 列表、详情、表单、正文中来自存储的所有文字（标签、路径、producer、ID 等）都按同一规则转义，不作为终端控制序列输出。
- 读取在后台线程进行并显示 `Loading…`；只在打开、筛选、翻页、切换派发、`r` 以及选中带正文或链路外 `carried_from` 的事件时读取，没有定时刷新。离开某层或重新查询后，迟到的旧结果被丢弃。鼠标：点行选中，滚轮滚动，底部快捷项可点。

本页不提供统计、评分、导出、自动分析或设置开关。05A 已移除旧 Drover Dispatch 页签与 dlog 执行路径，继续使用现有 Telemetry 关联入口；Dispatch selected 业务动作不变。

插件跳转（04B）：声明 `telemetry.open.v1` 的进程插件可在用户点击时请求打开本页并预填不透明绑定（[插件协议 §11](插件协议.md)）。宿主只按 Store 的绑定规则检查，不截断长值、不改写控制字符。预填值含控制字符时，Filter 行与 `f` 表单都以 `\x1b`、`\n` 这类可见转义显示，提交时按原值精确查询；在这样的格中输入、粘贴或删除即整格替换为新输入，其余格编辑方式不变，Esc 保留原筛选。关闭本页回到发起跳转的插件视图。

## Drover 可选记录（04B）

Drover 插件经宿主提供的 `SADDLE_HOST_BIN` 调用本页列出的公开命令，不读写遥测库或正文文件；Saddle 宿主不读取 Drover 数据，也无插件名分支。没有改动 Corral。

- **选择**：项目默认在 `.drover.conf` 的 `TELEMETRY_RECORD=on|off`，缺省为关；任务页顶部 `Record default` 按钮（键 `R`）保存。Dispatch selected 旁的 `[x] Record`/`[ ] Record` 只改这一次派发；ctl `dispatch` 可带可选布尔 `record`，未给时取项目默认。此设置只决定是否请求记录，不决定项目是否采用主控分派；全局总开关仍决定能否采集，Drover 不会开启它。
- **建立身份**：选择记录时，Drover 先用新 UUID 经 `telemetry trace create`（origin=task，binding `{kind:"drover.task",scope:规范化项目根,key:任务号,run:本次 run_id}`）和 `dispatch create`（controller_handoff）建立身份，两次调用总墙钟预算 300 ms。总开关关闭（disabled）、存储不可用、宿主路径缺失或预算耗尽时，在任何发送之前回到原直接 `corral send`，结果 `telemetry.status=no_context` 并写明原因。这是唯一回到原路径的点。未选择记录时完全走原路径，不调用宿主、不创建遥测目录。
- **交付**：有上下文时，原交付消息末尾加一段独立标记的记录上下文附段（只有 trace_id、dispatch_id、task、run，注明不是任务内容也不是授权），把 `{"schema_version":1,"trace_id","dispatch_id","send_kind":"initial"}` 写入 0600 临时文件，执行一次 `$SADDLE_HOST_BIN agent --corral <原 --corral 值> --record-context <文件> -- send <MAIN_AGENT> <消息>`。没有 MAIN_AGENT 时不发送，附段进入 manual_text。传给 Corral 与 agent 入口的环境去掉 `SADDLE_HOST_BIN`。
- **结果判定**：该子进程在自己的进程组运行，取消或 60 秒超时先对该组 TERM、至多 250 ms 后 KILL，再回收。进程退出且两路输出收齐后，只取 stderr 字节 0 起的第一条完整行与最后一条完整行，前缀、版本、final 与同一 call_id 配对后才采信 executed。配对且 executed=false 才报 `delivery.status=not_executed`、不登记 start；配对且 executed=true 按原 confirmed/unconfirmed/rejected/unknown 映射（Corral 自己退出 125/127 归 unknown）；回执缺失、截断、不配对、超时或取消一律 unknown。agent 入口一旦启动，任何情况都不改走直接 send、不自动重发；采集失败只写在 `telemetry.send`（begin/end/gaps）。
- **流转声明**：Drover 先按原规则写入自己的任务状态，成功后才 `telemetry append` 一条 task.transition（plugin_statement，producer `drover`，记录真实 from/to 与 business_committed_at=Drover 记录时间）。派发用本次 trace；之后的提交审查、接受、退回用完整 binding（含 run）经 `telemetry list` 找到该轮 trace 再追加，不按最新链路猜，也不在 Drover 数据中保存 trace_id；该轮没有 trace 时报 `not_recorded`，不补造。start 写入失败时不追加流转。
- **结果字段**：`delivery`、`record` 保持原义，另加 `telemetry:{status:not_requested|no_context|context, reason, trace_id, dispatch_id, send, transition}`；流转结果另加 `telemetry:{status,trace_id}`。两个存储不原子提交，遥测失败不改变交付或任务记录结果。
- **跳转**：有任务号的任务在详情页签行显示 `Telemetry ↗`，以 kind/scope/key（不带 run）打开宿主查询页，列出该任务所有轮次；未编号待办不显示。无需启用 dispatch 插件。

05A 源码已删除旧 Drover Dispatch 页签；`--dispatch-log <值>` 仅作弃用兼容解析，不读取或执行。真实安装及全局消费者切换尚未执行。

## 采集层的 Rust 接口

`telemetry::Store` 持有路径、不持有长期连接。`prepare_operation(OperationInput, Observation, brief_file)` 在读取正文前固定两级 generation，验证 trace/dispatch 和所有已存依据；生成 UUID v4 的 operation/begin/end ID，并在进程内保留原始暂存字节。返回的 Capture 不可序列化，调用者不能指定或刷新 generation。

- OperationInput：schema_version、trace_id、dispatch_id、kind、producer、basis_event_ids、decision_event_id、previous_brief_event_id。kind 为 route / agent.start / agent.send / agent.reply。
- Observation：observed_at、payload、bodies。brief_file 单独传绝对路径；reply 不接受任务书。未提供、不可读和超限正文以契约 gap 表示，不建立空壳 snapshot。
- `record_begin(&capture)`：在一次事务中复核 generation、发布正文、写 operation、brief.snapshot、begin 及关联。
- `record_end(&capture, observation)`：再次复核原 generation，存储端确定 begin_missing。begin 缺失时仅恢复预先固定的依据和原暂存快照；快照标 publication_phase=end。暂存丢失则保存 gap，不重读原文件。end 之后不能倒补 begin。
- end Observation 不接受调用方自填 begin_missing；存储负责它及恢复关联。关闭后重开不能使旧 Capture 复活。同值开关不撤销 Capture。

执行 payload 按契约白名单封闭。明确的 JSON 结构：`explicit_parameters` 是只含 model/effort 字符串的对象，`labels` 是只含 role/model/effort 字符串的对象；无法识别可为 null，并带同名 gap。对象不含某项表示未显式提供该参数，不用标签代替实际参数。版本、元数据或公开返回字段未知时为 null 并带对应角色 gap。`outcome` 为 `{kind:"exited",exit_code:0..255}`、`{kind:"signaled",signal:正整数}`，或仅含 kind=spawn_failed/timed_out/unknown 的对象；confirmed/pending/merged_with_draft 为布尔值或 null，name/instance 为公开返回字符串或 null；at 为公开返回的 **JSON 数值 Unix 时间戳（秒）或 null**，不转字符串、不冒充存储端时间。阶段 02A 按 Corral 契约纠正了阶段 01 的 at 字符串校验，已有字符串夹具同步改为数值；没有迁移或导入旧记录。成功 route 必须保留 response/suggestion 或相应 gap；成功 reply 必须保留 reply 或 gap，association 固定 not_proven。

`check_operation(&OperationInput)` 在读取正文前检查已存关联和开关；有库时，即使关闭也拒绝已确认不存在、跨 trace 或类型错误的关联，无库/不可用不猜测关联是否有效。`Capture::gaps()` 提供 begin 采集缺口供入口回执使用。Saddle 内部的有期限 end 写入缩短最终事务的等锁预算；既有 `record_end` 调用方仍沿用 100 ms 预算，无其他行为变化。

## Agent 执行入口（阶段 02A）

本入口不要求运行 TUI 或插件，不读取 Corral 私有状态，不调用 `stop`，也没有向 Corral 添加任何遥测参数、环境或标签。现有 UI/ctl 调用链尚未切换。

```text
saddle agent [--corral PROGRAM] [--timeout-ms MS] \
  [--record-context /abs/context.json] [--brief-file /abs/task.md] \
  -- start|send|reply <原 Corral 参数>
```

`--corral` 是一个程序路径（可含空格）或 PATH 中的程序名，默认 `corral`。例如 `--corral '/absolute/path with spaces/corral'`，不能填 `corral --flag` 这样的命令字符串。此 headless 入口不加载 TUI 的 config.toml。分隔符后的原业务 argv 用操作系统参数逐项传递，包括非 UTF-8 字节；stdin 和环境继承，不使用 shell 拼接。

上下文文件是至多 64 KiB 的 UTF-8 JSON、绝对普通文件；拒绝符号链接、FIFO、未知字段/版本及无效组合。示例：

```json
{
  "schema_version": 1,
  "trace_id": "synthetic-trace",
  "dispatch_id": "synthetic-dispatch",
  "basis_event_ids": ["synthetic-requirement"],
  "decision_event_id": "synthetic-decision",
  "previous_brief_event_id": "synthetic-previous-brief",
  "send_kind": "rework"
}
```

三个关联字段可省略，basis 默认空数组；send 必须显式指定 initial/followup/rework，start/reply 不能带 send_kind。reply 不接收任务书或依据/决策/旧快照链接。previous_brief_event_id 必须配合本次 --brief-file，生成新快照的 supersedes；不替代现场读取。generation、operation/event ID、producer、来源均由入口或 Store 生成，调用方不能传入。

任务书路径必须为绝对 UTF-8 路径；开启采集后按存储规则读取普通文件原字节。不可读（包括符号链接/FIFO）或超过 16 MiB 时保存 gap，不建空壳快照。不传上下文、开关关闭或存储不可用时，不读任务书正文、不初始化存储，有效业务仍只执行一次。已确认无效的上下文/关联在执行前拒绝；存储不可用时关联保持未核验。

现场证据范围：

- start 识别公开排列 `start NAME [--cwd DIR] [--unique] [--prompt TEXT] [--env K=V] [--label K=V]… -- PROGRAM ARGS…`；只保存 cwd、agent 程序、实际 --prompt 字节及 role/model/effort 标签。--env、其他标签和完整 argv 不落盘。
- 对 basename 为 codex/claude/pi/omp 的程序，识别 `-m VALUE`、`--model VALUE`、`--model=VALUE`；Claude 的 `--effort VALUE`/`--effort=VALUE`；Codex 的 `-c TOML`/`--config TOML`/`--config=TOML` 中显式 model 与 model_reasoning_effort 字符串，例如 `-c 'model_reasoning_effort="high"'`。不从标签、配置文件或默认值推测实际参数。已知的跳过权限开关及 --api-key/--settings/--permission-mode/--provider/--extension 值只用于安全跨过参数边界，不保存其内容；其他形式的 explicit_parameters 为 null/unrecognized。
- send 保存公开排列 `send NAME TEXT …` 中实际 TEXT 的全量字节；标签不代替模型参数，merged_with_draft 不推导出不可见的草稿全文。
- reply 解析公开 JSON 的 text 并保存其完整 UTF-8 字节（包括换行、NUL），保留数值 at、name/instance，association 固定 not_proven。响应缺字段为 null/not_available，错误类型或无法解析为 null/unrecognized；不把 reply 认作某次 send 的必然回复。
- 未识别元数据不猜测。无法识别 send/reply 的必要目标时，采集回执报告 capture/unrecognized，仍原样执行业务；Corral 自行判断业务用法是否有效。

每个正文上限仍为 16 MiB。额外的 stdout JSON 包络解析上限为 **32 MiB**：超过后只放弃遥测解析并报告 too_large，stdout/stderr 继续流式转发全部业务字节；不将截断前缀当成完整 JSON 或回复。stderr 不作为正文保存。

每次调用由 Saddle 新生成一个 UUID v4 `call_id`，独立于可选存储的 operation_id，不传入 Corral argv/env。正常 stderr 的布局为：

```text
saddle-telemetry: {"schema_version":1,"call_id":"本次 UUID v4","final":false}
<业务 stderr 原字节>
saddle-telemetry: {"schema_version":1,"call_id":"同一个 UUID v4","final":true,...}
```

第一行是宿主起始边界，从本次 stderr 的字节 0 开始，以 LF 完整结束；它只标识本次输出边界，不证明业务已启动。起始行先进入同一有界转发队列，完整写出后才转发业务 stderr；业务仍可执行，不因起始行背压额外等待 spawn。起始输出失败/部分输出时，不跳过它继续转发业务同名文本；取消或超时则按已有有限等待结束，不将不完整输出冒充完整返回。若只是输出等待而已取得业务正常退出码，继续保留该已知退出码。

最后一行是宿主终止回执，除同一 call_id、schema_version=1、final=true 外，仍包含 executed、operation_id（未捕获时 null）、begin/end 状态、outcome 和 gap code，不包含正文。若业务 stderr 没有行尾，在终止行前加一个分隔换行。无上下文、入口拒绝及启动失败也采用同一对边界；拒绝/启动失败没有业务 stderr，按顺序输出起始和终止两行。`--help` 不执行业务，也不输出此协议。

消费者必须等待进程退出并收齐本次完整 stderr，然后依次检查：

1. **只取字节 0 起的第一条完整 LF 行作为起始边界**，要求前缀 `saddle-telemetry: `、合法 JSON、schema_version=1、final=false，以及合法 UUID call_id。不得向后搜索其他 start，也不得在缺失/部分前缀后重新同步到业务文本。
2. **只取完整流的最后一条 LF 行作为终止回执**，要求同一前缀、合法 JSON、schema_version=1、final=true，且 call_id 与首行完全相同。末尾有部分行/额外文字，或最后一行标识不匹配时，不能向前搜索其他任意 final。
3. 仅匹配成功后采信该终止行的 executed/outcome。缺起始、缺终止、部分行或标识不匹配一律为 unknown，即使进程正常退出且已读到 EOF；不能根据业务同名行或退出 125/127 推断确定未执行，也不据此重发业务。

例如 stderr 背压时，业务同名 final 可能完整到达而宿主 final 完全未写出；它与首行宿主 call_id 不匹配，因此仍为 unknown。输出损坏、取消或 KILL 也可能使边界缺失，规则相同。这是本次调用的输出防混淆边界，不是针对恶意子进程的来源认证；不增加任何 Corral 接口或外部服务。

| 情况 | 退出码/回执 |
|---|---|
| Corral 正常退出 | 原样透传，含外部程序自行返回的 125/127；executed=true |
| Saddle 字段/组合/已知关联拒绝 | 125；executed=false |
| 无法启动 Corral | 127；executed=false；开启采集时保存 spawn_failed end |
| 子进程由信号终止 | 128+signal；已启动则 executed=true |
| 本入口 --timeout-ms 耗尽 | 124、outcome=timed_out；executed 按是否已经 spawn 判断 |

`--timeout-ms` 可选，范围 1–86400000，从入口解析开始计时，包含本次采集。未指定时由调用方管理总时限。剩余不足 100 ms 时跳过 begin/end 写入，end 最终等锁不超过剩余预算；不为遥测重置或延长业务期限。超时先 TERM，最多等待约 200 ms 后 KILL 并回收直接子进程；INT/TERM 单独发到 wrapper 时也转发给直接 Corral CLI 并回收。取消时可能只留下 begin 和缺 end；不补采、不刷新 generation，不重放业务。磁盘阻塞/fsync 不承诺硬实时，调用方仍必须管理外部总超时。

受支持的调用方须在 exec 前创建并记录本次独立进程组，包含 wrapper 和它的短命 Corral 客户端。Rust 可在 `std::os::unix::process::CommandExt::process_group(0)` 后 spawn，并记录 child.id() 作为 PGID；取消时 `kill(-pgid, SIGTERM)`，最多 250 ms 后 `kill(-pgid, SIGKILL)`，回收直接 child，并持续收取两路输出。只操作本次记录的组，不按名称找进程。wrapper 不另建子进程组，便于调用方覆盖整个短命客户端组。

Corral 自己已分离的 agent/pen 不在该组；取消不撤销已投递/已排队内容，不 stop 托管 agent。SIGKILL 无法转发，只杀 wrapper 时不保证后代停止。即使输出读取方停滞，入口仍监督取消/超时并回收直接客户端；取消时尚未转发完的输出不冒充完整返回，可能无终止回执。

## 内置插件的无界面命令（03A）

```text
saddle plugin [--config /abs/config.toml] status [ID]
saddle plugin [--config /abs/config.toml] run ID COMMAND [--record-context /abs/context.json] [--brief-file /abs/brief.md]
```

03C 的 core 目录含默认停用的 dispatch，提供 `route` 命令。`status` 输出一行 JSON，`core` 列出内置插件的 id/name/version/enabled/state、commands（含 capture 类型）、resources、setup_note 与 setup_files；`plugins` 只列外部登记的 id/directory/enabled/manifest_readable，不报告 TUI 进程状态。state 为 enabled/disabled/conflict。resources 与 setup_files 的含义见下节（03B）；不输出笼统的 installed 字段，安装与否只看各目标的实际分类。

`--config` 只定位其同目录的 `plugins.toml`，不读取配置正文；默认位置与 TUI 相同。显式路径须绝对、UTF-8，重复选项拒绝，命令不接受额外位置参数。`status` 不创建登记、遥测或资源目录，不安装或修复文件；退出 0 为成功，1 为登记不可读/输出失败，2 为参数错误或未知 ID。

core 开关存于可选 `[core.ID] enabled = true|false`，无表/无项默认停用；未知 core 项在新版读写外部登记时保留。旧二进制读取时忽略该表，写回登记会丢掉它，再回新版默认停用。core ID 由组装目录保留，禁止新增同名外部登记；已有同名外部条目仍沿用原流程，core 呈 conflict 并拒绝执行。启停只在 TUI 管理页进行（03B），不提供 headless enable。

`run` 只同步执行一次内置命令，不需 TUI。外部插件仍走运行中的 `saddle ctl plugin`。stdout 是插件返回的原字节；0–124 是业务退出码。参数/登记不可读/未知/停用/冲突/命令不支持采集/显式上下文无效都在进入插件前拒绝，退出 125、executed=false、outcome=null。插件 panic 或返回 ≥125 的非法业务码，退出 126、executed=true、outcome=unknown；若已有 Capture，保存 unknown end 与缺失正文 gap。调用期间静默并随后恢复原 panic hook，避免 hook 向 stderr 写 panic 正文或因背压阻塞。未增加信号处理或总超时，调用方终止进程后结果保持未知。

记录上下文与上面的 agent 格式相同，但 route 不接受 decision_event_id 或 send_kind（即使值为 null），previous_brief_event_id 须同时给 brief 文件。上下文仅接受最多 64 KiB 的普通文件，不跟随符号链接。没有上下文时不打开/创建遥测库，也不读 brief。预检已确认无效的关联会拒绝执行；关闭或不可用只影响记录。插件经 Recorder 提交一次 begin 材料，宿主生成身份和来源、固定 generation、原子保存快照与 begin，复用现有 Store 的缺 begin 恢复；不换 generation、不补造前置成功、不为记录失败重跑。

stderr 的起止回执前缀是 `saddle-plugin: `。除 `--help` 外，所有 run 路径（包括解析拒绝）先在字节 0 写 `schema_version=1, final=false, call_id=<UUID v4>`，最后写同 call_id 的完整 LF 终止行。终止行包括 plugin/command、executed/outcome/error、operation_id/begin/end/gaps，不含正文或密钥。每行写出等待上限 1 秒，每次最多写 512 字节；不更改继承 stdout/stderr 的 O_NONBLOCK。起始行未完整写出就不写终止行；终止行失败/部分写出即放弃，不改变已知业务码，不重试调用。stdout 写入或 flush 失败只在回执记 output/write_failed，不把 output 当作遥测事件正文角色。

消费者应等待进程退出、收齐输出，只匹配 stderr 字节 0 的第一条完整 LF 起始行和完整流最后一条 LF 终止行，要求前缀、版本、final 标志和 UUID call_id 匹配；不搜索其他行。缺失、截断、不匹配都保持未知，不能仅凭 125/126 断言未执行，也不能据此重跑。业务输出仍由 stdout 与业务码表达。

采集状态按以下优先级报告：拒绝为 not_requested；无上下文为 not_requested；预检 disabled/unavailable 固定保留；已请求且预检可采集但未调用 begin 才是 not_reached；调用 begin 后为 prepare/record_begin 的结果，有 Capture 才尝试 end。第二次 begin 忽略并只在回执加 capture/unrecognized。普通第三方 append 的未认证来源限制不变。

## Dispatch 路由与可选采集（03C）

在 Settings → Plugins 启用 Dispatch；同页显示接入说明、技能状态与模板位置，也可只读运行 `saddle plugin status dispatch`。启用安装全局技能不会自动让所有项目采用主控分派。希望项目默认采用时，由用户将模板第1节合入项目 AGENTS.md，填写参数并处理原有规则冲突；某次明确要求走分派流程也可以。宿主不维护项目名单、不自动改项目文件。

```sh
echo "<三五句任务摘要>" | saddle plugin run dispatch route
# 需要采集时显式提供已有 trace/dispatch 的上下文：
echo "<三五句任务摘要>" | saddle plugin run dispatch route \
  --record-context /绝对路径/context.json --brief-file /绝对路径/任务书.md
```

路由仅从环境读取 `TYPESAFE_API_KEY`；缺失或空串时返回 `ok:false`、业务码 1，不请求、不 begin。摘要须为 UTF-8，按 Python strip 字符集去首尾空白；空摘要照常请求。JEV 只收到摘要、固定模型和题目，任务书原字节由宿主按既有机制快照保存，不发给 JEV。没有记录上下文时不打开或创建遥测库。插件启停与遥测开关独立：遥测初始关闭；已启用插件在采集关闭或存储失败时仍返回相同业务结果，有效性检查发现无效上下文/关联时则由宿主在执行前拒绝。

stdout 一行业务 JSON，0 表示 `ok:true`，1 表示 `ok:false`。建议含 tier、cross_review、impact，各自可能为 null；model/usage 按完整解析值透传。主控决定实际档位、模型、验证预算和委派。调用结束并收齐输出后，按上节完整首尾配对回执判原因与采集状态。配对 error.code=plugin_disabled 才写「插件未启用」；缺失、截断或不配对只写原因未知，不能单看末行或退出码。停用/未知时依项目规则或本次明确分派要求自行定档继续，不自行启用、不重试、不回退 route.py、不追加询问；未要求分派的项目不因此自动委派。

传输固定 `https://api.typesafe.ai/v1/systemone` / `jev-1.13.0`，ureq 3.4.2 + rustls，正常证书校验，不跟随重定向，不开放换 URL 的环境或 CLI 参数。解析/连接/请求头发送/请求体发送/响应头等待/响应体读取分别 10 秒，无总时限；最多两次尝试。首次 429/529 等 1 秒，发送完成前的错误或超时立即重试一次；发送完成后的非超时错误、截断、无效 JSON、其他 HTTP 状态不重试。读取最多 16 MiB（多读一个字节判超限），内部重试仍共用一个 operation。

begin 保存 strip 后摘要、实际请求体、`router_version=route-v1` 及规则 SHA-256；end 的 response 是整个解析 JSON 的紧凑 UTF-8 表示，保留键顺序、重复键后值和首次位置，shape 失败仍保存。suggestion 是 stdout 原字节。最终非 2xx/网络失败/截断为 response not_available，JSON 无效为 unrecognized，响应或解析表示超限为 too_large；不保存前次 429/529 或 HTTP 错误体为完整 response。HTTP 错误前 300 字节只在 suggestion 的诊断文本出现，不捕获授权头。采集失败绝不重放业务。

旧技能链接是 foreign 冲突，不自动替换。资源 revision 和指纹随构建固定，模板逐字节沿用旧来源；05A 保留 SKILL 的派发规则，将可选记录操作改为同资源内的 [遥测操作.md](../plugins/dispatch/resources/corral-dispatch/遥测操作.md)。未做真实 JEV/TLS 或代理兼容性验证；2026-10-02 的本机安装与技能切换见 [05B记录](任务/遥测05B-实际切换记录.md)，未发布远端release。

## 内置插件资源与管理页（03B）

**现状**：03C 已在源码中接入默认停用的 dispatch，声明 `corral-dispatch` 的 SKILL.md、项目AGENTS模板.md、README.md；05A revision=2 增加同版本遥测操作.md。沿用 03B 通用资源安装器、所有权记录及管理页。2026-10-02 两处旧 Corral 链接已备份移走，公开管理页安装 revision2，两目标 owned_current；Corral 源目录未改。

**资源与目标**：v1 只支持 `AgentSkill`。资源名和文件名必须是不含 `/`、不以 `.` 开头的普通名称（不支持子目录），文件集必须含 `SKILL.md`，revision ≥ 1，同一插件内资源名唯一；未知类型或非法声明在 status 中报告 error，任何触发点都不写入。每个技能资源对应两个目标：`$HOME/.claude/skills/<名称>`（Claude Code）和 `$HOME/.agents/skills/<名称>`（Codex）。`~/.claude`、`~/.agents` 不存在时该目标 skipped(agent_absent)，不代为创建；`skills/` 可创建。HOME 本身是入口锚点；其下的 agent 主目录、`skills/`、目标目录及其中文件都不跟随符号链接，任一处是链接即报告冲突（父级为 reason=parent_symlink，目标本身为 symlink），原内容不动。读取、写入、删除和回滚都通过从 HOME 逐级不跟随链接打开并核实过的目录句柄进行，路径在核实之后被换成链接也不会改写或删除别处。清理空目录（移除、移除收尾、安装回滚、本轮新建的 `skills/`）时，只在该名字仍指向本轮核实或创建的同一目录时才 rmdir；同名目录已被替换或拿不到可信句柄时保留；正常移除及目标目录回滚等路径会注明 directory kept，新建 `skills/` 的部分失败清理详情仍缺保留说明（见下方 S1），不保证所有路径都有该提示。核对与 rmdir 是两次系统调用，不是原子操作。

**所有权记录**：`$XDG_STATE_HOME/saddle/plugin-resources.json`（XDG_STATE_HOME 须为绝对路径，否则 `~/.local/state`），按用户而非 `--config` 区分；写入用同目录临时文件、fsync、rename，与之并列的 `plugin-resources.lock` 用非阻塞 flock，忙则本次各目标为 busy，不等待、不重试。只有需要写入时才取锁并创建状态目录（0700），取锁后重新读取记录、重新分类再动手。内容指纹为“按路径排序的 `[[路径, sha256], ...]` 紧凑 JSON”的 SHA-256，写作 `sha256:<hex>`。记录读回后，已装与 pending 文件表中的文件名同样须是普通名称；否则该目标记 unreadable(invalid_record)，只报告，不按其中的名字读取、写入或删除任何文件。

**status 资源段**（只读，不建目录、不取锁、不写任何文件）：`resources[]` 每项有 kind、name、revision、fingerprint、error，以及 `targets[]` 的 agent、path、state、revision（已归属时为盘上版本）、reason、detail。state 取值：absent、missing、foreign（reason=symlink/directory/file/parent_symlink，链接附 `-> 目标`）、owned_current、owned_outdated、newer、incomplete、modified（reason=modified/user_file/content_differs/symlink/file/parent_symlink）、unreadable（reason=unreadable/invalid_record/skills_not_directory）。`setup_files[]` 给 label、resource、file 和 `paths`：只列本插件已装且未改动的目标中该文件的绝对路径，空数组即未安装。记录不可读时 status 退出 1（`resource_record_unavailable`）。

**触发点**（设计 §6.4）：

| 触发 | 行为 |
|---|---|
| 管理页 Enable | 先写登记；登记失败什么也不做。成功后处理资源：absent/missing 安装，owned_outdated 升级，其余不写。资源部分失败时插件仍是启用状态，逐目标报告。 |
| 管理页 Sync resources（仅启用时） | 与 Enable 的资源处理相同，用于重试或补装。 |
| TUI 启动（仅已启用的内置插件） | 只升级本插件拥有且未改动的旧版本；不新建缺失目标、不降级，其余只读。无事可做时不建状态目录。 |
| Disable | 只写登记，保留已装技能。 |
| 管理页 Remove resources（仅停用时） | SKILL.md 先删，只删记录在案且哈希未变的文件，目录空了才 rmdir；用户额外文件和目录保留；missing 只删记录。 |
| `saddle plugin status/run`、`saddle ctl` | 不写技能目录或记录。 |

**保留用户修改与冲突**：没有记录的同名目标（目录、文件或链接）是外来的，任何触发点都不写、不删，只报告冲突；切换前两处指向 Corral 仓库的 corral-dispatch 软链接属于此类，启用后会显示“Conflict — existing link kept”，原链接不动，这是预期而非失败。记录文件被改、删、换成链接，或同 revision 内容不同，都算 modified，不覆盖也不在 Remove resources 中删除；升级会写入的新文件名若已被用户占用，也记 modified。目标目录中用户新增的其他文件不算修改，升级和移除都保留。较新构建装过的版本（newer）不会被旧构建降级。核对与替换之间仍有极短窗口：用户恰好在那一刻编辑的文件可能被覆盖。

**失败与恢复边界**：写入顺序为确认父目录 → 写 pending 记录 → mkdir → 逐文件“同目录 `.名称.*.saddle-tmp` 临时文件 + rename”（SKILL.md 最后）→ 定稿记录；记录写失败则目录不动。同一轮失败只回滚能证明是本轮写入的文件（哈希等于本轮字节）：安装删除、升级恢复内存中的旧字节、被删的旧文件重新写回；对不上的文件原样保留并列在回执中，此时 pending 记录保留，下次分类为 incomplete。崩溃后：目录不存在为 missing（Enable/Sync 重装）；目录完整等于 pending 或旧版本则按该版本处理，并由下一次 Enable、Sync resources、TUI 启动或 Remove resources 在锁内重读后写回记录（新版本定稿、旧版本撤 pending），即使技能文件无需改动；status/run/ctl 只显示、不写回。移除已删完全部自有文件、只剩用户文件时，下一次上述入口清除本插件的记录、保留用户文件（Remove resources 在目录为空时还会 rmdir）。写回失败报告 failed(record_write)，pending 原样保留。两者都不完整为 incomplete，启动和 Enable/Sync 都不修补。处理 incomplete/modified：自行检查、保留需要的内容后删除该目标目录，再 Sync resources（启用时）按 missing 重装，或在停用时 Remove resources 清掉记录。没有自动修复或事务引擎。

**管理页**：Settings → Plugins 中内置插件排在外部插件之前，Runtime 显示 Built-in，Enabled 列为 Yes/No/Conflict。详情依次是 `ID · Built-in · 状态`、每个技能的分目标状态、插件提供的 setup_note、按 setup_files 解析出的路径（全未安装时写 “<label>: not installed (see skill status above)”），以及最近一次 Enable/Sync/Remove 或启动升级的结果摘要（启用结果与资源结果分句，冲突时注明 Nothing was overwritten）。窗口不够时省去说明与路径，改为提示 `saddle plugin status <ID>` 查看完整内容。按钮为 Enable/Disable、Sync resources、Remove resources、Add local…、Refresh、Back；内置行没有 Open panel、Restart、Remove（登记）。外部插件行的显示和动作不变。Plugins 搜索面板列出内置插件（状态 `Built-in · Enabled/Disabled`），Enter 或点 Manage 打开管理页并选中该行；与外部登记冲突的内置 ID 不在面板列出。宿主只渲染插件给出的文字与解析后的路径，不解析项目规则、不维护项目名单、不改 AGENTS。
