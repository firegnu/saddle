# 插件开发入门

> 已退役（2026-10-05）：Saddle 已删除遥测、Drover 和整个插件系统。本文只保留设计/验证历史，不再作为当前操作规矩或安装指引；旧磁盘数据不读、不删。当前功能与命令见 [README](../README.zh-CN.md)，派发路由由 ranch 提供。

插件是一个独立程序。Saddle 启动它，传入尺寸、主题和用户操作；插件返回画面，并可请求内部通知。画面显示在 Saddle 工作区内，插件不另开终端窗口。

当前支持本地可信进程插件，以及由宿主绘制的工作区或覆盖面板。插件从统一 Plugins 面板打开，不向外壳添加专用侧栏或状态栏。Drover 的任务核心、界面和后台通知已使用同一套 SDK 完整插件化。SDK 是开发中的 0.1 接口；插件以当前用户权限运行，不是沙箱。

## 从能运行的示例开始

准备 Rust stable 1.96 或以上，以及含插件功能的 Saddle。复制 [examples/counter-plugin](../examples/counter-plugin) 整个目录到你自己的项目位置，保留 Cargo.toml、Cargo.lock、plugin.toml、package.sh 和 src。它依赖固定 Git revision 的公开 SDK，不引用宿主私有模块，首次构建需要下载依赖。

在复制后的项目目录运行：

```sh
./package.sh
```

脚本为本机平台构建 release 程序，输出：

```text
dist/counter-plugin/
├── plugin.toml
└── bin/
    └── saddle-counter
```

也可以 `./package.sh /path/to/my-plugin` 指定长期保留的目录。设置 CARGO_TARGET_DIR 可以共用编译缓存，不是使用插件的必要条件。脚本不修改 Saddle 配置，不进行全局安装；再次打包会覆盖这两个交付文件。若目录已经被 Saddle 使用，先停用插件，打包成功后再启用。

在 Saddle 中打开 Settings → Plugins → Add local，填输出目录，依次 Read manifest → Add disabled → Enable，然后关闭设置，点击左侧 Plugins，在面板搜索 Counter，Enter 打开。点击 Increment 后计数增加并请求内部通知。整个输出目录可交给使用相同操作系统和 CPU 架构的用户；他们不需要 Rust。登记只保存路径，所以目录移动后需要重新添加；不需要那些临时测试环境的 XDG/SADDLE 环境变量。

## 清单和入口

[plugin.toml](../examples/counter-plugin/plugin.toml) 说明插件身份、入口和所需能力：

```toml
manifest_version = 1
id = "demo.counter"
name = "Counter demo"
version = "0.1.0"
protocol_major = 1
executable = "bin/saddle-counter"
args = []
required_capabilities = ["panel.v1", "notify.v1", "ui.entry.v1", "panel.overlay.v1"]
entry = "open"

[view]
id = "main"
placement = "overlay"

[action]
id = "open"
title = "Counter"
view = "main"
```

开发自己的插件时，修改 id/name/version，以及 Rust 实现中对应的 id()/version()。id 必须唯一，只能使用字母、数字、点、下划线和连字符。改变二进制名字时，同时修改 Cargo.toml 的包名（或显式 bin 名）、清单 executable 和 package.sh 的 `--bin saddle-counter`；输出目录默认名也可随之修改。不要把示例的固定名字误认为协议要求。

入口调用 `saddle_plugin_sdk::run(|| Box::<Counter>::default())`。业务初始化放在这个 factory 内，因为 SDK 会先保留协议管道，再将业务 stdout 转到日志、stdin 接到空输入。不要自行读取终端输入、进入 raw mode 或向终端发送 ANSI；不需要直接实现握手和 JSON 传输。

## 在 Saddle 内绘制和响应操作

完整、可编译的例子是 [src/main.rs](../examples/counter-plugin/src/main.rs)。实现 SDK 的 Plugin trait：

| 方法 | 输入 | 你的工作 |
| --- | --- | --- |
| id()/version() | 无 | 返回与清单一致的身份和版本 |
| render(area, theme) | 面板尺寸、主题 | 返回该区域的 Ratatui Buffer |
| event(event, context) | 输入、焦点、关闭、通知回执等 | 更新业务状态，按需请求重绘或通知 |

view.placement 可选 workspace（工作区 tab）或 overlay（居中覆盖界面）；新清单需与支持这些能力的宿主/SDK 配套。已运行的旧工作区视图会优先被聚焦，关闭它后再按声明打开新位置。overlay 的 Esc 由宿主关闭，Ctrl-] 关闭并返回 Agents；SDK 的 Context::reserved_keys() 提供本视图保留键。声明的 action 只负责打开视图，业务键鼠仍通过 event 处理。

在 render 中用 SDK 重导出的 `ratatui` 创建 Buffer、写入文本或绘制控件；SDK 转换为结构化字符帧，Saddle 负责显示。按传入尺寸裁剪，使用主题颜色；不要假定用户窗口固定大小。当前是字符界面，不是 HTML、任意像素画布或本机 GUI 控件。

`area` 是内容区，外框、插件标题和外层关闭入口由 Saddle 绘制。插件不要再套一圈整页边框；可为表单、按钮和内部区域绘制必要的边界。

Counter 在 Event::Input 中检查按键的 code、phase、modifiers，只有未带修饰键的 Enter press 才计数；因此 Shift+Enter 不触发按钮。鼠标使用面板局部坐标，检查按钮区域，并把按下/抬起与 frame_id、size_revision 对应，避免窗口变化后误点击。不要直接把任何 Enter 或 mouse up 都当成一次激活。

状态变化后调用 `context.redraw()`。SDK 会在尺寸或主题变化时安排重绘，业务状态的变化需要插件主动请求。调用 `context.notify("...内容...")?` 请求内部提示，再通过 Event::Notification 接收 accepted/limited 等结果；通知有长度和速率限制，Counter 展示了被限流的反馈。

event/render 在插件事件线程执行，应及时返回。耗时操作放到插件自己的后台工作中，Event::Tick 可消费有界结果队列；插件负责在 Drop 中取消这些工作。stdout 的普通日志可用，但不要输出敏感内容。

## 关闭、重启与验证

关闭面板只隐藏视图，插件进程仍可运行；Counter 重开后计数保留。Disable 停止进程，Restart 重建进程，Counter 的内存计数归零。Remove 先要求停用，只删除登记，不删除磁盘目录。Saddle 退出时回收它启动的插件进程。

对照这些行为验证自己的插件：能添加/启用；尺寸变化后仍能显示；输入只触发预期动作；通知可见；关闭重开与停用重启符合业务预期。需要保存业务数据的插件自行设计存储，Counter 没有持久化。

进一步查阅：[系统设计](插件系统设计.md)、[协议](插件协议.md)、[Rust SDK 源码](../crates/plugin-sdk/src/lib.rs)。本轮提供可复制的示例和本地目录交付，不提供插件市场、自动更新或压缩包安装。

## 提供 Attention 条目

[Attention demo](../examples/attention-plugin/) 是另一个独立 Rust 示例，打包方式仍是 `./package.sh`。默认产物 `dist/attention-plugin`，按相同本地目录流程登记和启用。它发布两条合成条目；在 Saddle 的 Attention 中点击 Demo item 1/2，会打开插件并显示准确目标。视图内 `u` 更新或恢复，`w` 撤回全部，Esc 关闭；关闭不停止后台来源。Disable 撤下条目，Restart 重建合成状态，不涉及真实任务。

清单增加 attention.v1，仍声明 main view / open action。调用 `context.attention(Vec<AttentionItem>)?` 发布完整快照，空 Vec 撤回；`Event::AttentionPublished` 是保存回执，`Event::AttentionOpen` 带回目标。后者可以先于视图尺寸消息到达，先保存目标并重读业务状态，再在 render 中绘制。不要据此自动执行提交、接受或派发。

快照只负责持续条目，不会自动发弹框；有一次性提示需求仍显式调用 notify。断连来源显示不可用，旧条目不能继续点；停用撤下自己的来源。详细限制见 [协议 §10](插件协议.md#10-通用-attention-来源attentionv1)。
