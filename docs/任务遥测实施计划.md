# Saddle 核心遥测实施计划

2026-10-01。依据：用户持续推进、主控与 Claude Code 三轮设计审查收敛、用户确认三项产品默认值。接口以 [契约 v1](任务遥测接口契约.md) 和 [DESIGN.md](DESIGN.md) 最新决定为准。各阶段串行接地基；不启动额外并行开发。

## 实施顺序与职责

| 阶段 | 本阶段交付 | 与后续的分界 |
|---|---|---|
| 01 存储与查询 | Rust 遥测模块、SQLite/完整正文、事件与关联约束、幂等和来源声明、持久化开关、纯记录及 headless 查询 CLI | 只落存储侧开关约束；不执行 Corral/JEV，不改 Drover 或 GUI |
| 02 执行采集与总开关入口 | Saddle agent 上层适配、现场快照/事件、开关在途语义、退出与取消、Saddle 设置入口 | Corral 仓库和核心保持不动；不恢复旧 Drover |
| 03 同进程路由 | saddle dispatch route 实际 JEV 请求及可选采集、明确版本/模型/原始解析响应 | 不通过普通 append 冒充直接观测；不切换真实主控流程 |
| 04 独立查询界面与 Drover 接入 | Saddle 宿主独立遥测查询界面；插件默认记录选择、task/run 关联、交付上下文、带关联条件的查询跳转与状态声明 | 通用查询不依赖 Drover；宿主不读业务文件；新消费者与依赖入口一起验证 |
| 05 消费者切换 | Saddle 提供同版本技能资源，迁移日常入口与旧配置依赖，验证后退役外部 dlog | 不导入旧日志；保留旧数据，切换前明确备份及回退；不顺带迁移 Corral |

阶段 01 独立可用，不需要阶段 02–04 才能验证存储/纯记录/查询，因此可单独审查合并。后续相互依赖的两半不能在集成验证前分别宣称交付。Corral 最后迁入是后续工作，不在这五阶段中实现。

阶段 02 串行拆为 02A（Codex 执行采集入口）和 02B（Claude Settings General 开关入口，沿用现有风格）。02A 审查后保留分支/worktree，02B 从该候选基线接入同一 Store 开关；主控负责集成，整阶段通过后一起合并清理。无需先改 Drover 或 Corral。用户要求凡需修改 Corral 或出现反向依赖，先暂停相关工作并告知，未经讨论不得实施。

阶段 04 独立查询界面属于 Saddle；Drover 的任务快捷入口只传不透明关联条件，不承载通用日志读取实现。具体布局在该阶段实施前确认；现有旧 Dispatch 视图至阶段 05 切换再退役，本轮不拆。

## 验证与切换边界

各行为实现按项目 RED→GREEN 执行。第一阶段仅合成/临时数据；项目标准检查是共享 target 下的 `cargo test --all-targets` 与 `cargo clippy --all-targets -- -D warnings`。不为了验证读取真实遥测、队列或会话。阶段结果分别记录“已实现、已验证、未接入、未切换”，不把设计或局部测试说成整条链路已交付。
