02

使用这套语言的四个前提

同类统一，合理差异保留

保留 Agents 3a、三行工作区 Tab、插件灰细外框、Drover 居中面板和 Plugins 面板布局。

调整展示，保持行为

不改业务状态、协议、数据、输入映射、默认焦点和确认流程；移动控件同步命中区域。

状态必须准确

成功、失败、加载、空态、未知与陈旧使用明确文字，不依赖颜色，也不互相替代。

先看代表性画面

先确认 Settings、Tasks 和选择列表，再逐页推广。常规、窄、矮窗口和长文本都需检查。

03

完整设计规范

以下保留 Markdown 规范全文。页面上方的 HTML 示例是辅助理解的候选表达，不覆盖原文及既有批准规则。

Saddle 设计语言 v1

讨论日期：2026-10-03；定稿：2026-10-04。定位：宿主与仓库内插件长期使用的轻量视觉规范。状态：Codex 与 Claude 已达成统一意见，六项最终文字修正已落实；尚未实施，现有已批准规则优先。用户尚未确认的新外观在代表性画面阶段确定。

配套文档：现有 UI 整理清单。本文回答“以后遵循什么规则”，清单回答“当前哪些界面需要改”。

1. 为什么需要设计语言

需要固定。当前问题主要是功能增长后同类控件出现多套表达；仅逐页修补，后续插件和功能还会再次分化。规范应固定语义、组件类别和信息层次，具体 RGB、宽度和视觉细节通过代表性画面确定；不另造通用组件框架，也不追求所有界面长得一样。

依据：主设计、主题设计、插件入口设计。沿用已有风格及英文界面，不改变用户正文/报告语言。文档不是用户已批准全部新外观的声明；拟改变既有获批规则时，应列明差异并在获准实施时同步主设计。

2. 应用范围和保留项

  • 本轮只涉及绘制、排版、已有状态和操作的展示，不改变业务状态、查询语义、数据、协议、生命周期或输入映射。
  • 保留 Agents 3a、三行圆角工作区 Tab、插件灰细外框、Drover 子页面居中内容面板、Plugins 启动面板布局（后两项于 2026-10-02 批准）、头部轻量入口和边框内控件等有依据的组件变体。
  • 同类组件统一，不要求侧栏、表格、选择列表、单选控件完全同形；确认、表单、阅读页使用各自适合的尺寸。
  • 本文规定展示角色，不授权增加快捷键、改默认焦点、改确认流程、迁移页面或删除功能。

3. 设计规则

3.1 语义和状态

  • 用现有主题角色表达正文、次要信息、边框、强调、错误；不在叶子界面随意新增固定颜色。Dune、Tide、Lagoon、Terminal 和用户覆盖语义保持不变。
  • 焦点、选中、主操作是三种不同概念：焦点有边框/光标等定位线索；选中用底色/标记/字重；主操作通过按钮权重表达。允许主题中的不同角色共用色值，但不能只靠颜色区分这三者。
  • 成功、失败、进行中、未知、陈旧保留明确文字或符号。错误不弱化成普通帮助；陈旧数据不假装实时；没有成功色可用的插件仍可用文字表达成功。
  • 标题优先用文字层级和字重，而非到处使用强调色；整页不要同时强调所有可点内容。

3.2 组件按类型统一

类型 推荐约定 保留的差异
普通单选列表/选择器 同类选择标记、选中底色和名称字重一致，路径/说明次一级 Agents 槽位、表格行、目录树、单选控件分别按其类型处理
按钮 沿用现有紧凑尖括号和圆角按钮两种已有用途；普通、主要、危险、禁用可辨识 入口文字、页签和链接不强行套按钮外框；页面主操作由页面目的决定
输入框 同类有/无焦点样式一致，标题只写字段名，帮助不塞进边框标题 Settings 行内字段、搜索框、多行正文框可以保留紧凑/普通/多行变体
弹窗 同类弹窗的边距、标题和按钮组稳定；确认、表单、报告采用不同尺寸档 宿主模态、插件外壳、工作区窗格保留所属层级，只针对 Search agents 一类“同一弹窗内输入框再套同款粗框”的重复强调作整理，不移除已批准的 Drover 居中内容面板
页签 同类页签保持选中表达、标题位置和间距 工作区三行圆角 Tab 不改成内容页签；Settings 与内容页签不机械同构
节标题/标签值 同级同样式；标签列对齐，值保留完整阅读能力 警告与状态标题可按语义区分，不将所有标题改成一种颜色

Diagnostics 的主要动作可以是 Refresh，Updates 的主要动作可以是 Upgrade all；Refresh 在两页权重不同属于合理差异。

3.3 间距、尺寸与溢出

  • 使用终端显示列宽，而不是字符串字节长度，计算中文、符号、按钮与截断。
  • 普通弹窗内容建议左右一列内边距，同组标签和值对齐；不建立全局空行/网格要求，Agents 3a 的紧凑字符格和已有行距保留。极窄/极矮尺寸优先保留内容和已有操作，不为装饰挤掉内容。
  • 弹窗按紧凑确认、常规表单、宽内容阅读分档，具体宽度与高度由代表性画面确定，暂不硬定所有页面同尺寸。
  • 同一终端尺寸下，Settings 家族采用稳定外框、顶边和页签位置；内容多少不应让切页时整个框跳动。常规尺寸以容纳六页签为目标；窄屏延续已有可用的换行/滚动能力并预留高度。具体列数和高度待代表性画面确定，不能只把框加宽就宣称适配完成。
  • 路径截断保留末级目录；名称、ID、报告不因排版丢失必要辨认信息，沿用已有完整阅读入口。
  • 同类界面使用一致的溢出提示，只有确有溢出时显示；页码/位置计数不挤在最容易被截掉的长帮助末尾。

3.4 文案、操作帮助与消息

  • 回车、Ctrl 各取一致写法，倾向 Enter、Ctrl-S，随代表性画面确认；已批准的 Agents 底栏 ↵ 等紧凑写法不提前替换。同一组件族避免混用 Ctrl-S 和 ^s，Esc 保持明确。
  • 按钮内沿用“标签 + 已有快捷键”；帮助列表可采用“键 + 说明”两列。没有快捷键的动作不伪造键位，也不因整理外观新增绑定。
  • 关键退出/保存操作保持可发现；字段的重复说明只在需要的上下文显示。帮助位置按宿主状态栏、模态操作栏、插件内容页脚三种职责分配，不强行把插件帮助搬到宿主。Plugins 面板已有获批的弹窗内提示行保留；若建议迁移，先在整理清单说明与既有设计的差异。
  • 同一个宿主状态栏采用一致的目标/帮助视觉结构，稳定表达当前输入目标；操作结果、表单错误有固定位置。一个作用域内避免把相同说明重复写在框标题、正文和底栏。
  • 成功/失败/加载/空态文字准确；空态引导只能引用已有可用动作；“没有活跃任务”与“没有任何任务”不能混写。

3.5 插件与主题

本规范先用于仓库内宿主、Drover 和 Diff；不修改第三方插件契约，不向插件开发入门/SDK 追加强制规则。

当前插件协议只有 text、muted、background、accent、error 五色。Diff 可优先使用已收到的颜色，尤其是未改动代码行背景、说明、错误与当前文件；不能顺手重做 diff 语义高亮。

Drover 在已有能力内统一布局、标签、选中和消息规则。不新增主题协议字段，也不承诺本轮完全统一所有状态色。更多主题字段、公共 UI SDK 或共享组件库属于后续独立工作，不能以“固定设计语言”为理由先造框架。

Dispatch 没有独立 UI，随宿主的 Plugins 列表和详情整理；示例 Counter/Attention 仅作演示，本轮不投入产品级改版。

3.6 状态表达对照

角色 非颜色线索 用法
焦点 光标或边框变化 指出当前输入对象，不等同于业务选中
选中 选择标记、底色或字重组合 指出当前条目/选项，失去焦点也不应丢失其身份
主操作 按钮权重、明确动词、操作分组 由页面目的决定，不能据此改变默认焦点或自动执行
危险 明确动作名与已有后果说明/确认 使用既有 danger 角色，不能只涂红不说明
禁用 弱化及必要的已有原因说明 不靠改变标签伪造业务禁用状态
成功/进行中/失败 明确状态文字或图标 有相应现成颜色时辅助表达，插件缺某色不扩协议
未知/陈旧 明确 Unknown/Stale 及已知原因 不呈现为成功，不触发重试或自动恢复
次要信息 位置、字重和信息层次 路径、说明、技术标识可弱化，但仍须可读

空态、加载、失败、陈旧分别说明“当前无内容”“尚在读取”“读取失败”“显示上次结果”；不互相替代，不编造未实现的恢复操作。

4. 采用方式

先用 Settings、Tasks、一个选择列表三类合成画面选定规则的具体表达，再补 Telemetry、New agent 和 Diff 的代表性内容；检查常规、窄、矮窗口和长文本状态后逐页推广。主题观感、颜色对比度和真实终端兼容需要实际渲染确认，不能由源码检查替代。

规范中的组件类型和语义保持稳定；具体画法一旦确定，在本文记录。新页面优先选择既有类型，确有新类型再说明理由；不要求先建共享框架。未来插件文档/示例任务可以引用本规范，但本轮不改对外契约。
