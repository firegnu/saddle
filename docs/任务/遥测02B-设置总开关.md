### 做了什么

- Settings → General 末尾新增 `Telemetry recording`，沿用 `Kind::Bool` 的布局、键鼠（Space/Enter/←→/点击切换、Ctrl-D 默认 Disabled）、Save/Cancel、冲突提示和错误行；没有新面板。下方两行说明：`On: only work explicitly chosen for recording may be recorded.` / `Off: no new recording; tasks and agents still run; history is kept.`；状态未知时第三行显示原因。为容纳 19 字符的标签，标签列只在 General 页由 18 列加宽到 19 列，General 弹窗高 12→15；其他页不变。
- 开关值直接来自同一 `Store` 的全局 `recording_policy`（App 用 `Store::from_environment()`，与 `saddle telemetry`/`saddle agent` 同一路径）。打开、Reload、从插件页回到暂存 Settings 只调用 `Store::settings()`，不初始化；无库显示 Disabled，读失败显示 Unknown，不当作关闭。不写 config.toml，不经插件。
- 遥测侧最小接口：`Store::set_recording_if(generation, SettingInput)`，在同一 IMMEDIATE 写事务内比较全局 generation（无库按 0，与 `settings` 一致）后再设置；不匹配返回 `conflict/setting_changed`，不写任何东西。既有 `set_recording` 行为不变；同值仍为 duplicate，不递增 generation。CLI 未改。
- `src/app.rs` 接线：打开时传入 Store；暂存的 Settings 恢复时 `refresh_recording()`；新增 `Outcome::Recorded`（只保存了开关，关闭并在面板提示实际状态）与 `Outcome::Applied`（配置已写入并即时生效，但开关未保存，Settings 保持打开）；`Saved` 的面板提示附带开关结果。颜色/宽度/吉祥物的热生效逻辑抽成 `apply_settings`，行为不变。
- `docs/遥测使用.md` 增加 Settings 总开关一节并更新开头范围说明。

### 保存失败与外部变更的取舍

- 编辑只是草稿；Cancel/Esc、Default、恢复原值都不触库。无改动（含切换后又切回）Save 直接关闭，不写库。
- 一次 Save 的顺序：先做配置字段校验、配置文件外部修改检查和新文本构建（任何失败都整体不写）；再以 Settings 读到的 generation 调用 `set_recording_if`；最后写配置文件。
- 外部变更：generation 不匹配，或打开时状态未知而保存时已能读到，都进入现有冲突界面（文案改为说明是遥测开关），Keep my edits 重读文件与开关并保留草稿，Discard 丢弃，Back 返回；这一路径什么都不写。未编辑开关时保存其他配置不触库，所以过期显示不会覆盖外部 CLI 设置。
- 存储不可读/不可写/锁等待超时：开关报告 `Telemetry recording not saved: …` 并保留草稿；其余配置照常保存（`Applied`，即时生效，Settings 保持打开），再次 Save 只重试开关。反向情况（开关已提交、文件写入失败）提示 `Telemetry recording saved: … Config not saved: …`，开关不回滚，其草稿已等于已存值，再次 Save 只重试文件，不重复发起开关写入。两者不宣称原子提交。
- 成功后显示的状态取自 compare-and-set 事务实际提交的值（generation+1），没有额外读回；之后重新打开或 Reload 显示存储当时的实际状态。
