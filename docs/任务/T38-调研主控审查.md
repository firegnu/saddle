## 已核实的事实

- route.py 从标准输入读取摘要，向标准输出打印 JSON，没有保存这两项的逻辑。现有记录零散存在于任务书／完成记录中，缺少统一、明确关联到任务及派发轮次的采集记录。不能扩大为“任何地方都没有任何记录”。

- saddle 现有 Git 只读读取与文本预览可以复用；它们没有替主控自动采集原始 JEV 返回／回复的能力。

## 对调研建议的判断

1. 同意必须增加主控侧的明确记录动作；不必为此先修改 corral／drover。只改 saddle 的项目 AGENTS.md 能约束本项目主控，不能宣称其他项目自动具有记录，其他项目需各自接入约定。
2. 不接受将独立本地记录等同于“新增任务状态系统”。只追加留存派发材料、不判定和推进任务状态，可以在本地独立持久化；是否另建存储只是实现取舍。
3. 不接受用实现者完成记录默认替代原始回复。用户已明确要求返回内容，记录应保留对应轮的原始最终回复；摘要／完成记录可以另展示，两者不能冒充。
4. 不把提交正文作为推荐的长期正文载体。可用独立明确格式的记录文件保存元数据及全文，并用 Git 历史保存版本；相比从长提交消息提取约定字段，正文与来源更容易核对。具体目录／格式尚待实施方案确认。
5. 派发前的提交只证明记录／准备时间，不证明 corral start/send 成功。方案必须区分准备的任务书与实际派发结果，实际 agent 名与实例从公开命令返回取得；轮次关联不能只凭文件路径和提交时间。
6. 历史缺失项显示未记录，不自动补造。T38 调研阶段已有的路由原文可在未来经用户许可明确标成补记，不能假装同时记录；不把历史补录扩成首版必做功能。
