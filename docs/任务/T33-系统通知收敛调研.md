### 查明的情况与依据

- Drover 的系统通知由独立 `drover loop` → `tick` → `collect / wait_items` → `notify_new` → `osascript` 发送，覆盖主控停下但判据不满足及任务待放行。通知分支不按项目 loop 开关筛选；本机 LaunchAgent 已配置，而公开 list 显示三登记项目 loop 均关闭，两者不矛盾。未确认引擎实时运行／OS 投递。源码与本机配置定位见报告 S1–S3。
- Hammerspoon 当前菜单栏脚本有三类系统提醒：进入限流、context ≥85%、5h／周用量 ≥80%；普通 Waiting／Done 不发。数据来自 abtop 和 Claude 用量缓存补充逻辑。只读了来源脚本，没有运行采集、打开用量缓存或发送探针。见 S4–S5。
- Claude CCNotify 的 Stop hook 仍配置着，但脚本发送调用已经注释；Notification 处理器虽有发送能力，本轮检查的配置没有接入它。不能将安装状态当作正在发送。Codex `notify` 已指向 Computer Use 客户端，内部作用和桌面投递未确认；其 TUI 终端通知是另一条能力。Herdr 当前选择内部 toast。见 S6–S10。
- corral 状态采集 hook 与 OS 通知不是一回事；旧看板的可选 bell 也不等于桌面横幅。Attention 当前只做清单、未读和跳转，尚未覆盖 Drover suggested、限流、context、用量阈值或非 corral 会话；ctl 没有 Notify 入口。见 S8–S13。
