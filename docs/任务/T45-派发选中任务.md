## 完成记录（2026-09-29，实现者）

修改：
- `src/drover.rs`：`Task` 新增 `dispatch_pending`（`PendingTarget{pos,target_token,unavailable_reason}`），走既有 `lenient` 解析，缺失或格式不对时为 `None`，不影响整份快照。新增 `Operation::DispatchPending{project,pos,token}`，参数只有 `dispatch-pending --pos N --target-token TOKEN --json`，令牌原样传。`Client::dispatch_pending` 先核对 worker 项目与点击时项目一致，只调用一次；非零退出也解析 stdout 的 JSON；无 JSON（旧 drover）或 schema_version≠1 报错，不做别的调用。`dispatch_report` 按 `delivery.status`、`record.status`、`error.code` 分行表述发送与记录；只有「退出 0、ok、有 task_id、record=recorded，且 delivery=confirmed 无草稿拼接，或 delivery=not_sent 带 manual_text」算成功，其余（含 ok:true 但结构矛盾、草稿拼接、记录未知）都以失败提示，并注明未重试、队列随即刷新、请核对主控。「Delivered」只在 delivery=confirmed 时出现；手动模式显示「not sent」和 manual_text 全文。
- `src/queue.rs`：选中 Pending 的操作行加单行按钮 `Dispatch selected`（无快捷键，与 Return to pending… 同法用专属点击键）。可用条件：在列表页、非忙碌、无读取错误、未暂停、无 Current／Awaiting，且这一项 `pos>0`、token 非空、`unavailable_reason` 为 null；否则画成禁用（无点击区）。点击时取当下快照里选中项的 pos/token 和 `panel.project`，置忙碌后发出 `Request::Run`。结果与 Next 相同进 Action result 页。Current／Awaiting／History 不显示该按钮。Help 加一行说明。
- 刷新：沿用 `drover::Worker`，每次操作返回后立即重读快照；项目切换在忙碌时本就被拒，切换会丢弃旧 worker 的结果。未改 Next 及其他操作。
