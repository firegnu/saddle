- saddle 只负责读取与展示，不调用记录器的 route/new/start/send/decide/note，不为查看页面触发采集、派发或 JEV 请求。

公开只读入口：

```text
dlog ls --project <drover 使用的项目根> --task <任务号>
dlog show <dispatch_id>
dlog cat <sha256>
```

`ls` 返回派发声明列表；`show` 返回派发及事件 JSON；`cat` 返回经内容哈希校验的原文。默认数据目录是 `~/.local/share/dispatch-log/`，格式版本为 1；saddle 优先消费上述 CLI，不另建历史库、不绕过 CLI 解析记录器内部目录。当前记录器尚未安装到全局 PATH，命令定位需沿用 saddle 现有外部命令配置方式解决，不能假定所有用户已经安装或写死本机源码路径。

## 已确认的界面与内容

- Tasks 详情新增第四个页签，顺序为 **Task text | Run details | Dispatch | Links**。Task text 保留用户原始需求与状态；Run details 保留既有运行状态、完成检查、时间和结果；Links 保留当前文件、提交和 agent 入口。
- Dispatch 按首次派发、返工、审查组织材料，多次派发与多份任务书分别保留。每条先显示时间、对象、模型／强度和简短结果；选中后在同一 Tasks 弹窗查看只读全文，Esc 返回原位置，复用现有阅读交互。
- 展示任务书快照、发送文本、JEV 输入与完整解析响应／整理建议、主控最终决定与验证预算、实现者完成回复、返工原因和主控审查。主控与 JEV 不同时展示已经记录的调整理由，不替主控生成理由。
- 派发快照与 Links 的当前文件明确区分；快照标明是派发前保存的文件内容，不声称 agent 实际读取了该版本。
- 未安装记录器、当前任务没有记录、某项未记录、读取失败分别如实显示。没有记录器也不影响现有任务功能；不把错误或缺失显示成成功／空历史。
- 无记录器、无数据、读取失败或数据格式不兼容时，Dispatch 仍可正常返回和切换，其他页签与任务操作保持可用，不崩溃。
- 不自动评分“过重／过轻”，不自动裁决、重试或补采，不扩展为全局操作日志；Attention 继续负责当前待处理事项。

## 关联与展示依据

- 使用当前所选任务的明确项目根与任务号查询；worktree 的 cwd 不是项目键。没有明确任务号或关联记录时不从任务名、时间或文件名猜测归属。
- `dispatch_id` 是记录器内的派发 ID，`parent` 表示声明的重派／审查关联；`operation_id` 关联一次操作的 intent/result，不把两条事件当成两次派发。
- JEV 建议、主控决定、实际显式启动参数与声明标签分别展示；未记录的默认模型或强度不推测。记录器中的完整解析响应与当前任务文件的 Route 摘要不可混用。
- 回复原文、实例与 at 来自公开 corral 返回；归属哪个派发是主控声明。实例不一致、关联缺口、recording_gaps 如实呈现，实例一致也不等于回复因果已证明。
- pending 只代表排队，只有 intent 没有 result 表示结果未知；合并草稿时，记录的发送片段不代表完整实际输入。时间区分记录器观察时间与来源提供的时间。
- 不读取私人会话或完整终端补历史；已有历史缺失明确保留。实现者回复中的验证结果是其报告，不能改写成 saddle 直接观测到的执行事实。
