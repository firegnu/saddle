## 要做的

1. 提供不依赖 TUI 或插件进程的 `saddle agent [Saddle选项] -- start|send|reply <原Corral参数>`。按契约支持 --record-context /绝对路径/context.json、--brief-file /绝对路径/task.md；配置/选择 Corral 可执行文件采用独立程序路径参数或现有配置，不拼接含空格命令字符串，参数形式写入使用文档。原业务 argv 逐项传递，不偷偷插入 prompt、标签、上下文或环境。
2. 无上下文、开关关闭或存储不可用时业务仍执行一次，不为无记录调用初始化遥测或读取任务书正文；明确无效字段或已确认不存在/跨 trace 的关联应在调用前拒绝。上下文固定 schema_version/trace_id/dispatch_id 与可选 basis_event_ids/decision_event_id/previous_brief_event_id，send 另含 send_kind=initial/followup/rework；调用方不能伪造 generation、operation ID 或来源。字段/组合按既定契约验证。
3. 在 Saddle 调用边界使用现有 Store/Capture 生成 execution_observed。保存调用前任务书实际字节、实际 start prompt/send 片段及公开参数，区分显式模型/强度与声明标签；不保存任意完整 argv/env、认证参数或推测出的配置。只解析受支持的公开形式，不认识的元数据记 null/gap。reply 保存公开返回 text 的完整字节，并保留 name/instance/at 和 association=not_proven，不伪称它必然回应某次 send。超限或不可读显式 gap，不能静默截断。
4. begin/快照原子提交，调用后用原 Capture 保存 end；关后重开不复活旧 generation，begin 失败不补造历史、不重读变化后的原文件。存储错误不重放真实动作。Corral 公开 confirmed/pending/merged_with_draft/name/instance/at 按实际返回保留，未知保持未知。公开 Corral at 是数值 Unix 时间戳：主控发现阶段 01 的内部校验目前按 nullable_string 接收 at；请核实并在 Saddle 内按“公开返回原样保存”的既有契约最小纠正相关类型/测试，不能转成字符串迁就校验，也不能改 Corral。其他真实契约冲突先报告。
5. 保持业务 stdout/stderr 字节和正常退出码，独立的 `saddle-telemetry: ` stderr 回执只含操作/采集状态及缺口，不重复正文。遵守 final=true 最终回执和 executed=false 边界；入口拒绝125、无法启动127、信号128+signal不能混为 Corral 正常业务退出。即使不采集也要为自身拒绝/启动失败给出可区分的回执。不能因存储失败改变正常业务退出码。
6. 依契约处理本次短命客户端的超时/取消、转发 INT/TERM 并回收直接子进程，保留已托管独立 agent 的生命周期。支持调用方隔离进程组的调用方式，明确本入口及调用方责任；不得按名称批量杀进程、不得为了超时调用 corral stop。锁等待沿用短预算，不能把数据库重试包住业务动作，记录不延长业务总超时。输出采集要保持真实业务输出，资源上限只形成遥测缺口，不能以截断内容冒充完整返回。

### 实现结果

- 新增独立 `saddle agent [--corral PROGRAM] [--timeout-ms MS] [--record-context /abs/context.json] [--brief-file /abs/task.md] -- start|send|reply <原参数>`。不要求 TUI/插件，不读取其配置；独立程序路径允许空格，业务 argv 含非 UTF-8 字节也逐项透传，stdin/env 不增加遥测内容。
- 上下文封闭校验；明确无效字段/组合、已确认不存在/跨 trace/错误类型的关联先拒绝。无上下文不接触 Store；关闭或不可用不读任务书正文、不初始化遥测，有效业务仍执行一次。
- 使用既有 Store/Capture 完成原子 begin/任务书快照、公开 start/send 输入、reply 完整正文及 end；基于调用前固定的 generation/关联和暂存字节恢复缺 begin 的 end，不重读已变化原文件。关闭后重开不复活旧 Capture，同值设置不撤销。
- 白名单保存明确模型/强度和 role/model/effort 标签，分开记录实际显式参数与声明；不保存完整 argv/env、认证参数或推测配置。reply 保持 association=not_proven；confirmed/pending/merged_with_draft/name/instance/at 按公开结果保留，缺失/错误类型保持 null/gap。
- stdout/stderr 流式转发原字节；16 MiB 正文上限及 32 MiB JSON 包络上限只产生遥测 gap，不截断正常业务输出。独立 stderr 终止回执含 final=true、executed、operation_id、begin/end、outcome/gaps，不重复正文；无记录调用也有宿主最后回执，以区分外部程序自行退出 125/127 和入口拒绝/启动失败。
- 正常退出码原样返回；入口拒绝 125、spawn_failed 127、信号 128+signal、可选本入口超时 124。只转发 INT/TERM 给本次直接客户端，200 ms 宽限后升级 KILL 并回收；调用方创建的独立进程组保持不变，不触及已分离托管进程。业务输出及回执写出都有背压/取消边界；取消导致不完整输出时不伪造完整终止回执。
- 锁等待沿用 100 ms；剩余不足预算则跳过采集，内部 end 最终事务可缩短到剩余时限。未扩大既有调用方预算，不在业务动作外套数据库重试。磁盘阻塞/fsync 仍依契约由调用方外部总超时兜底。
- `docs/遥测使用.md` 已说明参数形式、受支持的元数据语法、输出/回执、资源上限、进程组与调用方责任。main/lib 仅加 headless 入口和帮助；没有 config/UI/现有 Corral 调用链接线变化，没有新增依赖。
