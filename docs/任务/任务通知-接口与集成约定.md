# 任务通知：接口与集成约定

2026-09-28。用户已确认 Settings 选择 System／In saddle、使用现有 Attention，按一个 saddle 的日常场景设计，并授权「可以，按照你的计划开干吧」。本文件为两份独立实施任务的共同约定；T33 调研报告保留，不改成实施任务。

## 分工与交付顺序

1. drover/main 先派 Codex 实现通知层，由其主控审查，并按路由决定独立审查。
2. Drover 提供固定 SHA、公开契约和可供联调的 worktree 后，saddle/main 派 Claude Code 实现 Settings 和内部提示，负责集成。
3. 两边开发与审查 worktree 保留，联调通过前都不合并、不发布、不清理。集成直接使用被审 Drover worktree 内命令及隔离配置，不靠提前安装主分支版本。
4. 两边主控在联调通过后协调各自合并与发布。当前交给 Drover 主控的执行阶段止于“审查通过、保留待集成”，不可自行推送、重启服务或提前收尾。旧常驻进程加载新版必须列入联合发布安排。

## 行为范围

- 弹出仅限“任务完成且正在等待放行”，不覆盖自动模式完成后直接进入下一件。主控 idle 且判据未满足不弹，已有任务判据、公开 attention 和看板语义不变。
- Settings General 提供 Task notifications：System／In saddle，仅控制本用户跨登记项目的 Drover 任务通知；Hammerspoon、agent 自身通知和其他渠道不受影响。
- System：Drover 发系统通知，saddle 不发内部任务提示。In saddle：关闭 Drover 系统通知，saddle 从已有公开状态生成内部提示。saddle 未运行时不回退系统通知；无离线事件补发，未处理事项仍可在 Attention 查看。
- 查看或关闭提示不放行、不推进队列、不清除持续状态。首版不增加通知中心、后台通知服务、发送重试系统、多 saddle 实例选举或远程通知功能。
- 首次升级／首次开启／渠道切换／应用启动时，首次成功取得的已有 awaiting 集合作为基线，不补弹旧事项；读取失败不能当空基线。正常同渠道重启不因忘记已提示身份而重复弹。
- 同次运行不因刷新、文字变化、短暂观察缺失而再次提示。采用尽力提示；不承诺 OS 一定送达、用户一定看见或跨渠道精确一次。

## Drover 公开命令契约 v1

命令不依赖 cwd 或项目 init，只处理用户级系统通知偏好：

```text
drover notifications status --json
drover notifications on --json
drover notifications off --json
```

成功退出 0，stdout 为单个 JSON 对象：

```json
{"schema_version":1,"ok":true,"scope":"user","system_enabled":false,"revision":3,"application":"next_notification_check"}
```

- `system_enabled` 是布尔值；`revision` 是非负整数，缺失配置建议为 0，仅实际偏好变化时递增；重复 on/off 幂等。
- 缺失配置默认开启；status 只读且不创建文件。损坏／不可读／写入失败等返回非零，stdout 为带 `ok:false` 与可供机器判断的 `error.code`、人读 `error.message` 的 JSON；不得输出假成功。具体错误码由 Drover 公共契约列定后供 saddle 消费，saddle 必须保留未知错误降级。
- 写操作成功只代表偏好已保存，不表示常驻引擎确认已应用。后续通知检查读取新值；当前约 60 秒检查间隔不是生效时间上限。不能撤回在途发送或 OS 旧横幅。首次部署需更新旧引擎，不把“新 CLI 已安装”等同于“旧引擎已更新”。
- 通知偏好由 Drover 保存，是唯一事实来源。saddle 不直接读写 Drover 内部文件，不在自己的 config 复制开关。每次刷新依据公开状态校准渠道；读取失败或旧版本不支持时如实显示，不猜 System／In saddle，不发未经确认的内部提示。
- 这不是 Drover→saddle 推送协议；Drover 不依赖 saddle、socket、saddle 配置或 UI 实例。saddle 继续用已有 list／show，不新增通知接收 ctl 命令。

## 运行身份与切换边界

候选身份由规范化项目仓库绝对路径、task.id、task.t0、task.start、task.main 和事件类型组成。Drover 主控须以公开 list／show 契约核实字段和表示，随交付给出精确定义，saddle 照用；不得改任务事件格式来造新 UUID。必需字段缺失时不按标题或 T 编号猜，保留待处理清单并跳过自动弹出。

去重不得每轮用“当前能看见的事项”覆盖全部已见身份；保留正常重启所需记录，记录只用于减少重复，不是持久通知历史。模式 revision 变化使消费者建立新基线，避免漏掉两次轮询间的关→开。仓库搬迁、备份恢复／队列重置后的身份延续不保证。通知异常与记录错误不能影响任务状态和推进。

切换保存到引擎应用之间存在窗口，系统与内部渠道仍可能各出现一次；界面如实表达后续检查生效，不为消除这个窗口扩成消息事务系统。多个 saddle 同时运行的统一选举／全局内部提示去重不属于首版，不能宣称已经解决。

## 联调与接口变更

联调由 saddle/main 负责，使用隔离 HOME／XDG／runtime、合成项目与假 OS 发送器；核对公开开关、待放行出现、去重、渠道切换和跳转这一条主流程。不得推进真实队列、触发真实通知、读取内部状态替代公开接口或用生产服务作测试。

如果 Drover 发现此约定无法在通知层成立，报告具体缺口给 saddle/main，先更新共同约定再开发依赖部分；不能一边改命令／字段、一边让 saddle 猜。功能、错误语义或权限范围扩大须先提请裁决，不自行补成新需求。
