## 样式建议

（saddle/dev-agent-selection，第一阶段，仅建议，未改功能代码。）

### 现状（截图 + 源码核对）

- 选中项整块铺 `agent_selected`（默认 #302a23），范围是主行加全部附加行，条目间空行不铺；这部分在截图里已经足够认出选中项。
- 小白线是 `src/ui.rs` agent_rows 主行第 0 列的 `▎`：Agents 有焦点时用 `focus`（黄），没焦点时用 `muted`（ANSI Gray，截图里接近白）。它只画在主行，附加行第 0 列是空格，所以只有一小截，看起来像残留。
- 最左边几列本来就有三条竖向元素挤在一起：面板边框、第 0 列这条线、第 1 列树线 `│`/`└─`。

### 方案 A：去掉竖线，只靠背景 + 文字层级

- 第 0 列固定输出空格（保留这一列，树线、宽度计算、点击行都不变）。
- 背景照旧整块铺 `agent_selected`；选中项名称在现有 `bright` 上再加 BOLD。树线、状态、类型、effort、Git、◉/new 颜色都不变。
- 有焦点和没焦点时选中样式一样；焦点只靠现有的加粗琥珀边框表示（第 13 节“焦点、选中、连接三者不混用”）。

### 方案 B：第 0 列画一条贯穿整个条目的主题色竖条

- 选中项主行和所有附加行（包括折行和 Git 行）第 0 列都画 `▎`，条目间空行不画；滚动裁剪时逐行绘制，露出几行就画几行。
- 颜色的问题：已有主题色里，黄 = 焦点，也和 blocked 状态同色系；青 = 已接入 ◉ / repo；蓝 = working；绿 = idle；品红 = 未读；红 = 危险。拿哪个当竖条颜色都会和某个已有含义撞上。中性色也不行：`muted` 正是用户不喜欢的那种白，`dim` 放在 #302a23 底上几乎看不见。
- 显乱的风险：选中项如果不是分组里最后一个，附加行第 1 列有树线 `│`，和第 0 列的竖条会变成紧挨着的两条平行线，再加上左边的面板边框就是三条，很像多了一层树。截图里 dev-t2-new-form 被选中时就会是这样。

### 推荐：方案 A

- 理由：截图里现在的背景块已经清楚标出选中项的范围和高度，竖条只是重复这个信息。去掉后左边只剩边框和树线，树形结构更干净。A 也不需要从已有语义色里挑一个颜色，就不会和 blocked、已接入、working 这些状态混在一起。它还避开了“选中非末尾项时出现双竖线”的问题。
- 可辨识性：有没有焦点，选中项都靠整块背景 + 加粗亮色名称认出来。背景在主行、附加行、折行上都有，所以条目很长、被裁剪到只剩几行附加行时，露出来的部分照样有底色。
- 实施点（第二阶段，等主控通知）：
  - `src/ui.rs` agent_rows 主行第一个 span 改成固定的 `" "`，`focused` 参数不再有用就一起去掉；名称 span 选中时加 `Modifier::BOLD`。
  - 不新增主题字段，不改 `agent_selected` 默认值，不碰 Queue 自己的 `▎`（`src/queue.rs`，不在本任务范围）。
  - DESIGN 补一节，说明 Agents 选中不再用左侧标记，覆盖第 13、14、18 节里对应的“左条/竖线/左侧标记”说法。
  - 验证：一个合成渲染断言，覆盖选中前后第 0 列没有 `▎`、选中项的每一行（包括折行）都有 `agent_selected` 背景、名称加粗、条目间空行没有背景；再跑 `git diff --check`。
- 要问用户的事：Queue 的选中项还是 `▎`，去掉 Agents 的之后两个面板会不一致。要不要一起改，由主控问用户，本任务不自行扩展。
