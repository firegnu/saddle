# Settings 直接入口

用户原话：「既然只有settings一个功能了，就不要用...了，直接settings提出来不就好了？」

由主控直接实施，不委派。分支/worktree：`settings-direct`。

## 实施

- Agents 顶部直接显示 Settings，点击后打开设置，移除只有单个条目的 More 菜单及其专用模块。
- 保留更新圆点、悬停显示、按下/松开须同一目标、模态输入隔离、关闭后返回原焦点及逗号快捷键。窄栏中 Settings 单独放在 Attention 下方。
- 更新现有头部布局、宽度保存和完整鼠标流程测试；被删除的菜单测试随模块删除。README 与 DESIGN 同步记录直接入口。

## 验证

- RED：现有头部测试改为要求 ` Settings ` 后运行，实际仍为 ` ⋯ `，按目标缺陷失败（`/tmp/saddle-settings-red.log`）。
- `cargo test --test ui --test app --test workflow --no-fail-fast`：100 passed（UI 31、App 3、Workflow 66）；Clippy 全目标、格式及差异检查通过。
- 曾机械套用发布前规则启动全量；用户指出这只是 Settings 位置调整、不值得全量后停止。该次全量不计通过，不继续扩测；以已通过的直接相关检查收尾。
- 所有 Cargo 命令使用共享 `CARGO_TARGET_DIR=$HOME/Developer/personal_projs/saddle-worktrees/.target`，不用真实 agent，不改测试超时。
