### saddle 现状

- `src/queue.rs` 的列表已经区分 Current/Running、Awaiting、Pending、History 的 Done/Dropped。因此不是所有完成状态都完全消失，而是详情信息没有迁移齐。

- `src/drover.rs::Task` 只解析 id/title/body/status/reason。公开 JSON 已有的 start/main/end 和 t0/t1/t2 被忽略；可以恢复开始、完成、放行时间、用时、等待时长、提交区间。缺失值不能编成零或已完成。

旧看板的「过程」是任务阶段、Git 进展、完成判据和记账摘要，不是逐轮 agent 工具日志或完整审查往返记录；源码明确不统计返工轮数。当前 `.check-result` 是上次核对缓存，不是逐任务永久历史，不能声称能恢复任意历史任务的全部中间状态。

`drover board` 当前只有交互界面，没有可供 saddle 调用的详情 JSON。saddle 不复制 Python 内部函数，不直接读取 `.drover.conf`、tasks.state、验收缓存，也不以调用 done/go 的方式“读取”详情。

## 展示提案（待用户选定）

点击 Current / Awaiting / History 任务，在右侧 Viewer 原位置展示所选任务详情，左侧任务列表保留；点击 agent 或按 Esc 返回终端。继续沿用当前英文 UI，用户标题与正文原样展示。

```text
Agents / Tasks         │ Task · T4 · In progress
                       │ Elapsed … · Commits … · main +…
Current                │
  ▸ T4 …               │ Completion checks
Pending                │   ✓ / – / ✗ 依据、判据和具体原因
  T2 …                 │   Last check …（有效/过期/未运行）
History                │
  T11 Done             │ Task details
                       │   任务正文
                       │
                       │ Started … → Completed … → Released …
                       │ Esc: Back to terminal
```

所选任务完成后继续展示同一任务的完成状态，不能随列表索引移动而切到另一任务；历史详情只展示属于该任务的已知记录，不套用当前任务的判据结果。布局切换应让任务详情中的输入留在详情中，不发送给隐藏终端。具体实现方案在用户选定展示位置后确定。
