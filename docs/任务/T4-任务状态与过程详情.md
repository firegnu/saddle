### 必须遵守的接口语义

- 最终字段与评估不同：completion.rows[].state 为 met/unmet/unavailable/not_applicable/not_run；last_check 使用 status；routing 使用 cross；attention 使用 state/reason/unmet_rows/agent/inference。只看结构化字段，不解析 why 判定业务。
- task.location 区分 current/awaiting/history，awaiting 的 task.status 仍是 done。completion.scope=current_repository 是查询时重算；recorded_history 的 rows=null 是历史快照未保存。不得把现在 unmet 改成任务未完成，也不能把当前判据套到历史任务。
- last_check 单列：valid 也只是上次结果，不表示本次验收；retained_sample 是历史留存样本，不能宣称完成时快照。missing/invalid 不意味着从未验收。缓存的 record、过期原因与配置不适用按契约展示。
- Git range_commits 是区间计数，不归因于 agent/任务独占；end_head 不是结束 main；main_tip_committed_at 是提交时间。routing.source=task_file_now 明确来自当前文件；Hold 的未知保持未知。attention.suggested 是关注推断，不是已停工事实。
- warnings 的 snapshot_changed / snapshot_verification_unavailable 必须让用户看得出本次快照不一致或复核不可用，下一轮按正常刷新重试，不据此执行动作。
