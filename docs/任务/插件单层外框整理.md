# 插件单层外框整理

用户原话：“这个界面有点乱啊。drover插件包了两层border。那个counter的插件弹出来的也是一样。”

主控亲自实现，不委派、不操作真实任务或 agent。Dispatch：`ab034c84cd5740c7a364161fde44119b`。

## 改动

- Saddle 保留统一外框、名称、关闭按钮。插件覆盖期间清除底层工作区画面，避免终端框与工具栏从四周露出。关闭覆盖后按原布局恢复。
- Drover 删除旧 Tasks 页的整页边框与重复标题/总数；Pending/History 分组数量保留，表单、按钮和内部区域分隔不变。
- 可交互插件的临时提示移到宿主底部状态栏，不再压在插件第一行；不可用/失败占位仍显示。
- Counter 源码没有整页框；使用同一宿主修正，无需更新其插件程序或协议。

## 验证

这是视觉布局调整，不制造行为缺陷的 RED。使用既有大小窗口渲染、输入坐标、表单、覆盖关闭/焦点恢复、实际插件流程检查；原 all-pending 测试按文字行核对长标题完整性，不再依赖已删除的框线作为内容边界。

- 标准 `cargo test --all-targets -- --test-threads=4`：335 passed / 0 failed / 4 ignored；Clippy、fmt 和 diff 检查通过。日志 `/tmp/saddle-single-frame-{all,clippy}.log`。
- 实際已安装 Counter 二进制在隔离宿主中通过点击/通知/关闭重开兼容检查；Drover 表单与后台生命周期检查通过，debug 与 release 各1项。日志 `/tmp/saddle-single-frame-{counter,drover,release-counter,release-drover}.log`。
- 检查实际 PTY 渲染文本 `/tmp/saddle-single-frame-{counter,drover}.txt`：只剩一层插件外框，底层终端框/工具栏不再露出；临时捕获代码已移除。

不会强制退出用户窗口；需要同时加载新宿主与 Drover 包，用户重启 Saddle 后观察。Counter 包和所有任务数据/配置不变；发布hash与备份位置见 HANDOFF.md。
