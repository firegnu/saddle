结果文字还有以下直接契约问题，修正范围仅限这些反馈及相关检查：

1. `dispatch_report` 把所有 `record.status=not_attempted` 写成任务仍为 Pending。公开契约明确 target_changed 等前置拒绝可返回 `state:null`；任务可能已被移除或另行派发，不能由“本次没记 start”推断当前状态。去掉无依据的 Pending 断言，或仅按已知 state 表达；保留刷新提示。已有 target_changed 合成响应可直接覆盖。
2. `merged_with_draft:true` 无条件追加 Delivered。契约说该字段保留 corral 回包，而送达以 `delivery.status` 为准；unconfirmed 加草稿信息不能升级成确认送达。草稿提示只说明混入草稿及需要核对，不额外断言已送达。补这一个组合的直接检查。
3. `Client::dispatch_pending` 的命令执行错误直接通过 `?` 返回。超时或输出捕获失败时可能已经发生外部发送，现有 JSON 丢失分支的核对提醒也应覆盖这种执行错误：说明无法确认最终结果、未重试，提示检查队列和主控。保持一次调用和既有超时，不增加重试机制或 120 秒等待测试；用直接错误路径的合成检查即可。
