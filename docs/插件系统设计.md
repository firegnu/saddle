# Saddle 插件系统设计

2026-09-30。状态：首个 demo 通路已实施；Drover 插件及其他挂载位置仍待后续。架构依据见 [DESIGN §62](DESIGN.md#62-saddle-进程式插件架构2026-09-30)；首个实例见 [插件 Demo 设计](插件Demo设计.md)。

## 1. 已确认的方向与本稿范围

用户已确认：Corral / corral-dispatch 是基础设施，Saddle 是其上的操作台；操作台提供插件开发规范，插件可以独立开发、安装和使用。采用独立进程、版本化协议、Rust SDK，作为长期架构；接受可信本地插件以当前用户权限运行。先设计插件系统与最小 demo，Drover 是第二个插件。

用户要求后续由主控自己做，不再委派。本稿记录系统设计；首个 demo 与 SDK 的实施状态见 [实施记录](任务/插件首个Demo实现.md)，不授权更改 Drover 任务规则或真实任务。下面的交互、字段和初始限制是主控设计建议；demo 内容不是用户原话。

成功的目标是：一个独立 Rust 项目只依赖公开 SDK，即可在不修改、不重编 Saddle 的情况下提供可交互面板；删除或停用该插件后，agent、终端、分屏和布局仍可使用。核心不依赖 Drover 才能启动。

## 2. 模块职责

| 模块 | 拥有的职责 | 不拥有的职责 |
|---|---|---|
| Corral | agent 生命周期、通信、公开状态 | 插件加载与工作区 UI |
| corral-dispatch | 主控委派、审查和收尾方法 | Saddle 运行时与插件生命周期 |
| Saddle 宿主 | 工作区、面板位置、焦点、输入路由、插件运行与故障、通用通知展示 | 插件的业务状态与业务操作判据 |
| 插件 | 本地业务、后台工作、面板内容与局部交互 | 直接修改宿主内存、布局文件或其他插件状态 |
| Rust SDK | 协议编解码、事件循环、帧转换、请求匹配 | 任务流转规则、自动派发、通用业务框架 |

只有宿主主循环写布局。插件不获得 Ratatui `Frame`、PTY 或 Saddle 内部 `App` 对象；通信经过独立的协议类型。原生 Rust 插件仍能自行访问系统，这里是协作约定，不是权限沙箱。

## 3. 为什么选择进程

Saddle 面向本地开发工作：独立进程方便复用 Rust 线程、文件访问和公开 CLI，插件退出可以单独报告，不需要把本地操作先改写成 Wasm 宿主能力。

代价是自行维护协议、SDK 与进程管理；按系统/架构分别构建插件；没有权限隔离。Extism 能提供加载、资源限制、超时和 SDK，Wasmtime 能提供 Wasm 沙箱和类型化接口，但两者都不直接提供 Saddle 的输入、布局与业务集成。因此不引入它们作为首期依赖。

将来改用 Wasm 会涉及运行模型、系统访问、取消和错误语义，不能承诺只替换传输层。当前只设计一个运行后端，不为假设中的迁移增加抽象。Nushell 的进程协议和 Zellij 的面板生命周期作为参考，不引入它们作为运行依赖。

## 4. 安装与用户入口

首期采用“登记本地插件目录”，不做下载器、商店、打包解包或安装脚本执行。目录由用户放到希望长期保留的位置；登记不复制文件。移动目录后显示不可用，不猜测新位置。

每个目录有 `plugin.toml` 和可执行文件。例如：

```toml
manifest_version = 1
id = "demo.counter"
name = "Counter demo"
version = "0.1.0"
protocol_major = 1
executable = "bin/saddle-counter"
args = []
required_capabilities = ["panel.v1", "notify.v1"]
```

- ID 稳定且唯一，由 ASCII 字母、数字、点、下划线和连字符组成；不使用显示名作为存储身份。
- `executable` 必须是字面相对路径，拒绝绝对路径和 `..` 分量；允许目录内符号链接指向外部构建产物，便于共享 target 目录开发。登记时显示解析后的实际入口；这是路径解释规则，不是文件访问沙箱。不进行 shell 展开、下载或命令拼接，不存在、非可执行或平台不匹配时明确报错。
- 参数为字符串数组，直接传给子进程。运行 cwd 为插件目录，不借用当前 agent 的 cwd；首期不隐式提供项目上下文。
- 同 ID 不能重复登记。更新采用停用、替换原目录产物、再启用，重新核对清单；ID 改变视为不同插件，不热换正在运行的二进制。
- “移除”只删除登记，不删除目录或插件业务数据。

运行中的插件先 Disable，确认进程已结束并回收后才允许 Remove 或替换产物；停止失败时保留登记并显示失败。Restart 只重启当前实例已启用的插件，必须先结束并回收旧进程，不顺带改变其他实例或业务数据。

在现有 Settings 增加 `Plugins` 入口，打开宿主管理的列表：

```text
Plugins
Name                 Enabled    Runtime
Counter demo         Yes        Running

[Add local…] [Enable] [Disable] [Open panel] [Restart] [Remove]
```

首次登记默认停用；登记过程不执行插件。Enable 先保存 enabled=true，再启动可信本地程序；下一次启动 Saddle 时，仍启用的插件会启动。若保存失败，本次不启动；若保存成功但启动失败，显示 Enabled=Yes / Runtime=Failed，不伪装运行或暗中回滚配置。Open panel 只针对运行中的插件，不把打开动作隐式当作启用授权。

插件登记单独存放在实际选中的 Saddle 配置文件同目录的 `plugins.toml`，默认是 `~/.config/saddle/plugins.toml`；XDG 或 `--config` 改变配置目录时随目录变化。同目录的多个配置文件共用插件登记，不同目录隔离。文件包含格式版本及各插件的 ID、绝对目录、enabled；文件不存在相当于空列表。未知版本/损坏文件只让插件管理不可用，不阻止基础工作区启动，也不覆盖原文件。

Plugins 是从 Settings 打开的即时操作页，不参加其他设置的 Save/Cancel 草稿；界面标明操作立即生效，离开后原设置草稿保持。插件登记不写 `config.toml`，因此不会自己触发该文件的草稿冲突，也不会使旧版 Config 的严格解析失败。

Plugins 写入采用短写锁保护“重读比对、修改、原子替换”的全过程；与读取基线不符时拒绝写入并要求刷新，不覆盖另一个实例的改动。不能只靠原子替换来声称避免了并发丢更新。Add/Enable/Disable/Remove 的登记写入失败均明确报告，不执行依赖本次保存的下一步；其中 Disable 先保存 enabled=false，再走停止流程。保存成功但停止失败时显示 Enabled=No / Runtime=Stopping 和错误，不写成 Disabled。

其他 Saddle 实例不被当前实例的启停远程操纵；它们下次启动采用新登记，现有实例显示自己的运行状态与已加载的启用意图。重新读取登记会更新管理列表，不静默重启其他现有进程；变更需要在该实例上明确执行。

首期不新增独立插件管理 CLI；实现后再决定是否有真实自动化需求。按钮和状态见 [Demo 线框](插件Demo设计.md#界面线框已确认)，用户已确认并授权实施。

## 5. 生命周期与面板

一个 Saddle 实例对一个启用插件最多运行一个进程，首期每个插件最多一个面板。其他 Saddle 实例有自己的进程和会话，不能跨实例复用请求编号或停止句柄。

插件作者必须容忍同一插件被多个 Saddle 实例同时启动；宿主不做全局单例或主实例选举。插件自行处理业务数据并发与外部操作去重；它不能把本进程唯一当作系统全局唯一。首期 demo 无共享业务数据；Drover 的跨实例行为在迁移时按既有规则核对，不在此阶段扩为全局通知选举。

```text
登记（Disabled） → Enable → Starting → Running → Unresponsive
                           ↘ Failed
Running / Unresponsive / 仍有子进程的 Starting → 停止 → Stopping
Stopping → 旧进程已回收 → Disabled / Failed / Starting（按停止原因）
Failed（无存活进程） → 用户 Restart → Starting
```

- 子进程启动后完成握手才标为 Running。握手超时、版本不兼容、协议损坏先走 Stopping，回收后才成为 Failed；自主退出也先回收并报告原因。不自动反复重启。
- 首期使用按需存活探测，要求插件事件循环能及时回应；耗时业务放在插件自己的后台工作中。探测失败或输入通道无法可靠交付时进入 Unresponsive，面板不可交互，保留最后画面并标记失效，不重放输入。迟到的 ping 不自动恢复交互；用户选择 Restart 或 Disable。
- Restart 适用于已启用的 Running、Unresponsive、Failed：凡有尚未回收的子进程，先 shutdown、等待宽限、必要时终止自己持有的 PID 并 wait/reap，成功后才创建新会话进入 Starting；已回收的 Failed 可直接启动。任何时刻最多一个尚未回收的进程；结束/回收失败停留 Stopping 并报错，禁止启动第二个。
- Disable 停止当前实例的插件、停止接收其通知，保留面板占位。Enabled 配置与 Runtime 分开显示，不能用“已停用”掩盖停止失败。
- 关闭面板只关闭显示；进程继续运行，可以产生通知。重新打开时同一进程的业务状态仍在；停止/重启后是否恢复业务状态由插件决定。
- 正常退出 Saddle 时给插件发送 shutdown，有限时间后终止并回收自己持有的子进程。SDK 以协议输入 EOF 或协议输出写入失败判断父连接结束，退出并取消自身后台工作；不能用重定向后的普通 stdout 状态代替协议连接状态。
- 不按名称批量杀进程，不调用 `corral stop`，不沿用 shell PTY 的进程组关闭逻辑。插件负责取消、等待它明确拥有的短命子进程；Corral 托管的 agent 不属于此类。
- 宿主强制结束插件并不证明任意孙进程都已消失。首期不承诺回收用户程序主动脱离管理的进程；不能扩大 kill 范围来掩盖这一限制。

启动环境是接口的一部分：宿主显式将插件 stdin/stdout/stderr 接到各自管道，不继承用户终端。当前 macOS/Unix 实现须建立无控制终端的新会话，不分配 PTY；去掉 `CORRAL_NAME`、`CORRAL_INSTANCE`、`SADDLE_INSTANCE`、`SADDLE_PANE`、`SADDLE_REVISION`，防止插件误用父 agent/窗格身份。一般 PATH 等环境保留；这不限制可信插件主动访问系统，不宣称所有平台的进程隔离已实现。

SDK 入口在启动业务代码或线程前，把原始协议输入输出保存为私有且 exec 不继承的句柄；在 Unix 上使普通 fd0 指向 `/dev/null`，fd1 转到日志 stderr。这样 SDK 初始化后的 `println!`、普通子命令输出不进入协议，子命令也不会偷读协议输入。插件 main 必须先进入 SDK，初始化之前的输出仍属协议违规；非 Rust 插件需实现等价规则。协议句柄不得被业务子进程继承，所需子命令输入输出由插件显式提供，不接用户的控制终端。

## 6. 工作区中的交互与恢复

Open panel 默认新建右侧工作区 tab；若本插件面板已经存在，则定位到它，不新增副本，不替换用户 agent/shell。继续使用宿主已有的 tab、关闭和分屏布局规则；首期不增加插件自行创建任意面板或抢占位置的接口。

面板示意：

```text
Agents                  Workspace: [agent] [Counter demo]
                        ┌─ Counter demo ─────────────────┐
                        │ Clicks: 0                      │
                        │ [ Increment ]                  │
                        └────────────────────────────────┘
```

插件获得内容区尺寸，不包括宿主标题/边框。宿主负责焦点、标题、外框和 `Ctrl-]` 返回 Agents；其他输入只给当前聚焦且可用的插件。弹窗/Settings 打开时，插件不偷收输入。剪贴板粘贴作为一次带长度限制的文本事件交付，不转换成逐键回放。鼠标使用面板相对坐标；按下/抬起仍由插件决定是否构成按钮点击。

插件面板是新的内容种类，不伪装成 shell 或 agent，不创建 PTY。旧的终端键盘编码保持；插件收到结构化键名和修饰键，Shift+Enter 与 Enter 不能合并。

布局保存插件 ID 和面板位置，不保存 PID、会话 ID、业务状态或画面。读取旧版布局保留 agent/shell 行为；写入包含插件的布局使用新版文件格式，正常保存前保留旧格式备份，不让旧程序覆盖不能理解的内容。

- 已登记且启用：按配置启动插件，面板先占位，ready 后恢复内容。
- 已停用或目录缺失：保留 Disabled/Unavailable 占位，只提供打开管理入口和关闭显示；布局恢复不自动登记或启用。
- 插件崩溃：保留 Failed 占位，用户选择 Restart；业务操作不自动重发。
- 登记已移除：立即及下次恢复均保留 Unavailable 占位，只允许关闭显示；不能由占位重新登记或自动启动原目录。

`saddle ctl inspect` 需要能如实区分 plugin 内容与终端；其公共 JSON 扩展、旧消费者兼容必须在实现时一并核对。首期不新增 ctl 创建插件的操作；现有 close 只关闭显示，原 shell 关闭确认规则保持。

## 7. 通信契约草案

传输使用进程启动时的 stdin/stdout 管道承载 UTF-8 JSON Lines；SDK 按 §5 将它们转为专用协议句柄，普通 stdout 随后进入日志。stderr 是日志；宿主持续读取但只保留有界尾部，不默认记录终端/agent 内容。不得同时从重定向后的普通 stdin 读取协议。

每次启动分配新的 session ID。宿主请求初始化，插件返回实际身份、版本与能力；与清单不符或必需能力不足时拒载。协议主版本破坏兼容时递增；同一主版本内新增可选字段，不改变已有字段含义。

信封只包含三种消息：

```json
{"kind":"request","id":1,"method":"initialize","params":{"session":"s1","protocol_major":1,"capabilities":["panel.v1","notify.v1"]}}
{"kind":"response","id":1,"result":{"id":"demo.counter","protocol_major":1,"capabilities":["panel.v1","notify.v1"]}}
{"kind":"event","name":"panel.frame","data":{"panel":"main","size_revision":1,"frame_id":1,"rows":[]}}
```

示例仅说明信封，不是完整初始化/帧 schema。最终字段定义由公开 protocol crate 固化；清单版本、插件发布版本和协议版本分别管理。

| 方向 | 首期消息 | 语义 |
|---|---|---|
| 宿主 → 插件 | initialize、ping、shutdown 请求 | 建立会话、确认可响应、请求退出 |
| 宿主 → 插件 | panel.open/close/resize/focus、input、theme 事件 | 提供显示状态与交互，不执行业务 |
| 插件 → 宿主 | panel.frame / panel.error / input.rejected 事件 | 提交画面、绘制错误或明确拒绝过期输入 |
| 插件 → 宿主 | notify 请求 | 请求展示一次内部提示，返回接收或限流结果 |
| 双向 | response | 按 ID 返回 result 或 error，不能同时存在 |

请求 ID 在单次会话及各自发送方向内唯一；事件不强加请求/响应。请求有期限，超时显示未确定结果，不自动重试有副作用动作；通知接收成功只表示交给宿主，不表示用户已经看到。旧会话的回复、帧与通知不能进入新会话。

未知请求返回 `unsupported`；缺失必需字段或损坏的信封是协议错误。仅明确允许扩展的可选字段/可选事件可以忽略；不能用忽略掩盖不兼容。拒绝重复请求 ID，不宣称跨重启 exactly-once。

读写和编解码在后台执行，经有界通道交给主循环；主循环每轮有消息处理预算，只绘制已校验缓存。尺寸、悬停、未显示帧可以合并；按键、点击、粘贴和请求结果不能静默丢弃。队列满导致无法可靠交付时明确显示插件无响应，停止新输入，不自动回放此前操作。

实施限制已收敛于 [插件协议 §5](插件协议.md#5-有界预算与存活探测)：单条消息 4 MiB、粘贴与日志尾部各 64 KiB；可靠控制消息每方向 64 条且累计 256 KiB，画面另用最新帧槽。限制必须在分配/排队之前检查，超长粘贴先在宿主拒绝并提示，不能截断执行。它们是首版实施常量，不是新增用户配置或已经验证的性能承诺。

会话结束时所有未完成请求以连接结束/结果未知完成，释放等待者；不把插件“接收了输入”等同于其外部业务已经成功。不支持协议层透明重发。

## 8. 画面格式与 SDK

推荐完整的结构化字符格画面。插件在本地使用 Ratatui 生成 buffer，再由 SDK 转成 Saddle 自有的公开数据，不直接序列化 Ratatui 类型。首期不传 ANSI、HTML、控件树或逐像素图片，也不做增量帧。

帧绑定 panel ID、宿主给出的 `size_revision`、行列数及插件单调递增的 `frame_id`，尺寸版本与画面版本不能混为同一字段。宿主将用户实际看到的 `frame_id` 和尺寸版本带入面板输入，尤其是点击/按下/抬起。插件只能按该画面的交互目标处理；不再保留对应目标时明确拒绝过期操作并请求用户重试，不能按最新重排后的行号代办。插件仍需自行验证业务目标，帧身份不能替代 Drover 等业务令牌。

尺寸变化后的旧帧可以丢弃；旧尺寸缓存只能显示为非交互的等待状态，不能用新坐标点击旧按钮。SDK 将同一输入流中的 resize/focus/input 按顺序交给插件处理；一组跨画面、尺寸或焦点变化的鼠标按下/抬起不能误触发操作。

格子定义至少包含字形、占用宽度、前景、背景与样式；双宽字形的后续格有明确延续标志。拒绝越界、孤立延续格、跨行双宽符号和嵌入控制序列。原样保留组合字形，不按 UTF-8 字节数切割。空画面与隐藏面板不要求生成无意义的零尺寸 buffer。

全帧描述是逻辑语义，不要求在线路上逐格重复 JSON 对象。合成编码大小比较后，首版选按行同样式文字片段；宿主推导起始/延续格，不在线路上重复发送格宽。具体 schema、测量范围与结果见 [插件协议](插件协议.md)，不引入增量帧。

正常画面超出 SDK 可发送预算时，SDK 不发送截断/超长帧，而发送有界的面板绘制错误；宿主显示 Frame too large，保留旧画面但禁用其业务输入，仍允许用户缩小窗口、关闭显示或停用插件。健康进程不因正常尺寸过大被判为 Failed；后续合规新帧可恢复。实际违反消息长度上限的协议字节流仍按协议错误断开，不能为吞完无限长一行而突破内存或时间预算。绘制错误消息字段随帧 schema 定稿。

字符宽度规则固定为 [插件协议 §3](插件协议.md#3-字符宽度-profile) 的 saddle-grapheme-v1，宿主与 SDK 共用分词、宽度及校验。Unicode 宽度表或规则的改变需要另命名 profile 并显式协商。终端对某些 emoji 的实际显示仍可能不同；实现时要用中文、组合字符和双宽边缘的合成样例验证，不能仅凭 ASCII 计数器宣布通用渲染完成。

首期主题只传正文、次要文字、背景、强调、错误等少量语义色，SDK 转成插件本地样式。完整皮肤库、共享按钮库和宿主控件框架先不提取。首期不支持插件输入光标控制；Drover 编辑器接入前再按实际需要扩展，不能提前承诺现有编辑 UI 已可直接迁移。

主题与帧颜色使用 default、indexed(0–255)、rgb 三种表示；默认背景不强制替换为 RGB，以保持透明面板。插件输出需要新增 RGB 降级入口，复用现有 nearest_256 算法；当前 Theme::for_terminal 仅转换 Agents 专属字段，并未自动覆盖新插件。此规则不顺带改变现有其他区域颜色。

SDK 的概念接口是初始化、接收事件、按需渲染和退出。业务事件可由插件后台线程投递回来，长命令不能阻塞协议处理。SDK 对外是 Rust 类型和帮助函数；wire 类型不暴露 Saddle 内部对象。protocol crate 与 SDK 可位于 Saddle 仓库，但 demo 是独立 Cargo 项目，只通过公开 crate 接口依赖，不访问宿主私有模块。是否发布 crates.io 另议，首期可以固定 Git revision 消费，避免浮动 main。

## 9. 通知

首期只提供内部短提示：插件提交通知 ID、短文本和级别，宿主显示插件名称作为来源。ID 为会话内单调递增整数，以 accepted 高水位去重，不要求保存无限历史；提示槽或速率限额耗尽时返回明确限流结果，不悄悄丢失已确认接收的条目。具体预算和返回值见 [插件协议 §6](插件协议.md#6-通知的最小契约)。

提示不会抢焦点、自动打开面板或触发业务操作；首期只有关闭动作，没有带业务含义的通知按钮。不新增桌面通知后台服务。插件停用后取消它尚未显示的提示并移除可见提示。

现有 Drover 的“首次读取作基线、按 notification_key 去重、System/In Saddle 渠道、Attention”仍属于现有业务接入。本阶段只抽出通用展示入口，保留旧适配；第二阶段再迁移业务观察逻辑，不能把 demo 的即时通知当作 Drover 完成通知的替代验证。

## 10. 实施边界与第二个插件

| 当前耦合位置 | 首个 demo 所需调整 | Drover 阶段再处理 |
|---|---|---|
| `app.rs` 启动和更新循环 | 插件运行管理、事件入口 | 移出 Drover Worker/Surveyor/ChannelWorker 的创建 |
| `terminals.rs` / `viewer.rs` / `ui.rs` | 增加插件面板内容，复用布局、焦点 | 决定 Tasks 原侧栏/大面板的兼容呈现 |
| `layout_state.rs` / `control.rs` | 新内容身份、保存恢复、inspect 兼容 | 不加入任务专属布局类型 |
| `settings.rs` / 新插件登记模块 | 独立即时登记页与启停，不扩展现有 Config 表 | 再处理 queue 的专属配置 |
| `notify.rs` | 通用提示展示，旧任务入口继续适配 | 将任务基线、去重和渠道读取移入插件 |
| `attention.rs` / `diagnostics.rs` | 不提前加入插件业务条目系统 | 按真实需要设计通用来源条目 |
| `drover.rs` / `queue.rs` / `dispatch.rs` 等 | 不修改任务行为 | 搬迁业务接入，保留公开 CLI 与数据契约 |

所以，demo 完成只证明插件通路，不表示 Saddle 已经脱离 Drover。最终拆分在第二个插件阶段完成：没有启用 Drover 时，不创建任何 Drover 查询/轮询，任务 UI 和专属设置不残留，agent/终端仍可独立使用。旧业务实现只作为迁移期间过渡，迁移核对完成后删除，不长期保留两套路径。

不要求 Drover 重写状态机或改存储，不改 corral/corral-dispatch，不把 dispatch-log 变成插件依赖。Drover 的 Tasks 区域、Attention、配置及 Links/Dispatch 等已有操作要列迁移清单后再实施；本稿未为其锁定新的产品布局。

## 11. 首期不做与待验证事项

不做插件商店、在线更新、安装钩子、依赖解析、跨插件通信、多后端、权限沙箱、任意 UI 声明语言、业务持久化服务或新任务调度器。用户数据由未来插件自行管理；卸载不删除数据。

首版工程检查覆盖以下问题，实际证据与限制见实施记录，不作为新增用户验收承诺：全帧传输成本、中文/组合字符宽度、resize 与输入竞态、通道背压、异常插件退出、布局升级和旧 ctl 消费者兼容。假插件足以验证超时/卡死，不需真实 agent、任务或后台服务参与。

协议具体帧字段、宽度 profile 和数值预算已收敛于 [插件协议](插件协议.md)，作为 demo 实施基线；当前不是可供第三方发布稳定插件的 1.0 规范，实际隔离验证见实施记录。首个 demo 必须按下面的设计与宿主分开构建，不能用写死插件 ID 的分支绕过接口。

## 12. 调研依据

- [Nushell 插件协议](https://www.nushell.sh/contributor-book/plugin_protocol_reference.html)：独立可执行文件、stdio、握手、版本和请求编号的实际应用参考。

- [Rust ABI](https://doc.rust-lang.org/reference/items/external-blocks.html#abi)：不以原生 Rust ABI 作为独立分发插件的兼容契约。
