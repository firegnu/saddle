# 插件协议：首个 Demo 实施基线

> 已退役（2026-10-05）：Saddle 已删除遥测、Drover 和整个插件系统。本文只保留设计/验证历史，不再作为当前操作规矩或安装指引；旧磁盘数据不读、不删。当前功能与命令见 [README](../README.zh-CN.md)，派发路由由 ranch 提供。

2026-09-30。状态：首个 demo 的开发协议，已有实现和隔离验证，尚非第三方稳定版承诺。依据 [插件系统设计](插件系统设计.md)；本页收敛此前待定的完整帧、宽度规则、输入关联与运行预算。UI 另见 [Demo 线框](插件Demo设计.md#界面线框已确认)。

## 1. 传输与版本

沿用独立进程、专用 stdin/stdout 管道、UTF-8 JSON Lines；每行一个对象，LF 结尾。JSON 字符串内部换行必须转义，禁止原始 ANSI 输出。SDK 的 fd 重定向、环境清理和生命周期仍按系统设计执行。

三种信封：request 含 `id/method/params`；response 含 `id`，且 `result/error` 二选一；event 含 `name/data`。错误为 `{code,message}`，message 是有界纯文本。请求 ID 为从 1 递增的 u64，各发送方向独立；接收方保存高水位，重复或倒退请求是协议错误，无需无限保存历史 ID。响应可乱序，按尚未完成的请求匹配；已超时请求的迟到响应丢弃，超过已发最高 ID 的响应为协议错误。

每次进程重启新建 session。后台消息在宿主内附 session 标记；不依赖插件把旧消息正确标成新会话。wire 不为每条消息重复传 session，不跨连接接收回复。

`initialize` 请求包含 `session/protocol_major/capabilities/width_profile/limits/theme`；响应包含 `id/version/protocol_major/capabilities/width_profile`。这里响应里的 id 是插件字符串身份，外层 id 是请求编号。身份、发布版本必须匹配清单；主版本、宽度 profile 必须一致，清单的 required_capabilities 必须满足。首版能力为 `panel.v1`、`notify.v1`，首版只有 panel `main`。握手前除 initialize 响应外不接收业务消息。

主版本 1 内可忽略新增对象字段，但必需字段必须存在，已知字段必须正确；未知枚举值不隐式降级。未知 request 返回 `unsupported`；未知 event 只有名字以 `optional.` 开头才可忽略，否则协议错误。实现时 protocol crate 固化这些类型与校验，SDK 和宿主共用，不各自维护宽松版本。

## 2. 完整帧：按行样式片段

每帧带尺寸和版本，rows 是从上到下的行，每行是从左到右的同样式片段；不含差分、压缩字典或外部样式引用。以下是完整 6×1 示例（中占 2 格，A 占 1 格，再加 3 个空格）：

```json
{"kind":"event","name":"panel.frame","data":{"panel":"main","size_revision":1,"frame_id":1,"cols":6,"rows_count":1,"rows":[[{"text":"中A   ","fg":"default","bg":"default","modifiers":[]}]]}}
```

- `cols/rows_count` 为正 u16，必须与该 size_revision 的内容区尺寸完全相同；rows 长度等于 rows_count。每行片段文字的格宽之和恰好等于 cols，末尾空白也明确发送。0 尺寸仅可出现在宿主尺寸事件，插件此时不生成帧。
- 片段字段为 `text/fg/bg/modifiers`，全部必需；text 非空。样式绝对设置，不继承上一片段。相邻相同样式 SDK 合并，接收方无需强求规范化后才接受。
- 颜色为字符串 `"default"`，或对象 `{"indexed":0}`（0–255），或 `{"rgb":[r,g,b]}`（各 0–255）。修饰项仅 `bold/dim/italic/underlined/reversed/crossed_out`，数组不重复；blink/hidden 首版不支持，SDK 遇到不支持的样式返回绘制错误，不悄悄改变含义。
- `frame_id` 是会话内递增的 u64，重新打开也不归零。宿主只接受当前尺寸版本的完整有效帧；旧尺寸帧丢弃；尚未发送的未来尺寸版本或倒退帧编号是协议错误。
- 后台校验、转换完毕才整体替换缓存；不把半帧暴露给主循环。允许合并尚未显示的帧，不合并业务输入。

逻辑画面仍是字符格：双宽字形占起始格和一个延续格，延续格沿用其样式，不独立编码；解码后由宿主生成延续格。这样线路上没有孤立延续格，也没有可伪造的 width 字段。任何越过行尾的字形都拒绝整帧。

## 3. 字符宽度 profile

首版 profile 名 `saddle-grapheme-v1`，固定 `unicode-segmentation =1.13.3` 的 extended grapheme clusters（`graphemes(true)`），对每个 cluster 使用 `unicode-width =0.2.2` 的 `UnicodeWidthStr::width`，不用 `width_cjk`。这是当前 Cargo.lock 已有版本；公开 protocol crate 必须精确固定规则，不能只靠宿主锁文件约束第三方插件。

计算宽度时以 cluster 为单位相加，不对整个文字片段直接调用 width：部分文字存在跨 cluster 连写宽度规则，整串结果可能不同。每行拼接后确认片段边界位于 cluster 边界，禁止把组合字符或 ZWJ 序列拆到不同样式片段。原文不做 Unicode 归一化。

首版接受宽度 1 或 2 的 cluster。孤立零宽字形、宽度大于 2、单个 cluster 超过 128 UTF-8 字节，以及 U+0000–001F、U+007F–009F 控制字符均为无效帧；SDK 在发送前给出 `unsupported_glyph` 绘制错误，不截断、不偷偷替换。正常 `e` 加组合重音仍作为一个 cluster 保留。SDK 转换 Ratatui Buffer 时核对其格子位置与本 profile，不直接序列化 Cell；forced width 或直接写 Cell 造成的不一致同样报绘制错误。

宿主和 SDK 共用 profile 的校验与展开实现。升级宽度/分词规则必须另命名 profile 并协商，不能随依赖更新静默改变；首版只支持上述一个。该规则保证双方格子解释一致，不保证每个物理终端的所有 emoji 或复杂文字实际字形都相同，也不提供双向文字排版引擎。

实施时定向样例至少覆盖 `中文`、`e\u0301`、`👩‍💻`、右边缘双宽字、组合字符被样式边界拆开、孤立零宽字符及非法控制码。这些定向样例已通过协议/SDK 检查，实际终端验证范围见 [实施记录](任务/插件首个Demo实现.md)。

依据：[unicode-width 0.2.2 宽度规则](https://docs.rs/unicode-width/0.2.2/unicode_width/)、[unicode-segmentation 1.13.3](https://docs.rs/unicode-segmentation/1.13.3/unicode_segmentation/)。两者版本与本仓库锁文件核对一致。

## 4. 显示、输入与绘制失败

宿主的 panel.open/resize 给出 `panel/cols/rows_count/size_revision`；open 后独立发送 focus。resize 在尺寸变化时递增版本；close 销毁显示而不结束进程，重新 open 使用新尺寸版本。focus 含 `panel/focused`，失焦必须取消待完成的鼠标按下状态；theme 含 `text/muted/background/accent/error` 五个语义色。

input 含 `panel/input_id/frame_id/size_revision/event`，input_id 在会话内递增。引用的 frame_id 是宿主实际显示过的画面，不是最新收到的画面；首帧之前、失焦或占位状态不发业务输入。

- key：`type=key`，code 是命名键对象 `{name:enter}` 等，或 Unicode 标量字符对象 `{char:x}`；modifiers 为 shift/control/alt/super/hyper/meta 集合，phase 为 press/repeat/release。Enter 和 Shift+Enter 保留区别；宿主全局键先处理。命名键为 enter/esc/backspace/left/right/up/down/home/end/page_up/page_down/tab/back_tab/delete/insert/null/caps_lock/scroll_lock/num_lock/print_screen/pause/menu/keypad_begin；功能键为 `{name:function,number:n}`，媒体键或左右修饰键为 `{name:media|modifier,key:snake_case名称}`。宿主逐项映射，不能把库的 Debug 输出或平台整数码当协议。
- mouse：`type=mouse`，action 为 down/up/move/drag/scroll，x/y 为内容区 0 起算格坐标；down/up/drag 带 left/middle/right button，scroll 带整数 dx/dy，另带 modifiers。滚动正 dx 向右、正 dy 向下。越出内容区不转为业务点击；跨失焦或 resize 的按下/抬起不能构成一次激活；同一次有效按下的反馈重绘允许松开完成该手势，详见 §11。
- paste：`type=paste`，text 为完整 UTF-8 文本。超过限制先在宿主拒绝并提示，不截成多次执行。粘贴内容不作为显示帧，允许换行；插件按业务处理。

SDK 把 resize/focus/input 按到达顺序投递。定位输入只能按被引用画面的目标操作；键盘/粘贴按序交付，详见 §11。无法再解释旧定位帧时发送 `input.rejected` 事件，含 `panel/input_id/reason=stale_frame`，宿主提示重试，不自动重发。没有通用“业务成功”事件：接到键盘消息不等于外部操作成功。

`panel.error` 含 `panel/size_revision/code/message`，code 为 `frame_too_large/unsupported_glyph/unsupported_style/render_failed`，message 最多 1024 UTF-8 字节。SDK 发现无法按预算或上述规则编码时发送此事件，进程继续运行，宿主保留旧画面并禁用交互、显示错误；新的当前尺寸有效帧恢复交互。宿主直接收到不合法帧则属于协议违规，按停止/回收流程处理，不能混成正常尺寸超限。

宿主默认背景保持 default；彩色输出为 truecolor 时保留 RGB，否则在插件绘制出口复用 `theme::nearest_256` 转换 RGB，indexed/default 保持。现有 `Theme::for_terminal` 只转换 Agents 专属字段，不能声称它已经处理了插件；此新增出口不顺带修改现有其他区域颜色。

## 5. 有界预算与存活探测

以下是首版实施常量，并随 initialize 给出协议相关 limits；不是用户设置，也不是已验证的帧率或内存承诺。实现后的定向性能证据若要求调整，先同步本页与契约检查，不增加第二条传输路线。

| 项目 | 首版值与满额行为 |
|---|---|
| JSON 单行 | 含 LF 最多 4 MiB；有界读取，超限即断开，不继续吞无限长行 |
| JSON 结构 | 最大深度 32；帧最多 65,536 格；每个非空片段至少一格，因此片段数也受限 |
| 粘贴 | 最多 64 KiB UTF-8 字节，排队前检查 |
| 单个日志尾部 | 64 KiB；持续排空，尾部环形覆盖，不阻塞协议 |
| 未显示画面 | 每个插件一个最新帧槽；解析中的一帧、显示中的一帧可同时存在，不能声称只占一帧内存 |
| 可靠事件/控制消息 | 每方向每插件最多 64 条且累计 payload 最多 256 KiB；到任一上限即拒绝新交付并转 Unresponsive，不丢旧键/点击/响应冒充成功 |
| 未完成 request | 每方向最多 16 个；发起方达到限额时本地拒绝，不继续分配 |
| 主循环公平性 | 每轮每插件最多 8 条控制事件、最多接纳一个已校验帧；解析/校验/序列化/管道等待均在后台 |
| 握手 | 5 秒，自进程创建成功计时 |
| 存活探测 | Running 连续 15 秒未收到有效协议消息时发 ping；5 秒内未匹配响应转 Unresponsive；迟到响应不恢复交互 |
| 其他请求 | notify 5 秒；shutdown 最多 2 秒宽限，随后终止自己的子进程并回收；shutdown 响应不是进程已退出的证明 |

frame 走独立最新槽，不用 256 KiB 控制队列装 4 MiB 帧；panel.resize/focus/input 的有序控制流不按种类拆成可互相越过的队列。只可在不跨越可靠输入的连续尾段合并 resize/mouse move。I/O 背压不能卡宿主；协议违规后停止，可靠交付失败后无响应，均禁止自动重放。

## 6. 通知的最小契约

notify params 为 `notification_id/text/level`：ID 是会话内递增 u64，text 最多 1024 UTF-8 字节且不含控制字符，level 为 info/warning/error。与请求 ID 分开。来源名称取宿主已校验的清单，不信任请求自报来源。

结果 status 为 accepted/duplicate/limited。每会话保存最后 accepted 的通知 ID，低于或等于此高水位返回 duplicate，不再展示；插件必须按 ID 顺序提交，limited 不推进高水位。SDK/demo 不自动重试。这样去重无需无限存储，也没有“运行到第 256 条就永久满了”的问题；宿主不提供任意乱序业务 key 去重，未来 Drover 保留自己的 notification_key 处理。

每插件最多 8 条已接受且未关闭/到期提示（含可见提示），全宿主最多 32 条；满额返回 limited，接受后不会为另一条消息静默挤掉。每插件令牌桶初始 5、上限 5、每秒补 1，耗尽也返回 limited。提示 5 秒到期或手动关闭；Disable 清除该插件提示。该确认只说明进入展示队列，不能宣称用户看见了。

## 7. 编码大小的设计测量

2026-09-30 使用 Python 标准库 json 生成合成完整帧，仅计算紧凑 JSON 的 UTF-8 字节（含 LF），没有启动插件、编译 Saddle 或测量实际吞吐。普通面板为背景空格加 20×3 强调文字；极端样例每格交替默认/强调样式，全部 ASCII。逐格方案每格重复 text/width/fg/bg/modifiers；片段方案只合并一行中连续相同样式并去除推导出的 width；没有省略空白行。

| 尺寸 | 普通逐格 | 普通片段 | 交替样式逐格 | 交替样式片段 |
|---|---:|---:|---:|---:|
| 120×40 | 327,629 | 7,682 | 367,409 | 319,409 |
| 240×80 | 1,306,909 | 24,442 | 1,469,089 | 1,277,089 |
| 320×120 | 2,612,590 | 46,003 | 2,937,970 | 2,553,970 |

单位 byte；这些特定样例均在 4 MiB 下，但不保证任意 320×120 Unicode/样式组合都合规。结论只支持优先采用简单片段编码；不宣称比所有其他格式最优，不据此承诺 60 fps。UTF-8 复杂字形、解析耗时、持续多插件内存与 I/O 背压留给实现后的假插件定向检查。

## 8. 直接入口与覆盖界面扩展

manifest_version / protocol_major 仍为 1，增加 `ui.entry.v1`、`panel.overlay.v1` 能力。宿主与 SDK 的支持列表取公开 protocol::CAPABILITIES；SDK 只回报与 initialize 能力列表的交集，宿主继续核对全部必需能力。旧宿主遇到新清单的必需能力明确拒载；未声明新字段的旧插件仍是工作区面板。

清单可增加 `entry`、`[view]` 和 `[action]`，三者一起声明。view 为 `{id="main", placement="workspace"|"overlay"}`；action 为 `{id,title,view="main"}`，entry 引用 action.id。动作 ID 使用既有 ID 字符集/长度限制，标题非空、不含控制字符且最多128字节。不接受未知 view/action 字段或位置。该组要求 panel.v1 与 ui.entry.v1；overlay 另要求 panel.overlay.v1。它们都是宿主的声明式打开操作，不执行清单 argv 以外的新命令。

initialize 增加公共 `reserved_keys=["ctrl+]"]` 与 `view_reserved_keys` 位置映射（workspace 为 `["ctrl+]"]`，overlay 为 `["ctrl+]","esc"]`）。每次 panel.open/resize 另带实际位置的 reserved_keys，SDK 更新 Context::reserved_keys()；这也覆盖新版清单继续显示在已恢复的旧工作区面板的情况。旧宿主缺失时为空。SDK 的事件与帧格式不变。覆盖视图照常接收 main 的 open/resize/focus/input/close，每次关闭后重开生成新的 size_revision，拒绝旧显示帧的输入。它不创建 PTY、不写 layout、不新增插件进程。

`saddle ctl inspect` 增加可空的 `overlay`：显示插件覆盖视图时为 `{kind:"plugin",plugin_id:...}`，focus 为 plugin_overlay；tabs 仍只表示工作区的持久布局。覆盖界面存在时布局写操作返回既有 busy，不改变它背后的工作区。来源焦点消失时关闭返回 Agents，Ctrl-] 总是返回 Agents。

本步没有 Attention 条目、打开任务目标或业务上下文消息。原 notify 与后台工作仍可独立于界面使用。

## 9. 宿主插件命令面板

统一插件面板是宿主功能，不新增插件协议消息或能力。原entry/action.title用于列表标题，不再意味着常驻侧栏按钮；旧panel.v1清单使用插件名称，仍可从面板打开。协议与SDK版本不变。

公开ctl inspect在该面板打开时返回focus=plugin_palette、overlay={kind:"plugin_palette"}；tabs仍仅表示持久工作区。此时布局写操作返回busy。面板可临时覆盖已打开的插件视图，取消后恢复，打开另一插件时只关闭旧显示，进程保留。

## 10. 通用 Attention 来源（attention.v1）

插件清单必须声明 attention.v1，并提供现有 main view / open action（仍需 panel.v1、ui.entry.v1）。初始化双方协商该能力。旧插件无需升级；旧宿主拒绝必需的新能力。

插件发送 request `attention.replace`，params 为 `{ "items": [...] }`。每条字段：`id`（插件局部稳定 ID，ASCII 字母数字及 ._-，1–128 字节）、`title`（1–128 字节）、`note`（0–512 字节）、`action`（清单中 open action ID）、`target`（插件解释的 JSON，序列化最多 4096 字节，深度最多 16）。标题/说明禁止控制字符。每来源最多 64 条，整个 params 最多 64 KiB，ID 不得重复。

合法快照原子替换当前来源，返回 `{ "status": "accepted", "revision": N }`；空数组显式撤回。非法请求返回 `invalid_attention`，保留旧快照。缺少能力返回 `unsupported`。accepted 只表示宿主保存此快照，不保证人已看见；不自动产生 notify，不写业务状态。宿主为每次成功替换递增 revision，重启来源使用新的会话身份。

点击时宿主核对来源仍启用且 Running、会话与 revision 仍匹配、条目仍存在，并复用/打开插件视图；发送 event `attention.open`，data 为 `{ "item_id": "...", "action": "...", "target": ..., "revision": N }`。事件可先于 panel.open 到达；SDK 提供 `Event::AttentionOpen`，插件应保存目标待绘制，并重新核实业务状态。该事件不授权任何接受/派发动作。更新后的旧点击取消；消息入队失败不打开目标。用户再次打开同一条目不会新启进程。

断连、崩溃或重启时，旧条目替换成不可点击的来源状态，不显示为已处理；启用但尚未收到快照显示等待来源。停用/移除即时撤下自己的来源。状态只在当前宿主进程存活，不新增持久化、后台服务或跨插件通信。

Rust SDK `Context::attention(items)` 校验并提交完整快照；`Event::AttentionPublished { id, status }` 回报 accepted / invalid_attention / unsupported / unknown（超时）。每轮最多排队一份未发送快照（新的完整快照覆盖旧的，被覆盖的未发送 ID 不产生回执），最多一份请求在途；有新快照时等待在途响应后再送，不自动重试超时请求。Notification 与 Attention 回调互不混用。

## 11. 表单与通用导航扩展

以下为可选能力，插件在清单中声明需要的能力，旧插件无需升级：

- `panel.cursor.v1`：完整帧可附 `cursor: [x,y]`，相对于局部帧。必须在帧内并指向字素起点；省略/null隐藏。只有匹配尺寸、交互中且获得焦点的画面显示光标。
- `panel.escape.v1`：帧可附 `escape_input: true`，使覆盖面板的 Esc 交给插件处理返回/取消。默认 false，Esc 关闭宿主视图。Ctrl-] 始终由宿主管理，插件应自行更新当前局部页面提示。
- `view.context.v1`：用户从 Plugins 普通打开时，宿主发送 `optional.view_context` 事件，数据 `{"cwd": string|null}`。这是打开时的目录快照，不是任务项目或读取权限。Attention/通知跳转不发送它，避免覆盖已有业务目标。
- `view.close.v1`：插件从输入回调发送 `panel.close_request` 事件，数据 `{"input_id": n}`。宿主只接受当前会话最近用户输入，关闭视图但保留后台进程。陈旧输入、失焦、尺寸变化和停用使请求失效。
- `agent.open.v1`：插件从输入回调请求 `agent.open`，参数 `input_id/name/instance`。name/instance 必须非空、无控制字符、各不超过256字节。每次输入最多一个请求，不接受后台自主请求。宿主验证来源仍有效、公开 Corral instance 和附着状态，复用已有相同实例或在新 tab 接入并再次核验；绝不创建/启动 agent。响应 `status: opened|failed|cancelled` 及 message；SDK 超时报告 unknown，不重试。用户改变输入目标、关闭视图或进程更换后不执行迟到导航。
- `telemetry.open.v1`（04B）：插件从输入回调请求 `telemetry.open`，参数 `input_id` 与 `filter:{kind,scope,key,run?}`（未知字段拒绝）。规则与 agent.open 相同：只认当前会话最近一次用户输入，每次输入至多一个打开请求（与 agent.open 共用），不接受后台请求。宿主不解释筛选值、不按插件 ID 分支：只用遥测 Store 的绑定规则检查（kind/scope/key 非空且不含 NUL，run 省略或同样非空无 NUL），不另设长度上限、不截断或改写；其他控制字符照常接受，页面按可见转义显示。整条消息只受既有 4 MiB 帧上限约束，SDK 在排队前按该上限编码检查，超出返回本地错误而不发送。宿主在来源视图仍打开、没有其他对话框时，在其上打开宿主 Telemetry 列表页（Filter 行注明 `(from <清单显示名>)`），关闭后回到原插件视图。响应 `status: opened|cancelled` 及 message；无效筛选为 `invalid_filter` 错误，陈旧输入为 `stale_input`，未声明能力为 `unsupported`。SDK `Context::open_telemetry(TelemetryFilter)` 发起，`Event::TelemetryOpened{id,status,message}` 回报，20 秒无响应为 unknown，不重试。
- 进程环境（04B）：宿主为每个进程插件设置 `SADDLE_HOST_BIN`=当前宿主可执行文件绝对路径（取不到时删除继承值），供插件调用公开 `saddle telemetry` / `saddle agent` 命令；不放任何记录上下文。插件不得据此读取宿主 Store 或遥测文件。
- `notify.target.v1`：原 `notify` 可加 `target: {action, target}`，沿用 Attention 的 action/不透明目标大小和深度限制。用户点击仍有效的短提示时收到 `notification.open`，数据为该对象。提示身份绑定插件 session 与 notification_id，过期或停用不能跳转。SDK 提供 `notify_target` 与 `NotificationOpen`。

SDK 的键盘与粘贴是有序流：必须获得焦点、尺寸修订相同、frame_id 非零且不来自未来，input_id 严格递增；正常重绘不丢掉已经输入的后续字符。鼠标按下仍要求当前帧；已接受的按下允许匹配松开跨越其反馈重绘，插件仍需校验按下/松开目标一致。resize、close、失焦和其他输入取消该手势，陈旧按下不重新解释。宿主保留键在送达插件前处理。

## 12. 通用插件命令 command.v1

插件可声明 `command.v1`，接受 `saddle ctl plugin --plugin ID --method METHOD --params JSON` 的转发。宿主只传递不透明 JSON，不包含 Drover 业务。运行中且已启用的插件才能接收；不会为一次调用自动启动插件。界面表单/覆盖面板不阻挡命令，也不因调用改变焦点或布局。

宿主发送 event `command.invoke`，data 为 `{id, method, params}`。SDK 回调 `Event::Command`；插件可在自己的工作线程执行，再调用 `Context::command_result(id, result)` 返回 event `command.result`，data 为 `{id, result}`。耗时工作不要阻塞绘制线程。结果必须使用原请求 ID，不能重复返回。同一插件最多32个在途请求；method 1–128字节且无控制字符，参数与结果各最多48 KiB。SDK 对超大结果返回结构化 result_too_large，不终止整个插件。

宿主 ctl 首次返回 plugin_pending，使用既有 `ctl request` 读取完成结果。回执绑定宿主实例、插件 session 和请求 ID；相同请求重读不重放业务。停用、移除、进程退出、更换 session 或120秒无结果均为 uncertain/result_unknown；这不证明操作未发生，不自动重发。过期后的迟到结果丢弃，不能写入新进程或其他请求。消息总量和 ctl 回执沿用既有上限，满时明确拒绝。

## 19. 同包底层 agent 程序（Corral Rust 集成）

宿主为所有进程插件设置 `SADDLE_AGENT_BIN`，值为本次宿主按 Corral 配置解析出的绝对可执行路径。默认 `corral` 定位当前宿主旁的同包程序；自定义路径/其他命令名按配置解析，包内缺失不回退 PATH。环境值不含任务、项目或遥测上下文，底层程序不依赖插件或读取此变量来定位自己。

插件显式 `--corral PROGRAM` 仍优先；Drover 无显式参数时使用此绝对路径，独立运行且未提供变量时保留 PATH 中的 `corral`。`SADDLE_HOST_BIN` 和既有插件消息、能力版本不变。
